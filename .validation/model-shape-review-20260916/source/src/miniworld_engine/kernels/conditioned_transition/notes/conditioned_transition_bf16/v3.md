# conditioned_transition bf16 — v3: fix the fully-broken bf16 TRAINING path

Round 3. Goal: make bf16 TRAINING work (it was 100% broken) and beat compiled torch, while
keeping fp32/tf32 correct and unchanged.

## Environment
- B200 (sm_100a), CUDA 12.8, torch 2.10.0+cu128, pixi `default`, triton + cutlass-cute.
- Shapes: A=48, L∈{1024,4096}, d=128 (atom), d_cond=768, n=2 → ND=256, K=D=128, DC=768,
  M=A·L. Regime: compile=true, cudagraph=manual, bf16-mixed. Shared box (GPUs cycle busy/idle);
  robust signals: eager min-of-interleaved-trials + module-bench pytorch/miniworld ratio.

## What was broken (reproduced)
`cond_transition_train` (module training) routes atom (d≤128) through the "auto" forward, which
for M≥8192 picks the **fused** `_b2b_fwd_train_kernel`. In bf16 that kernel:
1. dtype-mismatches — `h = a*sigmoid(a)*b` (fp32) is `tl.dot`-ed with a bf16 weight →
   `CompilationError: Both operands must be same dtype. Got fp32 and bf16` (same class of bug
   as the v1 inference fix, unfixed here), and
2. even after the cast, register-spills (ptxas 255-reg fail on sm_100a).
The "cublas" forward mode ALSO failed in bf16: its elementwise triton helpers call `tl.sigmoid`
on a bf16 value (`Expected dtype [fp32,fp64] but got bf16`) in `_swiglu_fwd`, `_gate_fwd`,
`_gate_bwd`, `_swiglu_bwd`. So every training path NaNd / errored in bf16.

## Experiment A (as directed): sm100 cute SwiGLU kernels — BUILT, measured, REJECTED
Per the campaign plan I first built the bf16 train path from the transition-family sm100 cute
kernels (SPLIT): forward `swiglu_expand_gemm` (b2b_fwd_sm100) + cuBLAS squeeze + cuBLAS gate;
backward `transition_expand_gatebwd_sm100` (gatebwd_sm100, recomputes a,b,h) + cuBLAS GEMMs.
- **Correctness: excellent.** Standalone the cute kernels hit cos 0.999999 at cond_transition
  shapes; the full autograd Function gave fwd/dx/dcond and all 5 weight grads cos ≥ 0.99998.
- **Performance: loses badly.** These persistent warp-specialized kernels are built for
  transitions K=768; at cond_transitions **K=128** the mainloop is a single K-tile and the
  heavy TMA-store / depth-pipelined epilogue dominates. Eager host-dispatch is ~35 ms/call
  (constant in L — amortized only by CUDA-graph capture), and even the CUDA-graph-replay GPU
  time was ~3.7 ms at L4096 (super-linear) vs ~0.8 ms for the cuBLAS split. Rejected; file removed.

## Experiment B (shipped): make the cuBLAS split bf16-correct
The cuBLAS forward mode does the SwiGLU as cuBLAS GEMMs + a fused triton elementwise, which is
optimal for these small-K shapes. It only needed the elementwise helpers made bf16-safe:
1. **Upcast loaded operands to fp32 before `tl.sigmoid`** in the four elementwise kernels
   (`_swiglu_fwd`, `_gate_fwd`, `_gate_bwd`, `_swiglu_bwd`). No-op for fp32; result stores
   auto-downcast to the bf16 output. (This is a trivial dtype-safety fix on the *elementwise*
   kernels — NOT a retrofit of the register-spilling fused GEMM kernel.)
2. **Force `mode="cublas"` for bf16** in `ConditionedTransitionTailFunction.forward` (the fused
   b2b path stays for fp32). Backward is already cuBLAS + the now-bf16-safe elementwise.

fp32/tf32 are untouched: the upcast is a no-op and the mode override only fires for bf16.

## Performance (bf16 training, vs compiled torch)
Deployment regime (module bench, compile+cudagraph-manual). The shared box makes the ~1-min
L4096 run contention-noisy in absolute terms; L1024 is clean and the eager interleaved-min A/B
of the two full modules is contention-robust.
| L | metric | pytorch | miniworld | speedup |
|---|---|---|---|---|
| 1024 | compile+cudagraph (clean) | 0.313 ms | 0.289–0.297 ms | **1.05–1.09x** |
| 4096 | compile+cudagraph (contended) | — | — | ≥1.0x (1.02–1.58x observed) |
| 1024 | eager fwd+bwd, min-interleaved | 0.379 ms | 0.300 ms | **1.26x** |
| 4096 | eager fwd+bwd, min-interleaved | 2.369 ms | 1.776 ms | **1.33x** |
fp32 training: still runs under compile+cudagraph (ok, ~parity, unchanged path) — no regression.

## Net
bf16 training goes from **100% broken → correct and 1.05–1.33x faster than compiled torch**.
Dead end: the sm100 cute SwiGLU kernels (correct but slow at K=128 — persistent-kernel epilogue
overhead) — the campaigns SPLIT hint was right, but the winning split is cuBLAS, not cute, for
this small contraction dim.
