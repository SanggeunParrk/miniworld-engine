# te_style LN backward on B200 (sm_100) — apply hand-CUDA LN-bwd ideas

Round applying main's hand-CUDA LayerNorm-backward optimization to the trimul sm100 TRAINING
path. Two tracks: (1) drop-in wiring of the CUDA kernel to the LN_in backward; (2) — the
important one — porting the CUDA *design idea* into the te_style fused `_ln_bwd_kernel` (the
LN_out backward), which is fused with the linear and cannot be swapped for the CUDA kernel wholesale.

## Step 0 — does the hand-CUDA kernel even run on B200?
`layernorm/cuda/__init__.py` pinned `-gencode` to **sm_80 + sm_90 only** (`code=sm_90`, i.e. SASS,
no PTX). On B200 the module **built but the kernel launch FAILED** ("no kernel image is available"):
sm_90 cubin can't load on sm_100 and there is no PTX to JIT.
- Fix: add `-gencode=arch=compute_100,code=sm_100` + `-gencode=arch=compute_100,code=compute_100`
  (SASS + PTX fallback). After the fix the kernel builds AND runs, dx/dw/db cos 0.999999 vs fp32
  at N=128/256/512. This also re-enables the whole `compile_native` CUDA dispatch path on B200.

**Not bandwidth-bound (15% DRAM). Register-pressure/occupancy-bound** (255 regs -> 2 blocks/SM ->
12% warp occupancy) on top of uncoalesced m-major loads/stores.

## Track 2 — what CUDA idea actually ports (measured, not guessed)
The CUDA design = coalesced vector loads + warp-per-row register column-partials (no atomics) +
persistent grid. Ideas tried against the m-major `_ln_bwd_kernel`:
1. **Transposed tile** (inner dim = contiguous M axis): 0.97x — moving stridedness around is a wash
   (reduction axis worsens; DXn becomes the strided one).
2. **Recompute xhat from contiguous saved x_normed** (turns the strided x-read into a contiguous
   read): 0.92x — extra div/beta-load outweigh it; registers unchanged.
3. **Uniform layout** — the actual fix. The bottleneck is the **MIXED layout**: dx_normed (=dY@W)
   is row-major while x/dx are m-major, so any thread-mapping strides one operand. Feeding
   dx_normed **m-major** makes all three (M,K) operands share the contiguous m axis; the unchanged
   `_ln_bwd_kernel` then coalesces every load/store along m. Standalone: 0.4372 -> **0.3022 @ L1024
   = 1.45x**, same for the row-tile and transposed kernel (orientation stops mattering once
   uniform). This is the CUDA "uniform coalesced access" principle adapted to m-major — with ZERO
   kernel change.

### Implementation
`te_style._te_backward`: produce dx_normed m-major via the transposed GEMM
`dx_normed = torch.matmul(W.t(), dY.t()).t()` (cuBLAS transA/transB, +~2% GEMM cost, same values).
Full GEMM+LN sequence: 0.5366 -> 0.4024 @ L1024 = **1.33x**; dx/dgamma/dbeta cos 1.00000 (layout
only). Fixes BOTH single-dir (`v6_training_merged_sm100`) and bidir (`bidir_training_sm100`) since
both call `_te_backward`.

## Track 1 — LN_in bwd via the CUDA kernel (wired, DEFAULT OFF)
`TritonLayerNormFunction.backward` gains a gated branch (bf16, 128<=N<=512, contiguous, no rowscale)
calling `layer_norm_bwd_cuda`. Grads correct, CUDA-graph capture clean (worst_cos=1.0). But the
standalone 1.12x is **e2e-NEUTRAL**: LN_in bwd is ~7% of the step and the CUDA path's 2nd (reduce)
kernel launch eats the ~12% compute win at these M (graph-time delta within run-to-run noise).
=> kept as opt-in `MINIWORLD_LN_IN_CUDA=1`; default off (also avoids forcing the nvcc JIT build).
