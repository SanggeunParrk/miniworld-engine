## 4. Work done this round (all on the WIP GEMM)
Resolved every compile-time error; the kernel now builds a full valid CuTe IR. Fixes:
1. **4-mode staged smem layout**: `make_smem_layout_a/b` returns a 4-mode staged
   `((M,atom),1,(K,atom),STAGE)` layout, not 3-mode. Slice the stage with
   `(None, None, None, 0)` (was `(None, None, 0)`).
2. **SM100 TMA atom builders**: replaced the plain `cpasync.make_tiled_tma_atom` 2D-box
   path (which does not match the tcgen05 MMA smem layout) with
   `a_op = sm100_utils.cluster_shape_to_tma_atom_A(cluster_shape_mnk, tiled_mma.thr_id)`
   + `cute.nvgpu.make_tiled_tma_atom_A(a_op, mA, a_smem_layout, mma_tiler, tiled_mma, cluster_layout_vmnk.shape)`
   (and the B equivalent). Added `cluster_layout_vmnk = cute.tiled_divide(cute.make_layout((1,1,1)), (tiled_mma.thr_id.shape,))`.
3. **Epilogue acc view**: `flat_divide(acc, epi_tile)` must be applied to the (M,N) view
   `acc[((None,None),0,0)]`, not the MMA-partitioned `(MMA,MMA_M,MMA_N)` acc.
4. **Per-epi-subtile TMA store**: the epilogue smem is epi-tile sized; the C TMA atom box
   must be `epi_tile` and the store loops over epi subtiles (t2r -> r2s -> fence_proxy
   async_shared -> TMA store per (ei,ej)), rather than one full-tile store.
5. **SSA dominance**: issue the tcgen05 MMA at warp level (`if warp_idx == 0:`), NOT nested
   inside `cute.arch.elect_one()`. Mutating the `ACCUMULATE` field inside the elected
   sub-region made the mutated tiled_mma value fail to dominate the region yield.
6. TMEM protocol: added `relinquish_alloc_permit()` before `free()`.

## 5. Validation
- COMPILE: PASS (full IR verifies; kernel launches).
- NUMERICAL: **FAIL — not reached.** The kernel DEADLOCKS at launch: GPU pins at 100%
  utilization with no output and no completion (threads spin on a barrier/mbarrier).
  Correctness is therefore NOT claimed. Per the skill's correctness gate, the SM100 GEMM
  is NOT usable yet and is NOT wired into the tm1 path.

## 6. Bottleneck / blocker theory (deadlock)
- Symptom: launch-time spin-deadlock (100% GPU, no progress), i.e. a collective that never
  completes. Not a compile issue.
- Ranked hypotheses for the next round:
  1. `mbar_acc` + `tcgen05.commit` accumulator handshake: manual mbarrier init count=1 +
     `tcgen05.commit(mbar_acc)` may not flip the phase the way `mbarrier_wait(mbar_acc, 0)`
     expects (quack drives this via a full `acc_pipeline` producer/consumer, not a bare
     mbarrier). Most likely culprit.
  2. `mbar_ab` TMA expect-tx byte count mismatch vs what the (swizzled) TMA actually
     delivers -> `mbarrier_wait(mbar_ab, 0)` never satisfied. Compute tx via
     `cute.size_in_bytes` on the real sliced smem layouts instead of a hand count.
  3. Named-barrier id collision between `cute.arch.barrier()` (id 0) and the tmem
     `NamedBarrier(barrier_id=1)` vs any cutlass-internal reservation.
- Next-round plan: replace the bare `mbar_acc`/`mbar_ab` handshakes with
  `cutlass.pipeline` PipelineTmaAsync / accumulator pipeline objects (as quack does),
  and/or bisect by stubbing the MMA (store a constant to tmem) to isolate load vs MMA vs
  epilogue as the hanging stage.
