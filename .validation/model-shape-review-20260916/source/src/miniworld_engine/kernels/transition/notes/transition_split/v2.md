# transition split (d=512) — v2: per-length GemmConfig autotune (canonical)

Branch `b2b-cutlass-opt`. Follows v1 (ncu baseline). Goal: the d=512 split expand
(`gemm_ln_swiglu`, quack GemmLnGatedSm90 WGMMA) uses a **hardcoded** GemmConfig chosen only
by K (K>=256 -> tile 192x128, pingpong, cluster(1,2), swizzle 8). It was never autotuned —
picked once to beat triton. This round runs a proper **per-length** autotune (M = L^2 over
the bench seq_len set) to find the real optimum.

## Environment
- H100 80GB HBM3 (node01), CC 9.0, pixi `--frozen`, CUDA 12.8.
- d=512, n=4, K=512, N_gated=4096, expand out cols N=2048, bf16 in/out fp32 accum.
- Bench seq lengths L in {384,512,640,768,896,1024}; M = L^2 (pair repr, batch 1):
  147456 / 262144 / 409600 / 589824 / 802816 / 1048576.

## Method (two-stage + repeat-verified)
Harness `dev/scratchpad_ncu/autotune_split_expand.py` injects `config=` into `gemm_ln_swiglu`
(fold S/B2 + stats precomputed once, so timing isolates the GEMM; cos vs fp32 torch ref).
- **Phase A** — full grid at L=512: tile_m{128,192,256} x tile_n{64,128} x pingpong{T,F}
  x cluster{(1,1),(1,2),(2,2)}, swizzle 8, static persistent. 30 configs.
- **Phase B** — top-6 across all 6 lengths x swizzle{4,8}.
- **Focused verify** (`dev/scratchpad_ncu/focused_swizzle.py`) — winner config, swizzle{1,2,4,8}
  x is_dynamic_persistent{F,T}, 5 repeats x 60 iters, report min (single-shot Phase B swizzle
  deltas looked like 5-14% but needed repeats to separate signal from noise).
- Artifacts: `profiles/kernel-optimization/transition_split/v2/{phaseA_L512,phaseB_per_length,focused_swizzle}.csv`.

- tile_m=192 > 128 > 256 at the winner cluster; cluster(1,2) best for tm192.

## Conclusion — current config IS the optimum (gain 0.0% at every length)
The autotune confirms **tile 192x128, pingpong, cluster(1,2), max_swizzle 8, static
persistent** — the existing hardcoded config — is the best in the tile/tile_n/pingpong/
cluster/swizzle/persistence space, uniformly across the seq_len range. **No per-length table
is warranted (all lengths pick the same config); no code change.** The config was not
mis-tuned; the earlier "was autotune done?" concern resolves to "never run, but the hand
pick was already optimal."

This pins the v1 ncu picture as a genuine ceiling, not a bad selection: expand is
compute/tensor-bound at ~70% SM, occupancy 14% (1 CTA/SM, co-limited by 168 reg AND 220 KB
smem) — intrinsic to this WGMMA gated tile. Config tuning is exhausted.

## Next ideas (structural — config route is done)
Going faster at d=512 now requires an algorithmic/structural change, not a knob:
1. **Trim the LN-fold gated epilogue** (extra C1/B2/S loads + register-permute pairing) to
   cut the 168-reg / 220-KB budget → possibly 2 mainloop stages or a 2nd CTA/SM. Highest-
   potential but real kernel work in the quack epilogue.
2. **Squeeze**: already ~roofline at d=512 (SM 87%, tensor 91%) — leave it. Note at d=512 the
   squeeze is compute-bound (not HBM-bound as at d=128), which is exactly why b2b fusion (to
   save the h round-trip) does NOT win here — the round-trip isn't the bottleneck.
3. Accept d=512 split as compute-ceiling-bound and ship the confirmed config.
