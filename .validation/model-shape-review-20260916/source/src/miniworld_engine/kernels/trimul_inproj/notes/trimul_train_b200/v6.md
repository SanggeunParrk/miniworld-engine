# trimul_train_b200 v6 — kill the LLD<->DLL permutes (coalesced tiled transpose)

## Goal
Eliminate the permute copies that v5 nsys showed dominate the backward (direct_copy 6.04 ms/iter =
36% @ L=1024), plus the forward tri_lld permute.

## Blocker found on the "clean" approach (m-major dgrad output) — documented, then routed around
Item 1 of the plan (make dgrad_lnbwd_sm100 store dx M-major = DLL directly, dropping the
`d_tri_lld.permute(...).contiguous()`): IMPLEMENTED and TESTED — but it is a GENUINE correctness
blocker. Standalone dx cos DROPS to 0.982 (relmean 0.2) with m-major D vs 0.999999 n-major.
Root cause: the tcgen05 t2r fragment for an M-major D output is laid out M-CONTIGUOUS, so the
in-register LN row-reduction (`colvec_reduce_accumulate` sums over fragment mode[1]) sums over the
wrong axis (M instead of N=K). The LN reduction over N would then need a cross-WARP smem reduction
(a RowVecReduce-style op quack does not provide for the single-subtile in-visit finalize). So
flipping d_layout transposes the reduction dimension — not a drop-in. Reverted; kept dgrad n-major.
(Note: the H100 `training.py` reference ALSO does these permutes verbatim — it does not avoid them;
the H100 dgrad_lnbwd is wired into a different standalone LayerNormLinear, not this trimul path.)

## What shipped (correct, same values)
`training_b200.py`: replace the 4 `.permute(...).contiguous()` LLD<->DLL transposes with the
front's COALESCED tiled triton transpose (`front_sm100._transpose_kernel`, a (M,N)->(N,M) tiled
transpose). torch `.permute().contiguous()` uses an UNCOALESCED generic copy (~2.3 ms per L=1024
transpose); the tiled kernel is ~0.1 ms. Same bit values, just coalesced.
  - bwd: d_tri (LLD->DLL), d_left, d_right (DLL->LLD)
  - fwd: tri_lld (DLL->LLD)
Each is a 2D (M,D)<->(D,M) transpose (B=1). Gated by MINIWORLD_TRAIN_FAST_PERMUTE (default on).

## Correctness (full trimul fwd+bwd, grads vs fp32 ref; train_recon.py) — UNCHANGED from v5
Values are bit-identical to v5 (same math, faster transpose). L=1024 all tensors:
  dInput 0.99997/7.8e-3 ; dWL/dWR 0.99997/7.5e-3 ; dW*g 0.99996/8.8-9.2e-3 ; dWp 0.99997/8.1e-3 ;
  dln_in_w 0.99996/8.6e-3 ; dln_out_w 0.99996/8.1e-3.  cos >> 0.9999, relmean ~1.6x cuequiv (inside
  2x bf16 floor). PASS.

## nsys backward breakdown (v6-bwd-only run, L=1024, per iter, /20)  [before -> after permute fix]
  direct_copy (permutes)   6.04 -> 1.29 ms   (the 3 big bwd transposes gone; residual = small casts)

Remaining dominant (per iter): bf16 mul (dy*gate/dy*proj/GLU) 2.23 ; bf16 add (dx_n accum) 1.59 ;
LN Welford/reduce ~2.4 ; gatebwd GEMM 0.59 ; nvjet GEMMs ~1 ; dgrad GEMM 0.19.

## Status / next lever
CORRECT, real 1.5x-at-L1024 win over v5, still ~1.6x behind cuequiv. The remaining gap is
memory-bound ELEMENTWISE (mul 2.2 + add 1.6 + vec-mul 0.8 ~= 4.6 ms/iter) + LN reductions
(~2.4 ms) that cuequiv fuses into its kernels. Next lever (harder, needs kernel-side fusion):
fold dy*gate/dy*proj/GLU-derivative and the dx_n accumulation into the dgrad/gatebwd epilogues
(input-side operand transforms), and fuse LN_in fwd/bwd stat passes. The m-major-dgrad permute
kill is blocked by the reduction-transpose above.
