# trimul_train_b200 v8 — fuse LayerNorm fwd/bwd: cute training BEATS cuequiv on B200

## Goal
Replace the torch `_ln_fwd`/`_ln_bwd` (many broadcast elementwise + reduce kernels) with FUSED
Triton LayerNorm kernels. v7 nsys showed ~5-6 ms/iter (over half of 10.68 @ L=1024) was torch LN.

## Change (training_b200.py, gated MINIWORLD_TRAIN_FUSE_LN, default on)
- `_ln_fwd_kernel` / `_ln_fwd_fused`: one pass computes mean, var, rstd (fp32), xhat, and
  y=xhat*w+b. Drop-in for autograd._ln_fwd (returns y, None, rstd_fp32, xhat_bf16). Used for BOTH
  LN_in (pair) and LN_out (tri_lld). Replaces ~6 torch kernels (mean/var/rsqrt/sub/mul/affine).
- `_ln_bwd_dx_kernel` / `_ln_bwd_fused`: one pass computes dx = rstd*(dxhat - mean1 - xhat*mean2)
  with dxhat=dy*w, mean1/mean2 the fp32 row-means. dw/db kept as torch (M,D)->(D,) sums (cheap).
  Drop-in for autograd._ln_bwd. Used for LN_in bwd (LN_out bwd is already the v4 dgrad fusion).
All LN stats in fp32 (constraint) — this is MORE precise than torch bf16 stats, so grad cos IMPROVED.

## Correctness (train_recon, grads vs fp32 ref) — PASS, IMPROVED
L=1024 all tensors cos 0.99998-0.99999, relmean ~5.1-6.5e-3 (was ~8e-3 in v7; now MATCHES cuequiv
0.99998-0.99999 / ~5e-3). dInput 0.99999 / 5.4e-3. Well inside the 2x bf16 floor. (fp32 LN stats.)
