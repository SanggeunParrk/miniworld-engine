# trimul_bidir_b200 v3 — v6-FAITHFUL sm100 port -> 0 physical transposes, beats v2 at all L

## Goal
Re-write the bidirectional trimul TRAINING path (fwd+bwd) in the H100 PRODUCTION
`bidir_training.py` structure ported to sm100 — the SAME transformation that made single-dir
v12 (`v6_training_merged_sm100.py`) beat both v11 and cuequiv. Target: **0 physical transpose
kernels** (v2 has 8/iter) and **faster than the current bidir v2**.

## Environment
- B200 (sm_100a), cap (10,0), torch 2.10.0+cu128. Branch `perf/trimul-bidir-b200`, worktree
  `~/psk/mw-bidir`. B=1, d_pair=d_hidden=128 (h=128, H=2h=256), bf16 in / fp32 acc
  (fp32 LN stats) / bf16 out.

## Composition — `kernels/trimul_inproj/cute/bidir_training_sm100.py::BidirBackHalfSm100`
BYTE-FOR-BYTE port of H100 `bidir_training.BidirBackHalf`, identical autograd.Function
structure / op order / layout contract. The ONLY change vs the H100 bidir path is the FRONT:
the sm90 `trimul_inproj_cute_forward(bdll_direct=True, out_hidden=2h)` gated-GLU M-major store
(silently half-writes on sm_100) is replaced by the sm100 `trimul_front_sm100_train`
(non-gated m-major GEMM `x@b_lr -> preact[4H,L,L]` + Triton GLU pass -> left/right[2H,L,L]),
producing the SAME (left_bdll, right_bdll, preact_bdll) at out_hidden=H=2h with 0 transposes.
This is exactly the front reused from single-dir v12 — for bidir, `H=2h=256` and
`b_lr = prepack_lr_operand_sm100(WL,WLg,WR,WRg)` on the full (d,2h) weights.

Everything else is the H100 bidir path VERBATIM (all arch-agnostic; each op already proven on
sm100 by the v12 single-dir port):
- TWO `torch.bmm` contractions via transpose-VIEWS (zero-copy): outgoing `bmm(lf[:h], rf[:h].T)`,
  incoming `bmm(lf[h:].T, rf[h:])`, then `cat -> tri (H,L,L)`. bwd uses the CONTIGUOUS-grad
  formulas (outgoing `dl=G@R, dr=Gᵀ@L`; incoming `dl=R@Gᵀ, dr=L@G`), so every bmm output is
  contiguous — no relayout.
- `_te_forward/_te_backward` (LN_out+@Wp, cuBLAS+Triton, m-major in -> m-major out) makes
  `view = tri.reshape(H,M).t()` and `d_tri = d_view.t().reshape(H,L,L)` FREE contiguous views.
- `gate_elem_*` (triton), `front_bwd_dW` (triton; dW cuBLAS).
- `dxn = torch.mm(d_glogit, Wg.t()); dxn.addmm_(dconc.t(), W_stack)` — the gate input-grad + the
  x_n-add fused into one in-place cuBLAS addmm (v12 style; the H100 bidir `dispatch.pick` /
  quack-cute C-add wrapper is dropped: the addmm eager path never regresses and drops the
  quack import from backward).

### Why this kills all 8 v2 transposes
v2 (`bidir_training_b200.py`) uses `_fast_T` 8×/iter: front gated store (×2), tri->LN_out (×1),
d_tri LLD->DLL (×1), d_left/d_right (×4). The v6 structure removes every one: the m-major LN
in/out views make tri<->LN free, the contiguous-grad bmm formulas make d_left/d_right
contiguous, and the non-gated m-major front needs no store transpose.

fused-kernel + transpose approach on B200.
