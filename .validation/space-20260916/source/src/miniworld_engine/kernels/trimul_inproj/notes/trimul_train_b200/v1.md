# trimul_train_b200 v1 — faithful save-heavy forward (H100 training.py port, foundation)

## Goal
Port the H100 TRAINING algorithm (`cute/training.py` = `TriMulInprojFn`) to B200 faithfully:
same math / fusion structure / autograd graph, only the GEMM backend of the forward front
changes (quack WGMMA -> sm100 tcgen05 gated-GLU collective). Beat B200 cuequiv fwd+bwd.

## Baseline (B200, do_bench fwd+bwd, median; GPU 0)
| L    | cuequiv | cute_b200 (v0 naive) | v0/cuequiv |
|------|---------|----------------------|-----------|
| 384  | 1.31    | 3.04                 | 0.43x     |
| 768  | 3.94    | 9.69                 | 0.41x     |
| 1024 | 6.93    | 20.47                | 0.34x     |

## Backward stage breakdown (torch, L=1024) — evidence for the bottleneck
    recompute_backhalf (tri einsum + LN_out fwd + gate + proj) : 3.61 ms   (einsum_tri alone = 0.23 ms!)
    backhalf GEMMs (d_proj@Wp.t + 2 dW + dxn)                   : 1.02 ms
    LN_out bwd                                                  : 2.64 ms
    bmm_bwd (2 einsums + permutes)                              : 2.85 ms
    front gated_bwd (L+R)                                       : 2.78 ms
    LN_in bwd (+ stat recompute)                                : 4.54 ms
=> The cost is MEMORY-BOUND LayerNorm fwd/bwd + LLD<->DLL permutes + recompute, NOT the GEMMs
   (einsum_tri is 0.23 ms). This is exactly what the H100 fused epilogues (dgrad_lnbwd,
   dab_lnbwd, backward_gatebwd) target: fuse LN-bwd into the GEMM epilogue, kill the roundtrips.

## v0 deviation from training.py
v0 (git eb41ca4) used the max-fusion INFERENCE forward (fused triton back, saves nothing), so its
backward RECOMPUTED the entire back-half (tri + LN_out + gate + proj) and the LN_in stats. H100
`training.py` is SAVE-HEAVY (saves x_n, xhat_in, rstd_in, left_b, right_b, xhat_out, rstd_out,
out_n, gate, proj) so its backward recomputes NOTHING. v1 restores that faithful contract.

## Change (v1)
Rewrote `training_b200.py`:
 - forward: LN_in via `_ln_fwd` (fp32 stats saved) -> mask -> FAST sm100 tcgen05 front
   (`trimul_front_sm100_fused`) for left_b/right_b (bdll) -> einsum tri -> LN_out via `_ln_fwd`
   (saved) -> gate=sigmoid(x_n@Wg), proj=out_n@Wp, y=proj*gate. Saves all back-half intermediates.
 - backward: identical stage-for-stage to `training.py.backward` (plain torch/cuBLAS GEMMs,
   front pL/gL/pR/gR recomputed from x_n via `gated_bwd`), NO forward recompute.

## Validation (train_recon.py, grads vs fp32 autograd; cos / relmean / maxabs)

## Result / honest read
v1 is marginally faster (2-3%) and, crucially, CORRECT and faithful. It is NET-NEUTRAL because
removing the backward recompute just moved that same memory-bound LN/permute work into the
forward — do_bench measures fwd+bwd together. This CONFIRMS the bottleneck is unfused memory-bound
LN + permutes, and establishes the save-heavy contract that a fused backward needs. The win
requires porting the H100 fused epilogues (fuse LN-bwd + dgrad into the tcgen05 GEMM epilogue,
store d_tri bdll zero-copy) — next rounds.
