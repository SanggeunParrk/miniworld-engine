# trimul_train_b200 v2 — port H100 backward_gatebwd fused gate-backward to sm100 tcgen05

## Plan
Port the H100 fused gate-BACKWARD kernel (`transition/cute/backward_gatebwd.py`,
`GemmDLnGatedMixin`) onto the tcgen05 Blackwell collective and rewire the trimul front
backward to use it (== training.py `gated_bwd` math). One dual-accumulator GEMM recomputes
the front pre-activations from x_n and applies the GLU gate-backward IN the epilogue, emitting
interleaved [d_glogit|d_p]; downstream d_xn/dW then run as single 2N GEMMs.

## How the port maps to sm100
quack epilogue framework is arch-aware: `GemmGatedSm100` + gated postact (`self.arch==100`
branch in `epi_setup_postact`/`epi_convert_postact`) + dgate activations all support sm100.
So the port is: `class GemmDLnGatedSm100(GemmDLnGatedMixin, GemmSm100)` (swap the GemmSm90 base
-> GemmSm100), sm100 `default_config` (tile 256x256, cluster (2,1), dynamic-persistent), glu
activation. Trimul x_n is pre-normalized so the LN-fold affine is a no-op (rstd=1, c1=S=B2=0),
same as `transition_expand_gatebwd_cute`. The sm100 kernel takes 2 extra call args (mSFA,mSFB
blockscale placeholders) vs sm90 — handled. New file: `cute/gatebwd_sm100.py`.

## Result
Correct, validated port of one named H100 fused backward kernel to sm100 tcgen05, ~1.8x on the
front-side backward, ~1.3 ms off the full L=1024 step. Real but incremental (front is ~15% of
the backward). Still above cuequiv — the larger levers are the LN-backward fusions
(dgrad_lnbwd / dab_lnbwd) which remove the memory-bound LN_out_bwd (2.6 ms) + LN_in_bwd + the
LLD<->DLL permutes.
