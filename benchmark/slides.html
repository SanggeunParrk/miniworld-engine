TRACK 01 · Triangle Multiplication

Architecture — two fused kernels around one bmm

아키텍처 — bmm을 사이에 둔 두 개의 융합 커널

Fusion: fuse left+right into one gated GEMM; the bdll direct write removes the transpose (TMA); fold LN_in into the GEMM. → best at every L, 1.87 ms @ L=1024 vs cuEquiv 2.57.퓨전: 좌+우를 하나의 gated GEMM으로; bdll 직접 기록으로 transpose 제거(TMA); LN_in folding. → 모든 L에서 최고, L=1024서 1.87 ms vs cuEquiv 2.57.

TRACK 01 · Transition (SwiGLU MLP)

Architecture — fusion removes HBM round-trips

아키텍처 — 융합으로 HBM 왕복 제거

Fusion: back-to-back fuse LN + expand + SwiGLU + squeeze into one launch — the 4×-wide hidden h stays in SMEM, zero HBM round-trips. → ~5.5× vs PyTorch (1.24 ms vs 6.67 @ 1024).퓨전: LN + expand + SwiGLU + squeeze를 한 번의 launch로 b2b 융합 — 4× 넓은 h가 SMEM에 상주, HBM 왕복 0회. → PyTorch 대비 ~5.5× (1024서 1.24 ms vs 6.67).

TRACK 01 · LayerNorm + Linear

Architecture — LN folded into the GEMM epilogue

아키텍처 — LN을 GEMM epilogue에 folding

Fusion: compute LN mean/rstd inside the GEMM tile loop and fold normalize+affine into the epilogue — X̂ never reaches HBM. → beats TransformerEngine at every (M, d); note TE drops below compiled PyTorch at large d.퓨전: GEMM 타일 루프 안에서 LN mean/rstd를 계산하고 normalize+affine을 epilogue에 folding — X̂가 HBM에 안 감. → 모든 (M, d)에서 TE 능가; 큰 d에선 TE가 compiled PyTorch 아래로.

벽 — 그리고 기존 해법이 부족한 이유

단일 GPU 벽 ~1–3k residue (pair 표현 O(N²); LLM 대비 ≈100× 커널 런치).

TRACK 02 · the gap빈 자리

Why go further — co-design, not generic patches

왜 더 나아가야 하나 — 범용 패치가 아닌 공동설계

Each existing line solves one axis generically. None co-designs fused kernels + op-aware chunking for AF3 inference on a single GPU — where the gains compound.기존 방법들은 각자 한 축을 범용적으로 풉니다. 융합 커널 + op별 chunking을 AF3 단일 GPU 인퍼런스에 공동설계한 사례는 없고, 거기서 이득이 곱해집니다.
  • 1Chunking / streaming of the O(N²) pair representation, op-aware.O(N²) pair 표현의 op-인지 chunking / 스트리밍.
  • 2CPU offload for cold tensors, overlapped with compute.cold 텐서 CPU offload, 연산과 오버랩.
  • 3Inference-only fused paths — fewer intermediates → less memory and less recompute than chunking alone. cuEquivariance is not the speed ceiling.인퍼런스 전용 융합 경로 — 중간텐서↓ → chunking만 할 때보다 메모리·recompute 둘 다 절감. cuEquivariance는 속도 한계가 아님.
