# B200 (sm100)

NVIDIA B200 × 8 (148 SMs, 183 GB each), sm_100a, driver 580.95.05. The cards sit in a
container on a lab-external server, **not** in a cssb Slurm partition: there is no scheduler,
the GPUs are shared with other users, and access details are kept outside this repository.

- **Check the card is yours before every measurement**:
  `nvidia-smi --query-compute-apps=pid,process_name,used_memory --format=csv -i <gpu>`.
  Another process on the same GPU silently contaminates timings.
- **Environment**: the repo's pixi env installs and runs as-is (the 580 driver runs the cu129
  build): `pixi install --frozen`, `pixi run --frozen fix-te-cu12`,
  `pixi run --frozen miniworld-engine dev install-flash --arch sm100` (FA4 4.0.0b32).
- **Keep every cache on persistent disk**: `/tmp` is a tmpfs (RAM) and the home directory is
  container-local. Point `TMPDIR`, `PIXI_CACHE_DIR`, `RATTLER_CACHE_DIR`, `UV_CACHE_DIR`,
  `TRITON_CACHE_DIR`, `TORCH_EXTENSIONS_DIR` and `MINIWORLD_ENGINE_JIT_ROOT` at the shared
  workspace.
- **Power cap**: 1000 W per card. Under sustained load the SM clock settles near 1.89 GHz, so
  bandwidth- and tensor-bound kernels are limited by energy before they reach the datasheet
  rates.
- **Profiling**: the driver sets `RmProfilingAdminOnly=1`; `ncu` needs root on this machine.
  `ncu` also locks the SM clock (~930 MHz): compare cycles, not times.
- **cuEquivariance 0.12** ships sm_100a images in the cu12 wheel. Its B200 TriMul route is
  inference-only and admits hidden 256 with d_pair 256 / 384 / 512; D128 runs its generic path.
- **Anthropic on B200** (the measurement tables' Anthropic column): the release has no B200 kernel. Its TriMul ships two members,
  sm_90a (TMA + `wgmma`, H100) and sm_80 (`cp.async` + `mma.sync`, A100); `wgmma` does not exist on sm_100 (ptxas refuses the
  sm_90a sources for sm_100a), so the column is the **sm_80 member** built for sm_100a from the unmodified sources
  (`miniworld-engine dev build-anthropic-sm100a`, [anthropic-trimul-payload.md](../../kernels/anthropic-trimul-payload.md#b200-sm_100)).
  It is Anthropic's code, but tuned for A100 (tiles, 164 KB shared memory), not for B200, and it is a different kernel from
  the H100 column (sm_90a). Served: one direction D64-D384, bidirectional D64 / D128.
- **LayerNorm / RMSNorm** (`implementation=MINIWORLD`): on a B200 these resolve to PyTorch ops that `torch.compile` fuses, not to the
  engine's Triton kernels (`modules/dispatch._torch_on_b200`); every other card keeps CUDA (LayerNorm) / Triton (RMSNorm).
  `settings.b200_engine_triton = True` brings the engine kernels back on a B200 (the A/B switch) and a strict
  `engine_backend="triton"` process still wins. A caller that does not compile pays the unfused PyTorch ops. The PyTorch
  `RMSNorm` returns the input dtype like the kernel (torch's `rms_norm` would return fp32 under autocast).
- **nvcc for the fused Transition**: its kernels are built by the newest nvcc that knows sm_100a
  (`/usr/local/cuda-13.1` on the B200 box); CUDA 12.9's ptxas makes its backward ~8 % slower.
- Completion per shape: [below](#completion-status).
- Hand-written sm_100a paths (gated on compute capability 10.0), one page each:
  [TriMul](trimul/trimul.md), [TriangleAttention](triattn/triattn.md), [Transition](transition/transition.md), [token
  DiT](token_dit/token_dit.md), [bias-only token DiT](bias_only_dit/bias_only_dit.md) (inference, training),
  [AttentionPairBias](attention_pair_bias/attention_pair_bias.md), [OuterProductMean](opm/opm.md),
  [MSAPairWeightedAveraging](pwa/pwa.md) (the last two through their H100 integrations with sm_100a kernels,
  `integrations/csrc/sm100/`). The AF3-style atom DiT block runs hand-written sm_100a kernels for the whole block
  (`integrations/atom_dit.py`): [atom DiT](atom_dit/atom_dit.md). The AF3 block-local atom block (32 x 128 windows, trunked pair bias) runs hand-written sm_100a kernels for every stage: [local DiT](local_dit/local_dit.md). The SWA atom DiT block runs hand-written sm_100a kernels for
  every stage (`kernels/swa_dit/cuda/sm100`): [SWA atom DiT](swa_atom_dit/swa_atom_dit.md). The input embedder's token-pair
  initialisation is one kernel pair (`kernels/token_pair_init`): [token pair init](token_pair_init/token_pair_init.md).

shapes and modules no CUDA path takes.
