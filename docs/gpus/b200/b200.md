# B200 (sm100)

Cluster: cssb (the same cluster as H100/A100). Partition, QoS and node names: **to fill in**
when B200 work starts in this repo.

- v2.2.0 had no sm100-specific kernels (the CuTe DSL ones were removed). The first hand-CUDA
  B200 path is the pair Transition (n = 4, bf16, D64-512: `kernels/transition/cuda/fused_sm100a.py`
  at D128, `fused_wide_sm100a.py` at the other widths; [transition/transition.md](transition/transition.md));
  every other op runs its Triton path, and sm90 hand-CUDA kernels are not selected.
- The fused Transition's kernels are built by the newest nvcc that knows sm_100a (on the B200 box,
  `/usr/local/cuda-13.1`): CUDA 12.9's ptxas makes its backward ~8 % slower.
- No B200 autotune cache exists yet: build one with `miniworld-engine build all` on a B200
  allocation after installing the env there.
- FA4 supports sm100: `miniworld-engine dev install-flash --arch sm100`.
- Completion per shape: [below](#completion-status).

## Completion status

Facts as of 2026-09-28 (v2.2.0). Rules: [README](../README.md#completion-tables).

v2.2.0 removed the CuTe DSL kernels that were the only sm100-specific code; nothing in
`kernels/registry/registry.csv` declares sm100. The pair Transition at n = 4 / bf16 / D64-512 now has
a hand-CUDA sm_100a path (2026-09-29); every other op below runs its **Triton** (sm80+) path on B200,
and the sm90 hand-CUDA kernels are not selected (their dispatch checks compute capability 9.0).
No B200 autotune cache exists (`src/miniworld_engine/autotune/data/*/` has no sm100 file).
