# B200 (sm100)

NVIDIA B200 × 8 (148 SMs, 183 GB each), sm_100a, driver 580.95.05. The cards sit in a
container on a lab-external server, **not** in a cssb Slurm partition: there is no scheduler,
the GPUs are shared with other users, and access details are kept outside this repository.

- **Check the card is yours before every measurement**:
  `nvidia-smi --query-compute-apps=pid,process_name,used_memory --format=csv -i <gpu>`.
  Another process on the same GPU silently contaminates timings.
- **Environment**: the repo's pixi env installs and runs as-is (the 580 driver runs the cu129
  build): `pixi install --frozen`, `pixi run --frozen fix-te-cu12`,
  `pixi run --frozen miniworld-engine dev install-flash --arch sm100` (FA4 4.0.0b32).
- **Keep every cache on persistent disk**: `/tmp` is a tmpfs (RAM) and the home directory is
  container-local. Point `TMPDIR`, `PIXI_CACHE_DIR`, `RATTLER_CACHE_DIR`, `UV_CACHE_DIR`,
  `TRITON_CACHE_DIR`, `TORCH_EXTENSIONS_DIR` and `settings.engine_jit_root` at the shared
  workspace.
- **Power cap**: 1000 W per card. Under sustained load the SM clock settles near 1.89 GHz, so
  bandwidth- and tensor-bound kernels are limited by energy before they reach the datasheet
  rates.
- **Profiling**: the driver sets `RmProfilingAdminOnly=1`; `ncu` needs root on this machine.
  `ncu` also locks the SM clock (~930 MHz): compare cycles, not times.
- **cuEquivariance 0.12** ships sm_100a images in the cu12 wheel. Its B200 TriMul route is
  inference-only and admits hidden 256 with d_pair 256 / 384 / 512; D128 runs its generic path.
- **Anthropic on B200** (the measurement tables' Anthropic column): the release has no B200 kernel. Its TriMul ships two members,
  sm_90a (TMA + `wgmma`, H100) and sm_80 (`cp.async` + `mma.sync`, A100); `wgmma` does not exist on sm_100 (ptxas refuses the
  sm_90a sources for sm_100a), so the column is the **sm_80 member** built for sm_100a from the unmodified sources
  (`miniworld-engine dev build-anthropic-sm100a`, [anthropic-trimul-payload.md](../../kernels/anthropic-trimul-payload.md#b200-sm_100)).
  It is Anthropic's code, but tuned for A100 (tiles, 164 KB shared memory), not for B200, and it is a different kernel from
  the H100 column (sm_90a). Served: one direction D64-D384, bidirectional D64 / D128.
- **LayerNorm / RMSNorm** (`implementation=MINIWORLD`) on a B200 run the general CUDA kernels (`kernels/layernorm/cuda/general`,
  `kernels/rmsnorm/cuda`, built for sm_100; measured on H100 only, `docs/records/layernorm_general_cuda_h100_20261018.md`,
  `docs/records/rmsnorm_general_cuda_h100_20261018.md`), as on an H100. Before 2026-10-18 they resolved to PyTorch ops here. Every other
  card keeps CUDA (LayerNorm) / Triton (RMSNorm). `settings.b200_portable_kernels = True` brings the engine's Triton RMSNorm back on a B200
  (the A/B switch) and a strict `force_portable_kernels=True` process still wins. RMSNorm returns the input dtype like the kernel (torch's
  `rms_norm` would return fp32 under autocast).
- **nvcc for the fused Transition**: its kernels are built by the newest nvcc that knows sm_100a
  (`/usr/local/cuda-13.1` on the B200 box); CUDA 12.9's ptxas makes its backward ~8 % slower.
- **fp32 master parameters (AMP `bf16-mixed`)**: every B200 training path takes fp32 parameters over bf16 activations at
  the same speed as bf16 parameters -- TriMul, Transition (D 64-512), AttentionPairBias, OuterProductMean,
  MSAPairWeightedAveraging, TriangleAttention, token / bias-only DiT, local and SWA atom DiT, token pair init. The
  integration casts the parameters to the kernels' dtype inside its autograd function (outside autograd) and hands back
  the kernels' fp32 weight-gradient accumulators unrounded, in each parameter's own dtype (bf16 parameters get them
  rounded once, as before). A cast left in autograd would also serve, but rounds the fp32 gradient to bf16 values and
  costs a copy per call. Test: `tests/gpu/sm100/test_b200_fp32_master_gpu.py`.
- Completion per shape: [below](#completion-status).
- Hand-written sm_100a paths (gated on compute capability 10.0), one page each:
  [TriMul](trimul/trimul.md), [TriangleAttention](triattn/triattn.md), [Transition](transition/transition.md), [token
  DiT](token_dit/token_dit.md), [bias-only token DiT](bias_only_dit/bias_only_dit.md) (inference, training),
  [AttentionPairBias](attention_pair_bias/attention_pair_bias.md), [OuterProductMean](opm/opm.md),
  [MSAPairWeightedAveraging](pwa/pwa.md) (the last two through their H100 integrations with sm_100a kernels,
  `integrations/csrc/sm100/`). The AF3 block-local atom block (32 x 128 windows, trunked pair bias) runs hand-written sm_100a kernels for every stage: [local DiT](local_dit/local_dit.md). The SWA atom DiT block runs hand-written sm_100a kernels for
  every stage (`kernels/swa_dit/cuda/sm100`): [SWA atom DiT](swa_atom_dit/swa_atom_dit.md). The input embedder's token-pair
  initialisation is one kernel pair (`kernels/token_pair_init`): [token pair init](token_pair_init/token_pair_init.md). The diffusion loss's
  AF3 smooth lDDT term is sm_100a kernels (bit-mask pair sets, whole-structure and tile variants) with an analytic backward (`kernels/smooth_lddt`): [smooth lDDT](smooth_lddt/smooth_lddt.md). The Boltz-2 / RoseTTAFold3 / Chai-1 DiT stacks (`modules/dit_variant`, token and atom, inference and training, bf16 and fp32) run the token DiT's and the local DiT's sm_100a cores around their own CUDA rows: [model variants](model_variants/model_variants.md).

### TriangleAttention — [triattn/triattn.md](triattn/triattn.md)

The self-attention variant (`use_self_attention=True`), starting and ending node, any L >= 16 (a length that is not a multiple of
128 runs zero-padded with the pad keys masked). d_pair 64 covers its three registered head layouts (4 × 16, 4 × 32 with d_hidden
128, 2 × 32); d_pair 128 is the fused 4 × 32 path; 256 / 384 / 512 are 8 / 12 / 16 heads of 32 channels. Heads of 64 channels
(Chai-1, RF3 templates, IntelliFold-2) and FoldForge's model options (AF3 bias orientation, RF3 biases, Chai-1's untransposed / dual
outputs) run on the wide kernels, inference and training (2026-10-29). Heads of 96 / 128 channels, the bias-only variant and
`BidirectionalTriangleAttention` run the PyTorch statements.

Batched samples (2026-10-20, [triattn/triattn.md](triattn/triattn.md#batched-samples-b--1-any-length-and-chunking-2026-10-20)): B
samples in one call on both paths, up to `max_batch` = 48 per launch, more (or more than fit in memory) in deterministic chunks
(`plan`: shapes, node, mode and the device's total memory; never an OOM or a PyTorch fallback because of B or L); y bitwise equal to
B one-sample calls; L 1536-2560 served for inference and training. The attention core's forward runs long launches in groups of
~36 864 tasks (inference L768 B48 1.05x); `settings.triattn_b200_deterministic_wgrad=True` makes the fused path's parameter
gradients the same bits every run (per-CTA partials summed in a fixed order; +0.2-1.3 % on the B = 1 training step; off by default).
B = 1 unchanged in bits (output) and time (±0.5 %, d_pair 128). The ending node reads and writes the caller's layout through 4-D
tensor maps instead of transposed copies: 0-6 % over the starting node (was 9-67 %), 1.08-1.62x faster than before, same bits. CUDA graph,
bf16-mixed: one call vs B calls 1.00-5.82x where the saved tensors fit (0.93-0.98x for d_pair 256 inference at L768 and the chunked
training cells), 1.96-4.61x over cuEquivariance and compiled PyTorch wherever they run.
