# B200 (sm100)

Cluster: cssb (the same cluster as H100/A100). Partition, QoS and node names: **to fill in**
when B200 work starts in this repo.

- v2.2.0 had no sm100-specific kernels (the CuTe DSL ones were removed); except the token DiT (below), every op runs
  its Triton path, and sm90 hand-CUDA kernels are not selected.
- No B200 autotune cache exists yet: build one with `miniworld-engine build all` on a B200
  allocation after installing the env there.
- FA4 supports sm100: `miniworld-engine dev install-flash --arch sm100`.
- Completion per shape: [below](#completion-status).
- Token DiT: the one op with sm100-specific code -- hand CUDA + cuBLAS on B200 for inference and training, no Triton --
  kernels, dispatch and measurements in [token_dit/token_dit.md](token_dit/token_dit.md).

## Completion status

Facts as of 2026-09-28 (v2.2.0). Rules: [README](../README.md#completion-tables).

v2.2.0 removed the CuTe DSL kernels that were the only sm100-specific code; nothing in
`kernels/registry/registry.csv` declares sm100. The token DiT row (2026-09-29) is the exception: its B200 paths are
hand CUDA + cuBLAS, gated on capability 10.0 (details in its page). Every other op below runs its **Triton** (sm80+)
path on B200, and the sm90 hand-CUDA kernels are not selected (their dispatch checks compute capability 9.0).
No B200 autotune cache exists (`src/miniworld_engine/autotune/data/*/` has no sm100 file).
