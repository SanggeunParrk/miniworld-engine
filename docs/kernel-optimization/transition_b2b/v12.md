## Hypothesis

The v11 row-major output shuffle tile uses:

```text
pOutShuffle[m * 128 + n]
```

With bf16 scalar C-fragment stores, adjacent 2-byte stores and the 256-byte row stride create repeated shared-bank phases. The result is heavy shared-bank replay in the output epilogue. v12 keeps the v11 epilogue structure but changes only the shared tile layout and the store width into that tile:

1. XOR-swizzle each row at 8-bf16 chunk granularity so rows no longer start at the same bank phase for the vector reload chunks.
2. Opportunistically pack adjacent C-fragment column pairs into one 32-bit `st.shared.u32`, removing the 2-byte sub-word store pressure when the fragment presents `(m,n)` and `(m,n+1)` together.
3. Keep the same CTA barrier and the same `ld.shared.v4.u32 -> st.global.v4.b32` vectorized global store path.

Expected NCU movement:

- `l1tex__data_bank_conflicts_pipe_lsu_mem_shared.sum`: `5.77M -> ~0` or at least a large drop.
- `short_scoreboard` and `mio_throttle`: down.
- `issue_active`: up.
- Runtime: faster than v11's `~448 us`, assuming the swizzle arithmetic and 32-bit stores are cheaper than the replay they remove.

## v12 Layout Math

Chosen approach: **XOR swizzle plus 32-bit pair stores**. Padding was not used.

Padding check:

- Original per-WG pXn/output tile footprint: `64 * 128 * 2 = 16384 B`.
- Two WGs: `32768 B`, exactly the existing `pXn` region.
- A padded stride `128 + 8 = 136` would cost `64 * 136 * 2 = 17408 B/WG`, `34816 B/CTA`, exceeding the existing `pXn` region by `2048 B`.
- Because padding overflows `pXn`, v12 avoids smem growth and does not alias the dead TMA weight ring.
- Dynamic smem remains `230944 B`.

Swizzled index:

```c++
row_swizzle = (m & 15) * 8;
smem_idx = m * 128 + (n ^ row_swizzle);
```

Properties:

- The swizzle unit is `8 bf16 = 16 B`, so every vector-reload address remains 16-byte aligned.
- `n` for the reload loop is always a multiple of 8, and `row_swizzle` is also a multiple of 8, so `n ^ row_swizzle` is a multiple of 8.
- The map is a permutation within each 128-element row; no tile footprint growth.
- Rows cycle through sixteen 16-byte bank phases instead of all rows using the same phase.

Fragment store into smem:

```c++
for (int i = 0; i < size(out_acc); i += 2) {
    m0 = get<0>(tCOut(i));
    n0 = get<1>(tCOut(i));
    m1 = get<0>(tCOut(i + 1));
    n1 = get<1>(tCOut(i + 1));

    if (m1 == m0 && n1 == n0 + 1 && n0 is even) {
        pack BF(out_acc(i)), BF(out_acc(i + 1)) into uint32;
        st.shared.u32 to pOutShuffle + smem_idx(m0, n0);
    } else {
        scalar fallback:
        pOutShuffle[smem_idx(m0, n0)] = BF(out_acc(i));
        pOutShuffle[smem_idx(m1, n1)] = BF(out_acc(i + 1));
    }
}
```

Vectorized reload and global store:

```c++
kOutVecsPerRow = 128 / 8 = 16;
vec = wg_tid, wg_tid + 128, ... < 64 * 16;
m = vec / 16;
n = (vec % 16) * 8;
out_vec = ld.shared.v4.u32(pOutShuffle + smem_idx(m, n));
st.global.v4.b32(out[row, n:n+8]);
```

The store and reload use the same `smem_idx(m,n)`, while the global output address remains unswizzled row-major `out[row * 128 + n]`.

    230944 unchanged (swizzle, no padding/alias).
- Verdict: WIN, committed as new best. Approach = XOR swizzle (no smem growth) + opportunistic
  `st.shared.u32` adjacent-pair packing. Residual 2.1M conflicts + barrier 1.01 are the next levers.
