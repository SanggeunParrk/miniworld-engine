## Sync Audit

The active `transition_b2b_rs_wgmma_kernel` had four CTA-wide `__syncthreads()` before v13. The disabled scalar fallback also contains `__syncthreads()` calls under `#if 0`; those are not part of the active kernel path and were left untouched.

CTA-wide syncs kept:

- Pipeline initialization sync, immediately after constructing `PipelineTmaAsync`. This protects CTA-shared pipeline state before thread 0 issues TMA copies and the CTA consumes the pipeline. It is not a per-WG scratch sync.
- LN parameter sync, after `pG`, `pBeta`, `pRstd`, and `pC1` are staged. This is cross-WG: `pG` and `pBeta` are written by `tid < kK`, which is WG0 only, but both WGs read those parameters during normalization. This must remain CTA-wide.

CTA-wide syncs converted:

- Post-normalization `sXn` visibility sync. Each WG writes normalized `xn` only into its own `pXnWg` region and then uses that region as the SS WGMMA A operand. There is no cross-WG `sXn` exchange.
- Output-shuffle reload sync. Each WG writes its own `out_acc` fragment into `pOutShuffle = pXnWg` and then the same WG reloads that tile with `ld.shared.v4`. There is no cross-WG output-shuffle exchange.

The shared TMA weight ring (`pWa`, `pWb`, `pWs`) is not guarded by either converted sync. It remains synchronized by `PipelineTmaAsync` producer/consumer mbarriers via `producer_acquire`, TMA auto-arrival, `consumer_wait`, and `consumer_release`.

## Hypothesis

Replacing the two per-WG scratch barriers with 128-thread named barriers should reduce the `barrier` stall by avoiding CTA-wide participation and cross-WG arrival skew. Expected NCU movement:

- `barrier`: down versus v12 `1.01`.
- `issue_active`: up versus v12 `39.6%`.
- Runtime: faster than v12 `~442 us` if the named-barrier overhead is lower than the saved CTA barrier skew.
- No change expected to register count, spill, dynamic smem, TMA pipeline behavior, bank-conflict layout, or global-store width.

## Mechanism

v13 uses CUTLASS Hopper named barriers:

```c++
const int wg_barrier_id = wg_id + 1;
cutlass::arch::NamedBarrier::arrive_and_wait(kWarpgroupThreads, wg_barrier_id);
```

`kWarpgroupThreads` is `128`. The user-visible CUTLASS barrier IDs are:

- WG0: `wg_barrier_id = 1`
- WG1: `wg_barrier_id = 2`

CUTLASS offsets user IDs by `ReservedNamedBarrierCount`, so these do not use the CTA barrier ID used by `__syncthreads()`. The same per-WG ID is reused for the `sXn` visibility point and the output-shuffle point because those barriers are temporally separated within the kernel.
