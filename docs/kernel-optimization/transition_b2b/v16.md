## Gap Analysis

v14 is still the best standalone hand-CUDA b2b kernel: about `421 us`, roughly `1.29x` of the Triton b2b kernel. When wired into the Transition inference module through `cuda_transition_b2b`, the end-to-end module win is only about `1.20x`.

The module path previously paid a separate `stats_triton(x2, eps)` launch before the hand-CUDA b2b kernel. That pass reads the full `[M,128]` input to compute `rstd` and `c1`, then the CUDA b2b kernel reads `x` again into `sXn` in its prologue before normalizing. Since v14 already stages the full row tile into shared memory, the extra stats kernel is the main removable gap between the standalone kernel win and the module-level win.

## v16 Plan

Fuse LN stats into the existing CUDA b2b prologue:

1. Keep `transition_b2b_fwd(x, rstd, c1, g, beta, wa, wb, ws)` intact for the standalone microbench and any future backward-stats-reuse path.
2. Add `transition_b2b_fwd_fused_stats(x, g, beta, wa, wb, ws, eps)` for module inference.
3. Share the same kernel body through a `bool FUSE_STATS` template flag.
4. Replace the module wrapper's `stats_triton` call with the fused-stats entry point.

Expected benefit: remove one full global pass over `[M,128]` plus one launch from the module path, narrowing the module speedup gap toward the standalone v14 kernel speedup. Expected risk: extra fp32 row reduction work and one additional WG-local barrier in the prologue may increase register pressure or visible latency.

## On-Chip Stats Design

The existing prologue issues `cp.async` copies from global `x` into WG-local `sXn`, with shape `WG_M=64` rows by `K=128`. v16 waits for those copies, then computes stats directly from `sXn`.

Reduction scheme:

- One active thread per row: `wg_tid < WG_M` handles row `m = wg_tid`.
- Each stats thread reads all `128` bf16 values from `sXn(m, k)` and casts to fp32.
- Two-pass population variance to match `stats_triton` numerics:
  - `mean = sum(x) / 128`
  - `var = sum((x - mean) * (x - mean)) / 128`
  - `rstd = rsqrt(var + eps)`
  - `c1 = mean * rstd`
- Store `rstd` and `c1` into the existing shared-memory `pRstd[cta_m]` and `pC1[cta_m]`.
- Guard `row < M`; invalid boundary rows write zero stats.

Synchronization:

- Fused path adds a WG-local named barrier after `cp_async_wait<0>()` so every stats thread can read row elements staged by other threads.
- The existing WG-local named barrier before normalized-xn construction remains, so `pRstd/pC1` are visible before all threads read them.
- The precomputed-stats path still loads `rstd/c1` from global and uses the same downstream normalization and GEMM path.

## Code Changes

- `transition_b2b_rs_wgmma_kernel` gained template flag `FUSE_STATS` and an `eps` kernel argument.
- Precomputed path:
  - `transition_b2b_fwd(x, rstd, c1, g, beta, wa, wb, ws)`
  - loads `rstd/c1` from global exactly for the rows in the CTA.
- Fused-stats path:
  - `transition_b2b_fwd_fused_stats(x, g, beta, wa, wb, ws, eps)`
  - passes null `rstd/c1` pointers and computes stats from `sXn`.
- Shared host launcher `launch_transition_b2b<FUSE_STATS>` builds the same TMA descriptors and launches the selected template instantiation.
- Module wrapper `cuda_transition_b2b(x, ln_weight, ln_bias, wa, wb, ws, eps)` now calls `transition_b2b_fwd_fused_stats` directly and no longer imports or calls `stats_triton`.

- Stats visibility: fused path needs the added barrier after x staging and the existing barrier before normalized-xn reads.

  FUSE_STATS is the wrong structure for the CUDA b2b (reverted; wrapper keeps stats_triton).
