# bidirectional triangle attention — fused starting+ending (v1)

**GPU:** H100 (sm90). **Shape:** d_pair=512, n_head=4, L=384, bf16 (per-dir HEAD_DIM=128, d_hidden=512).

`BidirectionalTriangleAttention` computes the **starting** and **ending** triangle attention of
one shared LayerNorm'd pair in a single block (doubled-width projections split into
`[starting | ending]` halves, concat to `2*d_hidden`, one gate + `to_out`). Mirrors
`BidirectionalTriangleMultiplication`. This round adds the **self-attention (Q/K/V)** variant
(was bias-only) and a fused kernel path.

## Result (fwd+bwd, vs 2× single-direction `TriangleAttention`)

| variant | bidir (1 block) | 2× single-dir | speedup |
|---|---|---|---|
| **self-attention** | **10.65 ms** | 13.23 ms | **1.24×** |
| bias-only | 7.36 ms | 8.25 ms | 1.12× |

Correct: TRITON vs PYTORCH fwd cos 0.99999, grad_pair cos 0.99998 (both variants).

## The self-attention win — reuse the v7 kernels, no new kernel

Naive self-attention bidir (reuse the single-dir v7 kernel per direction; ending via
`q_e.transpose(i,j)` view in, `out.transpose` + `cat` out) measured **15.25 ms** — a 0.87×
LOSS vs 2× single-dir. Kernel breakdown: **21.5 % (3.26 ms/step) was transpose/concat/scatter
materialization** (not the attention kernels). The reads can't be sped up (the ending's strides
are physical), but the *copies* can be removed.

**`bidir_triangle_attention_pair_bias`** (new autograd Function, `triton/bidirectional.py`) runs
the v7 kernels (`_attn_fwd` / `_attn_bwd_*`) **twice**, writing every tensor directly into shared
`[B,L,L,2*d_hidden]` concat buffers:
- **starting** = tensors as-is (row = i).
- **ending** = the (i↔j)-transposed VIEWS (row = j); the OUTPUT is *also* a transposed view into
  the concat's ending slice, so the kernel writes the ending result straight into `[i,j]` layout
  — no explicit transpose, no `cat`. The kernels are fully stride-parametrized, so this is pure
  I/O-stride bookkeeping, **not a new kernel**.
- The Function takes the DOUBLED q/k/v `[B,L,L,2*d_hidden]` and returns the concat output + doubled
  grads, so `split`/`cat`/`transpose` never enter the autograd graph (their bwd copies are gone).

Result: 15.25 → **10.65 ms**, flipping the 0.87× loss into a 1.24× win.

## Requirement: grad-stride decouple in the v7 backward

The doubled projection makes q/k/v strided slices (token stride `2*d_hidden`), while the bwd
allocates dq/dk/dv in a fresh `[.,H*D]` (`d_hidden`) layout — the v7 bwd had reused `q.stride()`
for the dq write → wrong-stride write → NaN. Fixed by threading a separate grad-stride group
(`gs_*`) into `_attn_bwd_dq`/`_attn_bwd_dkdv` (write dq/dk/dv via `dq.stride()`, decoupled from the
q read strides). Algorithm-invariant; regression-verified a no-op for the single-direction path
(cos 0.99998, step unchanged). This also generalizes the kernel to arbitrary q/k/v input strides.
