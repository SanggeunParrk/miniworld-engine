# triangle_attention `_attn_bwd` — v1: register-wall diagnosis (NO SHIP)

**GPU:** H100 (sm90).  **Shape:** d_pair=512, L=384, n_head=4 → HEAD_DIM=128, B=1, bf16.
**Kernel:** `src/miniworld_kernels/kernels/triangle_attention/triton/main.py :: _attn_bwd`
(+ inlined `_attn_bwd_dqdkdv`). Flash-attention-style backward: fix a `BLOCK_N` kv-block,
loop over all query rows `m`, accumulate `dk`/`dv` in registers, `dq` via `atomic_add`.

## Verdict

**No profitable change found. Baseline `_attn_bwd` is at a hard register wall and is
already at the autotuner's Pareto optimum for this shape.** Documented so we don't
re-attempt the same dead ends.

## Profile (baseline, ncu, winning autotune config BLOCK_N=64 / num_warps=4 / stages=3)

| metric | value | reading |
|---|---|---|
| registers/thread | **255** (CUDA max → spilling) | register-starved |
| occupancy limiter | **registers → 2 blocks/SM** | hard cap |
| achieved occupancy | **12.5 %** | very low |
| SM throughput | 9 % | not compute-bound |
| memory throughput | 48 % | not bandwidth-bound |
| dominant stall | **long_scoreboard 8.55 cyc/issue** | waiting on global loads |
| lg/mio throttle | ~0.001 / 0.03 | atomics + spill traffic NOT the bottleneck |

Root cause: the persistent fp32 accumulators `dk`,`dv` of shape `[BLOCK_N, HEAD_DIM=128]`
demand ~128 reg/thread on their own; with the transient `[BLOCK_N,BLOCK_M]` tiles
(`qkT`,`pT`,`dpT`,`dsT`) plus `qT`/`do`/`k`/`v` the kernel wants >255 reg/thread and
spills. This pins occupancy at 12.5 % (2 blocks/SM) so the global-load latency
(long_scoreboard) can't be hidden.

## Levers tried — all negative

1. **copy-elimination (strided q/k/v consumption)** — separate track (see the module
   `.contiguous()` removal). Result: **nan** (kernel addressing bug) **and slower**
   (12.08 vs 10.98 ms/layer). The `.contiguous()` transpose is a *good* tradeoff, not
   waste: one-time coalesced copy ≪ repeated strided inner-loop loads. Abandoned.

2. **autotune-config expansion** — added num_warps=8, num_stages=2, BLOCK_N=32 variants.
   Autotuner picked **none** of them; step unchanged (10.973 vs 10.982 ms). Baseline
   config already optimal.

3. **force num_warps=8** (block=256) — registers **stay 255** (Triton doesn't shrink
   per-thread demand), occupancy_limit drops to **1 block/SM** → same **12.5 %** occ,
   duration **5.65 ms** (worse than 4.76). More warps ≠ more occupancy here.

4. **force BLOCK_N=32** (halves the `dk`/`dv` accumulators, no recompute) — the decisive
   test of "shrink accumulators → raise occupancy": registers only **255→234**
   (transients/other state still dominate), occupancy **still 2 blocks / 12.46 %**
   (unchanged!), duration **9.27 ms** (~2× slower — 2× the n-blocks ⇒ 2× redundant
   `q`/`do` loads ⇒ more long_scoreboard).

## Why the "obvious" rewrites won't work

- **head-dim (BLOCK_D) accumulator tiling** (process HEAD_DIM in 64-chunks): only halves
  the accumulator registers — but lever #4 proved halving accumulators leaves total
  demand at ~234 → still 2 blocks/SM → **no occupancy gain**, while adding recompute of
  `qkT`/`dpT` and a 2nd pass of `q`/`do` loads on an already load-bound kernel ⇒ certain
  regression. Not worth writing.
- **FA2-style two-kernel split (dq without atomics)**: atomics are not the bottleneck
  (lg_throttle ≈ 0.001), and the dk/dv kernel still holds both `[*,128]` accumulators ⇒
  same register wall. No expected win.

## Conclusion / where a real win would have to come from

`_attn_bwd` is genuinely register-bound at 12.5 % occupancy for HEAD_DIM=128, and no
tile/warp/stage/accumulator-size tuning crosses the occupancy threshold (need ≤170
reg/thread for 3 blocks, ≤128 for 4; the demand floor is ~234+). A real improvement
requires a fundamentally different implementation with explicit register/shared-memory
management (CUTLASS/CuTe, as done for trimul on B200) — a major project, not a Triton
tweak. Recommend treating the Triton `_attn_bwd` as near-optimal for this shape.
