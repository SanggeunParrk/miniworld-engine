# triangle_attention `_attn_bwd` — v3: stride-native loads (NO SHIP, reverted)

**GPU:** H100 (sm90).  **Shape:** d_pair=512, L=384, n_head=4 → HEAD_DIM=128, B=1, bf16.
**Base:** v2 (FA2 split, 8.36 ms/layer).

## Verdict

**NO SHIP — reverted to v2.** Making the attention kernels stride-native (consume the
module's strided `[B,H,L,L2,D]` transpose views for q/k/v + broadcast bias, no
`.contiguous()`) removes the copies but is **both incorrect (nan) and slower (9.59 vs
8.36 ms)**. The gappy strided loads cost more than the copies they eliminate — the
`.contiguous()` transpose is confirmed a *beneficial* tradeoff, not waste.

## Plan (this round)

Kill the ~2.2 ms/step copy family identified by shape:
- fwd `copy_` `[1,4,384,384,128]` 0.6 ms (q/k transpose) + `[1,384,384,4,128]` 0.2 ms (value)
- bwd `copy_` 0.6 ms (q/k grad transpose) + `repeat(bias)` `[1,4,384,384,384]` 0.47 ms +
  grad copy 0.33 ms
(the `add_`/`add` 0.66 ms are grad accumulation, not removable.)

Implementation: remove `.contiguous()` in module (q/k) and `Function.forward`; feed the
strided 5D q/k/v + strided bias to `_attn_fwd`/`_attn_bwd_dkdv`/`_attn_bwd_dq` via explicit
5D strides; keep the o-group (out/dq/dk/dv) contiguous; read bias broadcast over the row
(drop `repeat`). head_dim D stays stride-1 (coalesced).

## Result — negative on both axes

| | fwd cos | step | fwd `_attn_fwd` | bwd (dkdv+dq) |
|---|---|---|---|---|
| v2 (contiguous) | 0.99999 | **8.36 ms** | 0.53 ms | 1.92 ms |
| v3 (stride-native) | **nan** | **9.59 ms** | **1.31 ms** | **3.42 ms** |

- **Correctness:** cos = nan (same addressing bug class as a pre-v2 strided attempt).
- **Speed (decisive even ignoring the bug):** copies dropped (elementwise 24.6 % → 10.4 %,
  ~1.6 ms saved) but the strided kernels got **+2.3 ms slower** — `_attn_fwd` 0.53 → 1.31 ms
  (2.5×), bwd 1.92 → 3.42 ms (1.8×). Net **+1.2 ms**.

## Why (confirmed root cause)

The strided view's token(L2) stride is **H·D = 512** vs the contiguous **D = 128** (4×).
head_dim stays coalesced, but each token's D-vector is 4× farther apart → the per-token
loads scatter across 4× more cache lines. The v2 kernels stream q/k/v heavily, so this
gappy-load penalty (+2.3 ms) exceeds the one-time coalesced-copy cost it removes (~1.6 ms).
This is the same result seen pre-v2 and matches the general finding: for these kernels the
`.contiguous()` transpose amortized once beats repeated gappy strided loads. cuequiv also
copies non-contiguous input internally (2× on strided) for the same reason.

## Decision

Keep v2. The remaining copy family is **not** profitably removable by stride-native loads.
The only orthogonal, safe sub-win left is **bias broadcast alone** (drop `repeat(bias)`,
~0.47 ms, q/k/v stay contiguous) — small, deferred. The big "~2 ms copy" prize is a mirage
because eliminating it re-introduces more cost via gappy loads.
