# triangle_multiplication_tm1_cute - optimization round v10 (ln_in fusion attempt — REGRESSED)

- Date: 2026-07-04
- Goal (roadmap 1): fuse ln_in into the tm1 GEMM to remove the 185us ln_in kernel + x_normed intermediate.
- Baseline: v8 cute 1.560ms (cuequiv 1.345). Shipping unchanged (v8) — this round regressed, reverted.

## 1. Attempt: algebraic LN fusion (correct but slower)
LN over d fused algebraically so the MMA uses RAW x + folded weights W'=g*W, correcting the affine in
the GLU epilogue: proj[m,n] = rstd[m]*((x@Wp'.T)[m,n] - mu[m]*SWp[n]) + bWp[n] (same for gate),
SWp[n]=sum_k g*Wp, bWp[n]=sum_k b*Wp. Artifact: v10/sm100_ln_gate_gemm_attempt.py.
- Correctness: cos 0.999996 vs torch(layernorm+gate) — the algebra is correct.
- **Perf REGRESSED** (do_bench, GPU0, M=1048576, both sides, fold+stats precomputed once):
  - cute ln-gate kernel: **0.843 ms** vs gate_gemm 0.629 ms (+214us) — the per-element epilogue
    gather (sMu[m], sRstd[m], sSWp[n], sBWp[n] indexed per output element + FMA + exp) is expensive.
  - torch var_mean(x) for mu/rstd: **1.465 ms** (torch upcasts x to fp32 twice) — dwarfs ln_in's 185us.
- Net: worse than v8 on both counts. Reverted.

## 2. Why it regressed / the real blocker
- The algebraic approach trades the ln_in kernel for (a) a per-element epilogue correction (regresses
  the GEMM epilogue) and (b) a stats reduction. Both cost more than they save here.
- The *proper* ln fusion (normalize each A tile row IN smem before the MMA, no epilogue gather) is
  blocked by the **swizzled MMA smem layout**: make_smem_layout_a is atom-structured/swizzled, so a
  per-row (over d=128) reduction has no clean logical [m,k] access; options are a non-swizzled A smem
  (uncertain tcgen05 MMA validity) or a second simple smem buffer + smem->smem copy (extra smem ->
  1 CTA/SM). Not resolved.

## 3. Standing conclusion (updated)
- ln fusion (roadmap 1): algebraic form regresses; in-kernel form blocked by swizzled-smem reduction.
- both-sides fuse (roadmap 2): 4-acc form regressed in v9 (512 TMEM cols -> 1 CTA/SM); sequential
  2-acc form (read x once) is ~ -150us best-case -> ~1.40ms, still short of cuequiv and complex.
- The tm1 GEMM is stuck at **12% occupancy** (single-warpgroup structural wall, ncu v9). Neither
  tiling, smem reduction, nor these fusions break it. **The only path to beat cuequiv is roadmap 3:
  a persistent + warp-specialized GEMM** (dedicated load/MMA/epilogue warpgroups + tile scheduler,
  overlapping epilogue of tile i with MMA of tile i+1). That is a large, high-deadlock-risk port of
  the CUTLASS blackwell persistent dense-GEMM, adapted for the gated dual-output M-major case.

## 4. Best achieved / shipping
v8: cute 1.560ms (6.1x triton, 1.16x off cuequiv 1.345), correct cos 0.999977 (== triton). No regression shipped.
