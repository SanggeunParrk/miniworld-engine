# triangle_multiplication_tm1_cute - optimization round v12 (BIDIRECTIONAL cute via tm1 bdll_sm100)

- Date: 2026-07-04
- Goal: make the bidirectional cute path WORK and beat cuequiv/dtv1, by reusing the working
  single-direction bdll_sm100 kernel for both directions (drop the broken trimul_inproj/cute).

## 1. Problem
The bidirectional cute path routed through trimul_inproj/cute (BidirV6TriMul), whose front gated
GEMM asks quack 0.3.11 gemm_act for an M-major store over doubled 256 channels ->
`AssertionError: is_n_major_c()` (gemm_act.py:202) at all L. Same quack gated-M-major wall we
already bypassed for single-direction with our own sm100_gate_gemm (out_layout="bdll_sm100").

## 2. Fix (implementation change, same math, precision preserved)
Added a CUTE path to `BidirectionalTriangleMultiplication` (module bidirectional.py) that composes
the single-direction tm1 `bdll_sm100` gate-GEMM+einsum for BOTH directions, then the SHARED back:
- x = ln_pair(pair) [layer_norm_transpose nd->nd, or fused_ln_mask if mask].
- outgoing half (channels 0:h): left/right = tm1_cute_forward(x, W[:h].T ..., "bdll_sm100") -> [B,h,L,L];
  O = einsum("bdik,bdjk->bdij").
- incoming half (channels h:2h): left/right = tm1_cute_forward(x, W[h:].T ..., "bdll_sm100");
  I = einsum("bdki,bdkj->bdij")   (incoming = k<->contraction flip; handled by the einsum directly,
  no input transpose needed since we control the einsum).
- tri = cat([O, I], dim=1) [B, 2h, L, L]; ln_out over 2h (layer_norm_transpose dbn->bnd);
  back = sigmoid(x @ to_gate.T) * (ln_out @ to_out.T)   (gate K=d, out K=2h -> can't use the
  same-K fused tm2; done as two GEMMs + gate mul).
Note: this matches the SHARED-structure reference (one ln_out over 2h, one to_out 2h->d) exactly;
it is NOT two independent single-dir TMs summed (the 2h ln_out + full 2h->d to_out couple the
directions), so the naive TM_out(P)+TM_in(P^T) decomposition would NOT cos-match — verified.
