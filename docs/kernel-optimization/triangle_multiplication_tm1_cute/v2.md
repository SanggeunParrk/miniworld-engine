## 4. Bottleneck theory (targeted)
- tm1 gate pointwise was memory-bound and redundant: `torch.sigmoid(gate_buf)` allocated a temp then `mul_` — ~4 passes over 128M-element bf16 [B,D,L,L] buffers (sigmoid: read+write; mul: read+read+write).
- A single fused kernel needs 1 read proj + 1 read gate + 1 write = half the traffic.

## 5. Plan (one focused experiment)
- Hypothesis: fuse `proj * sigmoid(gate)` into ONE Triton elementwise kernel (in-place on proj), sigmoid+mul in fp32, single round to bf16.
- Expected metric movement: gate stage 468us -> ~234us; full L=1024 1.73 -> ~1.5 ms.
- Risks: none material; rollback = revert to torch sigmoid+mul_.
- Precision unchanged (fp32 intermediate is strictly >= previous bf16-temp precision).

## 6. Code changes
- `src/miniworld_engine/kernels/tm1/cute/launch.py`:

  - Replaced `left_bdll.mul_(torch.sigmoid(gate_buf))` and the right-side equivalent with `_fused_gate_mul(...)`.
