# triangle_multiplication_tm1_cute - optimization round v6

- Date: 2026-07-03
- Target: from-scratch SM100 tcgen05 GEMM -> dual-B gated GEMM (tm1 side op)
- Baseline: v5 (standalone SM100 GEMM correct)

## 1. Result
Single-kernel **gated dual GEMM**: `out = sigmoid(A @ Bg.T) * (A @ Bp.T)`, exactly the tm1
per-side op (proj = x@Wp, gate = x@Wg, out = sigmoid(gate)*proj). Two tcgen05 MMAs into two
TMEM accumulators + a fused GLU epilogue, one launch.

Validation vs torch fp32 (`python ~/psk/ncu/micro_gate.py 1024 128`):
- M=1024 N=128 K=128: cos 0.999999, maxabs 7.8e-3, meanabs 5.7e-4
Precision: bf16 in, fp32 accumulate + fp32 sigmoid/mul, bf16 out. Not reduced.

Kernel: `docs/kernel-optimization/triangle_multiplication_tm1_cute/v6/sm100_gate_gemm.py`
(live: `~/psk/ncu/micro_gate.py`).

## 2. Design
- Load A, Bp, Bg via one PipelineTmaUmma handshake (tx = A + 2*B bytes).
- Two TMEM accumulators: proj_acc at tmem_ptr, gate_acc at tmem_ptr + `find_tmem_tensor_col_offset(proj_acc)`;
  num_tmem_cols = 2 * get_num_tmem_alloc_cols.
- Two MMA sweeps (proj then gate), each with ACCUMULATE reset on the first k-block.
- One `acc_pipeline.producer_commit` after both; consumer_wait; GLU epilogue:
  per epi-subtile t2r proj + t2r gate -> `proj * (1/(1+exp(-gate)))` in fp32 (`cute.math.exp`)
  -> bf16 -> r2s -> per-subtile TMA store.
