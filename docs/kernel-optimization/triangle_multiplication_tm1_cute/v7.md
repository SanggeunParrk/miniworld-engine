# triangle_multiplication_tm1_cute - optimization round v7

- Date: 2026-07-03
- Target: SM100 gated GEMM with M-major [B,D,L,L] zero-copy output store
- Baseline: v6 (gated dual GEMM, row-major output)

## 1. Result
The SM100 gated GEMM now stores its output in M-major [B,D,L,L] layout directly (zero-copy),
exactly what tm1's einsum needs -- no permute. Achieved by replacing the r2s+TMA store with a
direct register->gmem store (make_copy_atom(CopyUniversalOp(), bf16) + cute.copy(simt_atom, rD,
tTR_gC)), partitioning the RAW gmem C via thr_mma.partition_C then the t2r tiled copy. This
handles arbitrary output strides (row-major AND M-major), which the TMA store could not (TMA
cannot transpose between the N-contiguous smem tile and M-contiguous gmem -> gave NaN).

Validation vs torch fp32 (python ~/psk/ncu/micro_gate.py 1024 128 [mm]):
- row-major : cos 0.999999, maxabs 7.8e-3
- M-major   : cos 0.999999, maxabs 7.8e-3  (out stored as [N=D, M=L*L] = [D, L*L] = [B,D,L,L])
Precision preserved (fp32 acc + fp32 sigmoid, bf16 out).

Kernel: docs/.../v7/sm100_gate_gemm_mmajor.py (live: ~/psk/ncu/micro_gate.py;
gate_gemm(A, Bp, Bg, mmajor=True) returns [N, M] = [D, L*L]).

## 2. Integration mapping (v8)
Per tm1 side: A = x_normed.reshape(L*L, D); Bp = to_left.weight (D,D); Bg = to_left_gate.weight.
out = sigmoid(A@Bg.T) * (A@Bp.T) matches proj=x@W.T, gate=x@Wg.T. mmajor=True -> [D, L*L] ->
view [1, D, L, L] = left_bdll (and to_right.* -> right_bdll). Replaces the 4 quack GEMMs + Triton gate.
