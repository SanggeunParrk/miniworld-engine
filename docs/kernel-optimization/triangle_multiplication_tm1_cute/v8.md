# triangle_multiplication_tm1_cute - optimization round v8

- Date: 2026-07-03
- Target: wire the from-scratch SM100 tcgen05 gated GEMM into tm1 (drop quack for the tm1 side)
- Baseline: v2 (shipping best, quack + Triton gate); cuequiv reference

## 1. Result: from-scratch SM100 tcgen05 kernel is CORRECT and INTEGRATED
`_forward_cute` tm1 now uses `out_layout="bdll_sm100"`: two launches of the from-scratch SM100
gated GEMM (`sm100_gate_gemm.gate_gemm(x_flat, W, Wg, mmajor=True)`) produce left/right [B,D,L,L]
directly. This replaces, on the tm1 side, the 4 non-gated quack GEMMs + the Triton gate kernel
(v2) AND the old permute -- all folded into 2 tcgen05 launches (proj+gate MMAs + fused
sigmoid-gate + M-major store). quack is no longer used for the tm1 side GEMMs.

## 2. Correctness (gate)
`python ~/psk/ncu/compare_cute.py 768 1024` vs fp32 reference:
- L=768 : cute cos 0.999977 (== triton exactly: maxabs 1.556e-2, meanabs 1.520e-3, relmean 6.686e-3)
- L=1024: cute cos 0.999977 (== triton exactly)
The SM100 path is now bit-for-printed-digits identical to triton and MORE accurate than v2
(0.999974), because it accumulates in fp32 like triton. Precision preserved (bf16 in/out).

## 3. Performance (do_bench, bf16, B=1, d=128)
| L | triton | v2 cute (quack+triton gate) | v8 cute (SM100) | cuequivariance |
|---|--------|------------------------------|-----------------|----------------|
| 1024 | 9.55 ms | 1.506 ms | **1.560 ms** | 1.345 ms |
| 768  | 3.05 ms | 0.856 ms | **0.891 ms** | 0.761 ms |
- vs triton: ~6.1x faster (L=1024). vs cuequiv: 1.16x slower. vs v2: ~3.5% slower.
- The from-scratch GEMM is a naive single-CTA-per-M-tile, single-K-stage, single-warpgroup kernel
  (no K-pipelining, N=128 is a tiny MMA N, ~55 tail waves at L=1024). It is competitive but not
  yet beating the highly tuned quack GEMM. It fuses the gate + kills the permute, offsetting most
  of the GEMM inefficiency.

## 4. Code changes
- NEW `src/miniworld_engine/kernels/tm1/cute/sm100_gate_gemm.py`: `GateGemm` (tcgen05) + `gate_gemm`.
- `launch.py`: added `out_layout="bdll_sm100"` (two gate_gemm launches -> [B,D,L,L]); weights
  mapped Bp = (W.T).mT = W (contiguous), inputs detached for from_dlpack.
- `module.py`: `_forward_cute` uses `out_layout="bdll_sm100"`.

## 5. Next ideas (ranked) -> v9 to beat v2/cuequiv
1. Fuse BOTH sides into ONE kernel (read x once, 4 accumulators WLp/WLg/WRp/WRg -> 2 GLU outputs)
   -- halves the x global reads.
2. Combine proj+gate into one MMA with N=256 (concat B) instead of two MMAs.
3. K-pipelining (multi-stage AB) + larger per-CTA M work to cut the ~55 tail waves / raise occupancy.
4. persistent-tile scheduler.
