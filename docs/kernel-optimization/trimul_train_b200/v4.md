# trimul_train_b200 v4 — dgrad_lnbwd sm100 port: CORRECT standalone (3 blockers solved)

## Goal
Port the H100 fused dgrad kernel `layernorm_linear/cute/dgrad_lnbwd.py` (dY@W GEMM + LN-normalize
backward folded into the epilogue -> dx) to the sm100 tcgen05 Blackwell collective. This is the
biggest lever to close the B200 trimul-training gap to cuequiv (removes the memory-bound LN-bwd
passes + the dx_normed HBM round-trip).

## What was done
New file `src/miniworld_kernels/kernels/layernorm_linear/cute/dgrad_lnbwd_sm100.py`:
`class _DgradLNBwdSm100(GemmDefaultEpiMixin, GemmSm100)`. Same math/precision as H100
(bf16 in / fp32 acc / fp32 LN stats+reductions / bf16 out):
    A=dY(M,N)  B=W^T(K,N)  C=xhat(M,K)  D=dx(M,K)
    dxhat=acc*g ; c2=mean_k(dxhat) ; c1=mean_k(dxhat*xhat) ; dx=rstd*(dxhat - c2 - xhat*c1)

## The 3 blockers (from v3) and how each was solved
1. `_compute_stages` arity (sm90 10-arg vs sm100 17-arg call -> TypeError):
   -> DO NOT override it. The sm90 override was only a smem-reclaim perf tweak. Inherit
      `GemmSm100._compute_stages` (17-arg, returns 4 values incl. num_acc_stage). Blocker
      dissolves.
2. Full-N single epilogue subtile (sm90 hook `_sm90_compute_tile_shape_or_override` is never
   called by tcgen05; natural sm100 `compute_epilogue_tile_shape` gives epi_N=32 for bf16 ->
   4 subtiles -> partial c1/c2 -> cos~0.5):
   -> Override `_setup_attributes`; scope-monkeypatch `blackwell_helpers.compute_epilogue_tile_shape`
      to return a single full-CTA-N tiler ((tile_m):(1), (cta_n):(1)) so the whole K-row lands in
      one subtile. Restored in a finally.
3. tcgen05 lane reduction (H100 hardcodes `warp_reduction(threads_in_group=4)` for the WGMMA
   t2r layout; wrong for tcgen05):
   -> Derive `lanes_in_N`/`warps_in_N` generically from `tiled_copy_t2r` in `epi_setup_postact`
      (via quack `_get_lane_warp_layouts(..., reference_src=False)`, exactly as `ColVecReduce.end`).
      Reduce in-visit with the derived lane count (skip when lanes_in_N==1 -> whole row already in
      one thread's registers). Assert warps_in_N==1 (holds for this config). `colvec_reduce_accumulate`
      already has the arch>=100 packed-f32x2 path, reused unchanged.

## Validation (standalone dx vs fp32 reference dx = LNbwd(dY@W), non-degenerate random W + randn x)

  M=4096  N=128 K=128 : cos=0.999999  relmean=1.41e-3  maxabs=2.99e-2  (refscale 1.03)
  M=16384 N=128 K=128 : cos=0.999999  relmean=1.41e-3  maxabs=3.12e-2  (refscale 0.94)
  M=4096  N=256 K=128 : cos=0.999999  relmean=1.41e-3  maxabs=3.12e-2  (refscale 1.24)
relmean ~1.4e-3 is the bf16 grad floor. cos matches the FULL LN-bwd reference (with the c2/xhat*c1
subtraction), which proves the tcgen05 row reduction is correct, not just the raw dY@W.
