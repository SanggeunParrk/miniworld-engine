# A100 TriMul TriangleAttention APB 추론 SOL

2026-10-05. `a100` 브랜치에서 다음 추론 최적화의 기준점으로 우리 MiniWorld 구현 120개 shape를 측정했다. [합의한 shape protocol](../gpus/module-comparison-protocol.md)을 따른다. 이번 결과는 구현 변경 전 측정이며 Anthropic 대비 배속이나 학습 결과가 아니다.

B=1, 한 블록, BF16 연산, TF32 허용, mask 0%, dropout 0%, compiled 실행 + manual CUDA graph. TriMul은 outgoing과 bidirectional이며 hidden 폭은 각각 D와 2D다. TriangleAttention은 starting, d_hidden=d_pair, heads=D/32다. APB pair 폭은 128이고 single 폭과 head 구성은 아래 표에 표시했다. 모든 shape에서 실제 compiled 실행과 CUDA graph 재실행을 확인했다.

시간은 공통 benchmark의 warmup 후 median이며 NCU 없이 측정했다. TriMul은 공통 모듈 runner·측정·정확도 함수를 호출하는 scratch wrapper로 실행했고 MiniWorld implementation environment guard를 적용했다. TriAttn/APB는 공통 CLI를 사용했다. TriMul 54개는 fullgraph, 양방향 D512 6개는 기존 protocol의 partial_allowed다. 후자는 strict fullgraph에서 C.cat context의 dim 추적이 실패했고, partial compile에서는 실제 13개 graph가 실행됐다. TriAttn/APB의 성능 측정 scope는 partial_allowed다. 별도 fullgraph profiler의 성공을 성능 측정 자체의 fullgraph 증거로 바꾸어 표기하지 않았다.

## SOL 정의

**SOL(%) = 100 × Σ커널 max(필수 tensor bytes / 1.60 TB/s, matmul FLOPs / 240 TFLOP/s) ÷ 측정된 모듈 시간**이다. 기준 피크는 기존 A100 문서의 sustained calibration을 유지한 값이며 이번 GPU에서 새로 캘리브레이션한 값이나 제조사 이론 peak가 아니다. 현재 실행되는 weight pack, materialized tensor, layout copy 등 직렬 단계를 포함해 재계산했다. 각 항목의 bytes/FLOPs는 JSON에 있다.

이는 실행 경로에 따른 **모델 기반 SOL**이다. 캐시/L2 재사용, SFU·reduction 처리율, launch·동기화 비용을 완전히 모델링하지 않으며 warm-cache 실행의 엄밀한 하한은 아니다. 구현이 더 많은 중간 tensor를 만들면 floor도 올라갈 수 있어 SOL만으로 서로 다른 구현의 속도를 비교하면 안 된다. 아래 SOL 표와 실제 시간을 함께 읽는다.

NCU는 별도 replay에서 120개 shape의 커널별 SM·DRAM·tensor 처리율을 수집했다. CSV의 NCU 수치는 커널 duration 가중 평균이며 커널 사이 간격을 제외한다. NCU sustained-peak 비율은 위 SOL과 다른 지표다. TriMul/TriAttn은 clock-control/cache-control none, APB는 NCU 기본 clock/cache 설정을 사용했으므로 모듈 간 NCU 수치의 직접 비교에도 이 차이가 있다. NCU replay 시간은 정상 성능 시간으로 사용하지 않았다.

## 실행 경로와 해석

- APB 24×16은 기존 Triton attention fallback이며 나머지 네 layout은 A100 CUDA+cuBLAS 경로다. L768의 24×16은 약 0.425 ms, SOL 85.3%로, 다른 single384 layout의 약 0.174–0.178 ms보다 느리다. materialized stage가 늘어난 높은 floor가 높은 SOL을 만드는 예다.
- TriMul D512는 전용 fused/wide 경로와 다른 일반 CUDA+cuBLAS composition이다. 일부 layout copy는 Inductor가 생성한 Triton 커널이다. D64/256/384는 sm80_wide, D128은 fused sm80를 사용한다.
- TriangleAttention은 width에 따라 fused 또는 CUDA rows+cuBLAS 경로를 사용한다. 일부 기존 harness execution_path 문자열에 triton이 남아 있어 실제 profiler 커널 목록으로 확인했다. D128/L768의 mask/bias compaction도 floor에 포함했다.
