# A6000 opcheck input coverage audit

The earlier full GPU suite passed 226 tests, but its opcheck fixture exercised 26 custom operations and reported 66 imported operations it never called. This was a fixture scope limitation, not a list of operations unsupported by A6000.

The fixture previously ran only training with several obsolete width combinations. It omitted inference, ordinary atom/token DiT at production widths, and all SWA/RMSNorm/RoPE cases. The expanded fixture uses token widths 768/384, atom widths 128/128, inference A5 and training A48. Sequence lengths are reduced for metadata checks; atom256*A48 retains the large-row conditioned-transition branch. Existing pair/MSA cases are retained in both modes.

Validation job 1678469 completed successfully: 5 tests passed in 43.92 seconds, checking 42 operations. Shipped and private tile caches were unchanged. These module cases use BF16; the standalone numerical suite separately exercises its declared precision cases.

Schema, fake tensor metadata, static AOT and dynamic AOT forward checks remain enabled. FlashWindow explicitly registers autograd, so its registration and real backward are tested positively; lower-level launch wrappers retain their enclosing autograd.Function contract.

Backend evidence includes the wrapper dispatch when it spans multiple implementations; a `/cute/` directory alone does not establish CuTe, because several of those wrappers launch registered Triton glue kernels. A numerical checker verifies arithmetic, not custom-op schema, aliasing, fake metadata or AOT tracing. The mapping below is static: listed checkers cover reachable registered launches, not necessarily every branch/precision/layout of the wrapper. A blank static mapping is not a claim that no historical validation exists.

Expanded capture: 42 operations; 16 of the original 66 are now checked. Imported-operation denominators depend on which modules a test process loads, so the new remainder must not be subtracted directly from 66.

The 23 operations imported but not reached by the expanded cases are alternative normalization/linear paths (including RMSNorm modulation), memory-efficient or bias-only attention variants, FP32 token SwiGLU backward, legacy gate/backward wrappers, and alternative transition implementations. For example, `conditioned_transition_swiglu_bwd_packed` is the FP32 token fallback (training.py:661-668); BF16 uses the fused `conditioned_transition_dh_swiglu_bwd`. `trimul_gate_elem_fwd_infer` remains in CuTe/legacy split paths, while the current A6000 inference path uses the checked `trimul_back_fused`.

The first expanded attempt passed schema/fake/AOT checks but exposed an old test-harness assumption: it detached only the first input before checking backward. FlashWindow has a real autograd formula, so remaining references could point to a freed graph. The final test detaches every input, then makes one input differentiable. No runtime source was changed.
