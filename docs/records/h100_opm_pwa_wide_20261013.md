# H100 OuterProductMean / MSAPairWeightedAveraging beyond MiniWorld's width: 2026-10-13

Record of one round on H100 (sm_90a, cluster `cssb`, partition `h100`, one GPU at a time), torch 2.13 + cu129, bf16, batch 1. Branch
`h100/opm-pwa-wide2` (from `h100/cuda-sweep` d3a9e21d). Numbers come from probes outside the checkout
(`~/miniworld-engine-scratch/opmpwa2/`): median of 7 x 50 CUDA-graph replays of one captured call, training = forward +
`autograd.grad` to every input and parameter, dropout 0, masks ~10 % false, S = 1024 unless stated. They are not the maintainer's
performance check and have not been re-run with `benchmarks/runners/bench.py`.

## What changed

| Change | Effect |
|---|---|
| OPM at d_msa 128 with d_pair 256 / 384 (Protenix-v2, ESMFold2, OpenDDE) and the ESMFold2 normalisation order (`normalize_before_proj=False`): `opm_epilogue.cu` is built per (OPM_CM, OPM_CZ); the epilogue and dWo cut c_z into 128-wide CTA slices, the prologue backward widens to d_msa 128. Any length / MSA depth (the wrapper pads with masked rows and cuts back). | new shapes served, training and inference |
| New CUDA prologue `opm_prologue_tma_wide<CM>` (persistent TMA + wgmma, LN + both projections + mask -> A2 / BT, statistics, bit mask, exact count) for d_msa 64 and 128. | wide OPM has no Triton stage |
| The same prologue serves the MiniWorld-width inference cells that kept the Triton prologue (S 1024 / 2048 / 4096 x L 512-768, S 4096 x L 256 / 384). | 1.6-5.5 % faster at all 11 cells (below); the table is all CUDA |
| PWA wide path `integrations/pwa_wide.py` (`csrc/pair_wide.cu`, `csrc/pwa_wide.cu`): d_msa 64 / 128, d_pair 128 / 256 / 384, 8 heads x 8 / 16, any depth, N <= 1024. B200 structure written for wgmma: pair_fwd -> ln_vg -> cuBLAS `o = w v` -> gate_out; backward gate_bwd -> cuBLAS dv / dw / dW -> dm_bwd -> pair_bwd. The module has no pair-LayerNorm beta: the kernels are given zeros. | new shapes served; h8 has no Triton path (it refuses d_hidden < 16) |
| `dm_bwd`: x and the residual gradient tiles are prefetched into shared by cp.async instead of read from HBM in the epilogue. | 1.24 -> 0.69 ms (128/256/h16 L768) |
| `pair_bwd`: one pass instead of two: the row sums of dzn gamma and dzn gamma xhat come from a [16 x 8] mma of the x tile with P = gamma Wb (fp32 split into hi + lo bf16, error ~2^-17) and the constants c_h, so dzn is formed once; xhat^T for the M^T mma comes from registers (`movmatrix`), one fewer tile per warp; per-width warp / CTA table measured. | 0.95 -> 0.64 ms (384), 0.40 -> 0.34 ms (256) |
| `opm_dgrad_kernel`: 16 (c_z 256) / 8 (c_z 384) dz rows in flight per thread while staging the tile. | 1.17 -> 0.95 ms (128/256 L768) |

## Accuracy

Reference: the module's own PyTorch statements in fp32 (random LayerNorm / projection weights, masked, ragged L and S).
OPM: output and every gradient cos >= 0.9999, bitwise deterministic across calls, `dz` of the residual exact, inference equals the
training forward bitwise. PWA: output and dm cos >= 0.9999, dz / parameter gradients >= 0.9998, bitwise deterministic, row dropout
fused (dropped (token, channel) leaves the residual untouched). Tests: `tests/gpu/sm90/test_opm_wide_sm90a_gpu.py` (13),
`tests/gpu/sm90/test_pwa_wide_sm90a_gpu.py` (15); with `tests/gpu/any/test_opm_train_gpu.py` and `test_pwa_train_gpu.py`:
48 passed, 4 skipped. `test_opm_train_gpu.py::test_refusals` was updated: the ESMFold2 order and a ragged depth are now served.

## Findings that did not become changes

- `opm_dgrad` K = 256 with the double-buffered weight chunk: 0.271 -> 0.299 ms (L384); reverted.
- `opm_dgrad` with 64 pairs per CTA (two or three CTAs per SM): not faster at either width (1.13 / 1.76 ms against 1.17 / 1.54) and
  `test_opm_wide` failed at 128/256; reverted, the cause was not looked into.
- `pair_bwd` with more warps per CTA (7 / 10): slower (1.07 / 0.50 ms); the width table in `pwa_wide.PAIR_CFG` is the measured best.
- `gate_bwd` head-major flush with rows fastest (removes 2-way shared bank conflicts): time unchanged (the kernel is memory bound);
  kept, it is correct and conflict free.
- The CUDA-graph step is about 10 % longer than the sum of its kernels at the large OPM cells, as in the earlier record; the cause is
  not determined (clock behaviour under a sustained GEMM load is the suspect).

## Left

PWA training sits at 45-60 % of its fusion floor: the head-major intermediates (v, o, do, dgp, dv) round-trip HBM in six kernels plus
three cuBLAS calls. Candidates, each 2-5 % of a step: the `dv` copy into the natural-layout `dgv` (200 MB at L768), `gate_bwd` /
`dm_bwd` closer to their traffic floor. OPM: `opm_dgrad` at c_z 384 needs a warp-specialised,
TMA-pipelined rewrite (about 0.5 ms of 10 ms); small L is launch-count bound (0.1 ms of a 0.4 ms step at L128).
