# H100 OuterProductMean: speed of light and the training prologue, 2026-10-07

Dated record; not edited after the fact. Page that tracks the current state: [../gpus/h100/opm/opm.md](../gpus/h100/opm/opm.md).

Branch `h100/cuda-sweep`, single NVIDIA H100 80GB HBM3 (Slurm `h100` / `normal_h100`, one GPU per job), torch 2.13.0+cu129.
bf16, batch 1, d_msa 64 / d_hidden 32 / d_pair 128, masks ~10 % false, fp32 LayerNorm parameters. Every latency is the median
of 7 x 50 replays of one CUDA-graph-captured call (`timeit` of the scratch `msa_h100/bench.py`); training = forward + backward to
every input and parameter. Scripts and raw JSON/logs stay outside the checkout (`~/miniworld-engine-scratch/opm_sol_h100/`).
Run-to-run spread between jobs is 2-3 %; compare ms within one job, not SoL percentages across jobs (the ceilings are re-measured
in every job).

## 1. The earlier H100 SoL was computed with B200 ceilings

`msa_h100/bench.py` hard-codes `HBM, TC = 6.9e12, 1.73e15` (measured on B200). The "27-36 % of SoL" in the 2026-09-30 survey used
them and is void for H100. Ceilings measured on this card, same CUDA-graph timing:

| ceiling | value |
|---|---|
| HBM, `torch.mul` read + write over 1 GiB bf16 | 3.04 TB/s (a `copy_` reaches 2.45 TB/s) |
| cuBLAS bf16 8192^3 | 703 TFLOP/s |
| cuBLAS on the module's own grouped GEMM `A2[(i,c),s] @ BT[(j,e),s]^T` | measured per (L, S) and used as "module-TC" |

Floor = sum over the kernels of this fusion algorithm (prologue, O GEMM, epilogue; training adds dgrad, dA, dB, dWo, prologue
backward) of `max(bytes / HBM, FLOPs / TC)`, with the byte and FLOP counts of `kernels("opm", ...)` in the scratch `bench.py`.
Two floors are reported: **module-TC** (cuBLAS rate at the module's own GEMM shape) and **peak-TC** (the 8192^3 rate). The
floor is not a strict lower bound: it takes cuBLAS's measured rate as the tensor ceiling, so a step can pass 100 % of it
(L768 S1024 training measured 101.3 % of module-TC and 95.4 % of peak-TC).

## 4. The persistent TMA prologue in training

`MINIWORLD_OPM_H100_TMA_PROLOGUE=1` forced on every training cell (job 27358), ms: (128, 1024) 0.315, (256, 1024) 0.944,
(384, 1024) 1.981, (512, 1024) 3.439, (640, 1024) 5.375, (768, 1024) 7.288, (384, 2048) 3.503, (768, 2048) 12.891,
(384, 4096) 6.427, (768, 4096) 23.873. It matches or beats the legacy composition at every cell (0.5-12 %).

Change made: `_h100_path(..., training=True)` returns `"tma"` for `S in (1024, 2048, 4096)`, `"native"` otherwise (it was `"tma"` only
for (1024, 384) and (1024, 768)). A first version returning `"tma"` for every S broke
`test_default_auto_path_compiles_forward_and_backward`: that test's shape is S = 256, L = 384, where inference takes the native path
and training took TMA, and the test requires the training forward and the `no_grad` forward to be bitwise equal (1 % of the
outputs differed by one bf16 step). Training and inference are still not bitwise equal at the cells whose inference path is the
legacy composition (for example (1024, 512), and (1024, 768) before this change).

## 5. Mask count from the bit mask

The TMA prologue already writes the bit mask. The default count was the fp32 cuBLAS product (mask cast, sgemm, splitK reduce,
clamp: four launches, ~0.024 ms at (384, 1024)). New kernel `opm_count_tiled` (16 x 16 pairs per block, both rows' bit words in
shared memory with row stride W + 1, AND + popcount; exact) replaces them with one launch; default of
`MINIWORLD_OPM_H100_CUBLAS_COUNT` is now 0 (1 restores the cuBLAS count).

Job 27377 (all 10 cells, default dispatch, ours only), ms, inference / training:
(128, 1024) 0.096 / 0.309, (256, 1024) 0.313 / 0.948, (384, 1024) 0.645 / 1.945, (512, 1024) 1.173 / 3.463,
(640, 1024) 1.886 / 5.272, (768, 1024) 2.562 / 7.155, (384, 2048) 1.135 / 3.372, (768, 2048) 4.326 / 12.823,
(384, 4096) 2.204 / 6.481, (768, 4096) 7.990 / 24.008. Training SoL (module-TC) 79.9 % at (128, 1024) to 101.6 % at (768, 1024);
inference 86.8-99.7 %. Against the previous job the gain is 1-5 % on the TMA cells and inside the 2-3 % spread elsewhere.

Profile at L128-384, S1024 (job 27372): the cuBLAS GEMMs run at or above the floor's 700 TFLOP/s (L384 O GEMM 0.410 ms against a
0.442 ms floor); the hand-written epilogue, dgrad, dwo, prologue and prologue-backward kernels sit 10-40 % over their floors (L384
training: 0.57 ms against 0.45 ms of floor); at L128 the small kernels (weight pack, count pieces, memset) were 17 % of the
inference step before the count change. At L384 S1024 training the CUDA-graph time (~1.95-2.03 ms) exceeds the eager kernel sum
(1.81 ms); the reason was not determined.
