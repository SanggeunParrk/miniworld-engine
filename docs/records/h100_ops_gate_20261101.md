## Finding: the previous Triton triangle-attention core is wrong for QK-normed q / k with a strided v

Probe (job 41353, bf16, L64, 4 x 32): `triton_triangle_attention_pair_bias(q, k, v, bias)` with contiguous q, k (what the QK norm returns) and v a strided
`rearrange` view returns an output with relative error 1.41 against fp32 (uncorrelated); the same call with v contiguous: 2.1e-3; all-strided (no QK norm): fine. So
`ops.triangle_attention(..., norm_*_weight=...)` on the portable path (any card with a record, and H100 before this change under the A/B switch) returned wrong values; the
new path agrees with fp32 to 4.4e-3. `modules.TriangleAttention` with `use_qk_norm` on a portable card has the same input layout. Not fixed here (a Triton kernel change moves its caches).
`test_ops_no_triton_gpu.py` reports it and does not compare against the previous output for that case (fp32 yardstick instead).
