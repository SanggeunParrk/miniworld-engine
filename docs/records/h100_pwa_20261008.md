# H100 MSAPairWeightedAveraging: kernel work, 2026-10-08

Record of one optimisation round on `MSAPairWeightedAveraging` (MSA 64 / pair 128, 8 heads x 32, bf16, batch 1) on H100 (sm_90a, cluster
`cssb`, partition `h100`). Branch `h100/cuda-sweep`, torch 2.13 + cu129. Numbers are from local probes outside the checkout
(`~/miniworld-engine-scratch/pwa_sol/`): median CUDA-graph replay of one captured call, training = forward + `autograd.grad` to every input
and parameter (dropout 0). They are not the maintainer's performance check and have not been re-run with `benchmarks/runners/bench.py`.

## What changed

| Change | Effect |
|---|---|
| The module no longer has `ln_pair.bias` (`LayerNorm(d_pair, bias=False)`). Its beta adds `beta . Wb_h` to every key's logit of head h, a shift shared by all keys, which the softmax over keys cannot see: the output never depended on it and its exact gradient is 0. The H100 backward recomputed that gradient in fp32 (the "beta shadow": 5.6 ms at L384, 14 ms at L768 per step). The kernels still take a beta argument and are given zeros. A checkpoint's `ln_pair.bias` is dropped when loading (`_load_from_state_dict`). | Training 4.5-5.6x faster; outputs and every other gradient bit-identical to the old module with beta = 0 (L384 / L768, S 1024). |
| `pwa_pair_reduce`: 4 blocks walking all N rows per thread (0.16 ms at N = 768) became a fixed-order two-stage reduce. | -0.16 ms at L768, deterministic. |
| `dv = w^T . d_o` runs on cuBLAS instead of `pwa_plain2` (0.81 ms, 2x the cuBLAS time for the same FLOPs). `dgv_bwd` reads the head-major result as two [64 i][32 c] tiles per k-block (2-D TMA, 64-byte swizzle); dy uses K = 32 wgmma, and dWv is accumulated transposed (y tile and dv tile both MN-major) so the register budget is unchanged. | L768 training -7 %, L384 -4 %; forward and every gradient bit-identical to the `pwa_plain2` path. |
| N >= 512: the contraction `o = w . v` runs on cuBLAS (head-major o) and the gate / out pass is a new kernel, `pwa_gateout.cu` (the epilogue of `pwa_fwd3`, o read as a TMA tile instead of a wgmma accumulator). In training `pwa_glue3` reads the head-major o (`o_head_major`). | Inference L768 -18 %, L640 -14 %, L512 -3 %; training L768 -7 %. The fused kernel stays below 512 (L384: cuBLAS contraction 0.163 ms plus a gate / out pass of at least 0.116 ms of traffic, against the fused kernel's 0.257 ms; the split there was estimated, not run). |
| Removed the environment knobs of the beta shadow (`BETA_SHADOW`, `SHADOW_*`, `EXACT_DWB`, `OWNED_BLAS`), `CLUSTER` (cluster 2 measured no faster) and `PWA_PYTORCH_NULL_BETA`, and `_h100_beta_shadow`. Kept: `MINIWORLD_PWA_TRAIN`, `MINIWORLD_PWA_INFER`, `MINIWORLD_PWA_H100_CUDA_AUX` (kill switches the tests build their baselines with). | |

## Accuracy

Relative error against an fp32 copy of the module (L768, S 1024, random weights): output 2.93e-3 (fused kernel) vs 3.18e-3 (split path), update
of the inference output 5.39e-3 vs 5.65e-3; every training gradient 1.9e-3 to 5.8e-3 and identical in the two paths. The split path rounds o to
bf16 before the gate (as the module's bf16 statements and the sm_100a path do), so its forward is not bit-identical to the fused kernel's;
`test_native_inference_default_live_master_graph` therefore compares the AUX=1 and AUX=0 inference at N >= 512 to 1e-2 instead of bitwise.

Tests (`tests/integrations/test_pwa_train_gpu.py`, `tests/numerics/test_msa_triton_gpu.py`): 30 passed, 2 failed, 4 skipped. The two failures
(`test_fused_training_path_matches_the_engines_own[full|ragged]`) fail on the tree before this round as well, by a hair over the 5e-3 limit
(0.0052 / 0.0053 before, 0.0052 / 0.0050 now); the limit was not changed.

## Findings that did not become changes

- Cluster multicast of W (`cs = 2`) in the fused forward and its `nst` / `blocks_per_sm` knobs: no gain; the default is the best. Its n = 64 wgmma
  tiles cap it near half the tensor-core floor, which is why the contraction moved to cuBLAS.
- A 4-D TMA box (c, h, i, s) over the head-major dv faulted (illegal memory access), also with increasing strides; the per-head 2-D tiles above
  are what works.
- Training of L512 / L640 (outside the required shapes, legacy path) fails with `invalid argument` when it runs in a process after a qualified
  shape (L384 / L768); L256 / S256 did the same with the error raised in `pwa_glue3`. The tree before this round does the same; not fixed.

## Left

(needs an fp32 dyg, about 0.15 ms net), the gate / out pass (0.30 ms vs 0.23 ms), dropping the inference `ln_vg` y write (about 0.07 ms). The
