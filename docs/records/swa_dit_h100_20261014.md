# SWA atom DiT on H100: weight-gradient and modulation kernels, distance to the floor (2026-10-14)

Dated record; not edited after the fact. Page with the current state: [../gpus/h100/swa_atom_dit/swa_atom_dit.md](../gpus/h100/swa_atom_dit/swa_atom_dit.md).

## Setup

- One H100 80GB HBM3 (cluster node01, 132 SMs), one GPU job at a time; torch 2.13 + cu129, nvcc from the repo's pixi env;
  branch `swa-dit-cuda` (merged main ce7fd93b) plus the uncommitted all-CUDA H100 work and this record's changes.
- Harness (scratch, outside the checkout): three blocks of `swa_dit_hoist_modulation` + `swa_dit_block`, forward + backward through
  `h.backward(dy)`, B = 1, d_atom 128; step captured in a CUDA graph and replayed (min of 7 x 20 replays). bf16: activations and
  weights bf16, matmul precision "highest"; fp32: activations and weights fp32, precision "medium" (TF32 allowed). Ragged `seqused`
  (S - 300 - 7 i). Triton row: `engine_backend="triton"`; no H100 autotune cache.

## What changed, in order, with the A = 1, S = 4096 bf16 step (3 blocks, ms)

| change | ms |
|---|---|
| starting point (all-CUDA block, torch modulation GEMMs in fp32 SIMT, cuBLAS weight gradients) | 0.656 |
| `swa_mod.cu` v1 (fused modulation fwd + bwd) | 0.509 |
| `swa_wgrad.cu` (one-launch weight gradients) | 0.468 |
| modulation backward restructured (dmod through smem planes, cp.async ring, saved silu) | 0.443 |
| dmod zero-fill skipped at A in 1, 2, 4, 8, 16 | 0.418 |
| modulation backward with three exact bf16 planes of dmod (was two) | 0.444 |

The last row is a deliberate +26 us: two planes (2^-17) were already below the bf16 rounding of the results, but the plane rounding
boundaries move with the run-to-run order of the atomic dmod accumulation; three planes make dc / dWmod the fp32 GEMMs' (no new source
of difference).
