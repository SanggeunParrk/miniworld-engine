# TriangleAttention: current H100 and B200 implementations

Audit date: 2026-10-05. Source: `h100/master-weights`, `4ee68216232a2085f8fce7737948afb2d338d8d8`. This is a source/dispatch comparison, not a new cross-GPU speed measurement. Production code was not changed.

## Required shapes and scope

The accepted comparison matrix has 194 inference configurations; every MiniWorld configuration ran successfully and passed the existing harness checks. Token DiT always buckets: historical L200/450/700 diagnostics are excluded. Shape support does not mean dedicated CUDA coverage. The user requires eventual Triton removal from every required execution path, but defers broader CUDA implementation while TriangleAttention is examined first.

Here C denotes pair-channel width, H the head count, and Dhead the per-head width. The agreed TriangleAttention cases use C=64/128/256/384/512 with Dhead=32.

| Aspect | Current H100 | Current B200 native path |
|---|---|---|
| Native forward coverage | Core gate: B1, H4, Dhead32/C128, L384/768/1024, BF16, qualified artifact and layout. Other agreed inference shapes use the Triton core. | Self-attention, no QK normalization, BF16 activations; C64..512 in multiples of64, Dhead16/32, H<=16, L divisible by128, arbitrary B. Covers the agreed widths and bucket lengths. |
| Inference frontend | LN produces normalized pair in global memory; separate Q/K/V/bias/gate projections and bias/mask layout work. | CUDA frontend combines LN, five projections, head-major bias layout and mask. Normalized pair remains in shared memory; Q/K/V/gate/bias are still global intermediates. |
| Attention core | Hopper TMA + WGMMA, 64-query/64-key tiles, register accumulators. | Blackwell TMA + tcgen05 + TMEM, 128 tiles; schedules 2 query-row tasks for L<=384 and4 otherwise to reuse K/V. |
| Output | Gate/output fusion exists in Triton for selected shapes; other widths use gate plus GEMM. Dropout scaling and residual addition remain separate module operations. | CUDA tail combines sigmoid gate, output projection, dropout scaling and residual. Dropout random sampling is still outside the tail. |
| Existing training fusion | B1/C128/H4/L384/768/1024 can fuse Q/G projection into attention; K/V still use cuBLAS, LN and bias projection remain separate. This route requires gradients enabled and is absent from the inference comparison. | Whole-module front/core/tail autograd path, with native gate/delta, attention, projection/LN/residual backward across the admitted wide shapes. |

## Implications for H100 optimization

The transferable part is the fusion algorithm and tensor lifetime design: frontend LN/projection/layout, tail gate/projection/dropout/residual, and grouped projection gradients. B200's tcgen05/TMEM instructions and clustered compute implementation cannot be copied into H100; the Hopper implementation must use its own TMA/WGMMA scheduling.

User direction: follow the B200 implementation wherever practical. The default H100 design is therefore the same front/core/tail fusion boundaries and grouped backward layout, reimplemented with Hopper compute primitives. Keep the existing narrow H100 Q/G training fusion only if matched whole-module measurements justify an exception. For wide shapes, examine frontend/tail global intermediates and the full backward gradient layout before tuning isolated attention tiles. Ending-node transpose copies exist in both paths and remain additional traffic. Front/core/tail refers to three main compute stages, not an exact total launch count.

Any future claimed improvement needs matched H100 whole-module timing and actual dispatch checks. The existing Anthropic comparison measured inference; it does not establish training speed or the benefit of transplanting B200 fusion boundaries.
