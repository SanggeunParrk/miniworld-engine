# TriMul H100 opt12 — B7 affine partials in registers, 2026-10-12

The D64 single-direction B7 kernel now retains input-LayerNorm affine partials in registers across persistent tiles. Compared with [opt11](trimul_b200style_h100_opt11_20261012.md), all **30 changed conditions improve in each of two full forward+backward comparisons**. The first sweep gives **1.002345–1.016504x**; reversing graph-capture order gives **1.005484–1.029991x**. Fresh FP32-master measurements beat cuEquivariance 0.12.0 in **16/16 single-direction D64 shapes, by 2.209796–3.090654x**.

Three qualified files are installed behind the existing `MINIWORLD_TRIMUL_H100_B200STYLE=1` path. Its default remains zero. **SOL90 and the requested 70–80% range remain unmet.** This report adds no inference/Anthropic measurement and does not refresh the wider-width [120-shape training baseline](trimul_h100_master_matched_20261012.md).

## Change and selected scope

Single-direction B7 previously loaded and stored four input-affine partial sums per thread in shared memory on every persistent tile. The candidate keeps four FP32 sums in registers, then publishes them into the original per-warp shared array once before final reduction. Lane ownership, additions, reduction order and rounding are unchanged. Shared-memory allocation remains 170,560 bytes. Saved tensors, global partial buffers, B200 fusion boundaries and HBM traffic are unchanged.

The new source is `h100_sources/d64_train/uni_bwd_wg_affinereg.cu`. Its host entry is `h100_uni_d64_b200gate.py`; the third installed file is `tests/gpu/sm90/test_trimul_h100_d64_b200gate_gpu.py`. The selected three-file manifest records their exact hashes. B1, final reduction and bidirectional kernels retain their preceding algorithms.

The new `_b2w_affinereg` symbol runs for the nonsplit affine configuration, outgoing and incoming, at the eight D64 lengths from 128 through 1024, except outgoing L256. That existing opt11 exception retains `_b2w_b7gate` and was an unchanged control in this experiment. Explicitly forced `MINIWORLD_TRIMUL_H100_D64_UNI_AFFINE_SPLIT=1` retains the old gate-pipeline kernel: the forced split variant passed numerical/sanitizer tests but its NCU result did not justify selecting it. No new environment flag is introduced.

Both graphs are compiled and manually captured, then measured in 90 alternating CUDA-event pairs. Input and parameter tensors match exactly. Profiles check actual kernel selection and absence of Triton. Independent timed dropout draws are not claimed identical.

The two outgoing L256 controls use identical kernels and are excluded from the improvement count. The main sweep's gain is about **0.23–1.65%**; many long-input rows improve by about 0.6–1.1%. The 3% repeat maximum is not a typical or guaranteed gain. Ratios divide sample medians, not confidence bounds. These improvements are relative to the already optimized opt11 kernel, not to the original implementation.

Native paired comparisons use the fixed FP32-master runner `f0ad9729a094a76739865370bc5ace02a1aff3d8178def949876c1090e5aa26d`, with identical shared wrappers on both sides. The vendor comparison uses unrounded FP32 master parameters and BF16 activations, with matching input, parameters, mask and dy. Both native and vendor satisfy the unchanged output/gradient limits of 0.006/0.01, with finite gradients. Same-process outgoing L384 captures profile baseline and candidate B7 with kernel replay. They diagnose the kernel; selection relies on the whole-module pairs above.

| Nonsplit | 86.432 | 83.552 | 38.23% | 39.92% | Yes |
| Forced split | 82.944 | 84.448 | 38.11% | 39.52% | No |

The candidate uses 162 registers versus 156, with zero B7 stack/spill bytes and local-memory sectors. Nonsplit shared-load wavefronts fall from 3,346,723 to 2,586,969; shared-store wavefronts rise from 2,869,067 to 3,204,320. Thus this is not a claim that every shared-memory counter falls. DRAM reads remain about 96.22 MB. B1 is unchanged, including its existing bidirectional spill. Utilization is still well below the requested range; these counters do not prove a hard fusion limit.

## Rejected earlier-input-transfer candidate

A separate candidate prefills both B7 staging slots, then refills tile k's slot for k+2 immediately after its output TMA store finishes reading the slot. This preserves B200 fusion, arithmetic and buffers but requires an immediate store-read wait before replacing XS. That dependency is a plausible source of lost overlap; nominally earlier input transfers do not guarantee faster execution.

The candidate passes 18 bitwise comparisons, the 48-case oracle grid, 36 GPU tests and all nine direction/tool sanitizer combinations. Job 28273's first external pytest invocation fails only because its helper path referred to a missing sibling; the failure is retained, the helper path is corrected, and job 28275 completes qualification without changing CUDA bytes.

Its initial 30 paired cells have only seven wins; 26 cells actually change kernels. Ratios span 0.989654–1.013662x. A four-cell L128 repeat with reversed capture order has two wins, one tie and one loss, including an incoming BF16 regression to 0.991255x. NCU agrees with the long-input regressions: outgoing L384 B7 changes 86.592→87.584 µs and bidirectional 121.856→125.984 µs. Outgoing L128 is essentially unchanged at 20.800→20.832 µs. This candidate is **not installed**, including for short inputs.
