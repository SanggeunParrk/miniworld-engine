# TriMul H100 opt14 — D384 TMA saves without register spills, 2026-10-12

D384 training K3 now saves projection and gate values through TMA while retaining the B200 fusion structure. Relative to [opt13](trimul_b200style_h100_opt13_20261012.md), **92/92 resident full forward+backward comparisons improve, by 1.016024–1.049730x**. The largest bidirectional condition is measured separately in four ABBA/BAAB cohorts and also improves. Fresh FP32-master comparisons beat cuEquivariance in **24/24 training shapes, by 1.361019–2.709819x**, and Anthropic in **16/16 supported inference shapes, by 1.180007–1.265025x**.

Four files are installed behind the existing `MINIWORLD_TRIMUL_H100_B200STYLE=1` path; its default remains zero. The inference algorithm is unchanged. Vendor advantages mostly predate this edit: its incremental result is approximately 3.6% geometric-mean speedup in the resident training comparisons. **SOL90 remains unmet. Unfiltered whole-module synccheck remains incomplete after reproducing a stall on both the original baseline and candidate.** Change-scoped synccheck and racecheck pass as detailed below.

## Change and selection

D384 uses BN192, four operand stages, two column blocks and the original producer/consumer register budgets of 40/232. A direct port of opt13's D256 TMA-save source compiles with **72 stack bytes and 43 local instructions** for both H384 and H768. Obsolete projection accumulator entries remain live across the column-block loop through the WGMMA register dependencies. Clearing those entries after their rounded projection values have been packed removes that lifetime. The next gate WGMMA starts with accumulation disabled, so those old values have no numerical consumer.

The selected CUDA source differs from the D256 scalar TMA source only in its entry name and two accumulator clears. Both hidden widths compile with **168 reported registers, zero stack bytes and zero local load/store instructions**. After each preceding TMA store finishes reading shared memory, K3 reuses the same tile for output, projection and gate stores. Per-warpgroup barriers, store-read waits and the final store-completion wait protect reuse. No saved tensor, global allocation or kernel launch is added or removed. Gate-first GEMM order, scalar LayerNorm statistics, reductions, rounding points, layouts and B200 fusion boundaries are preserved.

Three zero-spill variants each pass 73 GPU tests, four standalone K3 bitwise fixtures and nine official F+B pilot pairs. Their speedup geometric means are 1.033460 for clearing dead projection entries, 1.033512 for clearing every accumulator at the column-block boundary, and 1.032970 for shortening statistics lifetimes with 24/240 register roles. The means differ by less than 0.06%; the selected variant makes the smallest change, preserves register roles and avoids extra input-statistic loads. These pilots are excluded from the final timing grid.

The four files are the host `h100_b200style.py`, new helper `h100_b200style_d384_tmasave.py`, new `h100_sources/b200style/k3d384_tmasave.cu`, and the existing GPU test's D384 dispatch expectation. The host adds saved-output tensor maps and selects the new kernel only for D384 with `save=True`. A source audit checks 2,289 existing source files; only the host file changes. Inference and D256/D512 CUDA sources remain byte-identical. Opaque operation and extension names distinguish the coexisting frozen baseline and candidate.

## Correctness and sanitizers

The selected implementation passes **73 GPU tests**. Across all 48 D384 conditions, output and eight saved tensors match opt13 bitwise. Scaled inference matches training output; inference matches the baseline. All eleven input/parameter gradients on both sides meet the unchanged independent FP32 reference threshold of 0.01, with 0.006 for output. No bitwise gradient equivalence is claimed. Maximum native output/gradient relative errors in the final grid and vendor comparisons are **0.00360377 / 0.00638694**. All nonresident legs meet the same limits.

At D384/L256, six changed-value graphs cover all three directions in inference and training. Each changes inputs, weights/affines, mask and applicable dropout scales/dy over three trials, including zero mask. **Unfiltered whole-module memcheck passes with zero errors.** Full-module racecheck restricted to K3 passes with zero hazards, errors or warnings. Unfiltered standalone K3 racecheck also passes H384/H768 × L128/L256, three changed trials each, with output, projection, gate, mean and rstd bitwise equal to the original K3. These cover persistent tile and shared-memory reuse.

**Unfiltered whole-module synccheck does not complete.** The initial candidate run stops progressing at incoming-training Graph replay, with its process waiting in `torch.cuda.synchronize`; that run is explicitly stopped and its log and Python/native stacks are retained. A frozen opt13 baseline control reproduces the incoming-training replay stall and reaches a 120-second timeout. A fresh incoming-only candidate control also times out, before completing capture. Neither control is a pass. A specific kernel cause or an instrumentation defect has not been established.

Full-module synccheck restricted to K3 passes all six changed-value graph conditions with zero errors. Unfiltered standalone K3 synccheck passes the four H/L cases with three changed trials and five bitwise output checks. These results qualify the changed K3's synchronization; they do not claim whole-module synccheck coverage. This limitation remains visible in the installation receipt and summary.

An earlier selected-file packaging run renamed the requested CUDA symbol but omitted its source declaration rename. It fails with `CUDA_ERROR_NOT_FOUND`. The declaration is corrected before restarting qualification; the original failure and manifest are preserved. No arithmetic or threshold change is used to resolve it.
