## B200 fusion exception and lifetime analysis

The B200 wide backward in `b200_train.py` recomputes front preactivations in `k1wb`, then separately materializes BF16 XN through `wide_ln_apply` for the weight-gradient GEMM. On the H100 D384 RS implementation, K1 already holds these normalized fragments in registers. The separate materialization rereads the input and saved statistics despite those values being available during recomputation.

The change merges that materialization into K1. This is an explicit exception to the exact B200 launch partition. The folding identities, contractions, gradient reductions, GEMMs, normalization order and BF16 rounding remain the same. XN retains its token-major layout and remains unmasked, as required by the output-gate weight gradient. Forward output and all eight saved tensors retain their layouts and measured bitwise values. No new activation is saved across forward/backward, and no extra device tensor or shared-memory allocation is introduced. XN already existed as backward scratch; dW remains its consumer.

The selected implementation converts each 64-channel fragment group into the existing 8 KB per-consumer epilogue stage with `stmatrix`, then issues a TMA store. A store-read wait drains the preceding persistent tile's dcat write before the stage is reused. Proxy fences and warpgroup barriers protect each XN store and subsequent stage reuse. The existing final store-completion wait covers XN as well as dcat. The producer's input-prefetch stage is unchanged. Opt15's dplane prefetch remains active.

The nominal avoided input read is `2 * L * L * 384` bytes, or 113,246,208 bytes at L384, plus repeated statistic/affine reads. XN's write and its later dW read remain. NCU below confirms a reduction in reads; fewer launches alone did not determine selection.

The first scalar-store variant enables K1's existing EMITX path. It passes four changed-input Graph cases and six independent full-gradient fixtures, but its L384 complete F+B gains are only 1.007527x outgoing and 1.004289x bidirectional. The TMA-stage variant passes the same fixtures and improves those pilots to 1.017766x / 1.015479x, so it is selected for the full grid.

The selected source passes **73 GPU tests in 115.33 s**. Six full-module L256 Graph cases cover inference and training in every direction while changing inputs, masters, masks, dropout scales and dy.

Unfiltered standalone **memcheck, synccheck and racecheck** pass H384/H768 at L128/256 with zero errors/hazards/warnings. Unfiltered full-module memcheck passes all six Graph cases. Full-module synccheck and racecheck restricted to the changed K1 pass all three training cases; inference does not launch that kernel. Full-module synccheck with WGMMA checking disabled also passes all six cases and is recorded as a distinct scope.

**Unfiltered whole-module synccheck is intermittent.** The selected prototype completes all six cases with zero errors in job 28749. Its frozen opt15 control also times out after 120 seconds, before outgoing-training capture completes. Preserve the one successful run and both timeouts; do not describe this as stable unfiltered whole-module coverage or as a fixed sanitizer defect.

Packaging formats the new helper and adds a host-side missing-XN argument check. Both H384 and H768 have exactly the same **5,664 encoded 64-bit GPU words** as the measured prototype. Both baseline and candidate use **168 registers**, zero stack/local storage and zero local load/store instructions. Dynamic shared memory remains **216,192 bytes**; kernel parameter constants grow by one 128-byte tensor map. The packaged source passes **73 GPU tests in 116.56 s**, six changed-value Graph cases and unfiltered standalone synccheck.

Tooling failures remain available: an initial launch omitted `bash` for a non-executable wrapper; the first TMA source used a host-only constexpr conversion; a local `profile.py` shadowed the Python standard module; and the first progress reader expected long-form NCU CSV rather than the actual wide form.
