# TriMul H100 opt17 — D256 backward XN emission and dplane prefetch, 2026-10-12

D256 backward now writes normalized input XN during K1 recomputation and overlaps dplane loads with WGMMA. Relative to [opt16](trimul_b200style_h100_opt16_20261012.md), **96/96 resident complete forward+backward comparisons improve by 1.015317–1.047550x**, geometric mean **1.032689x**. Fresh FP32-master training comparisons beat **cuEquivariance 0.12.0 in 24/24 shapes**, by **1.184106–2.863649x**, geometric mean **1.979919x**.

Three files are installed behind the existing `MINIWORLD_TRIMUL_H100_B200STYLE=1` path. Its default remains zero. Inference and other widths retain their algorithms. **SOL90 and the requested 70–80% range remain unmet.** Most of the vendor advantage predates this edit; the incremental result is the comparison against opt16.

## Fusion exception and memory lifetime

The B200 wide backward in `b200_train.py` runs `k1wb_forward` to recompute front preactivations and separately calls `wide_ln_apply` to generate BF16 XN for dW. Opt16 already documents the D384 exception that materializes XN from K1's normalized register fragments. This change independently validates the same launch-partition exception at D256. It also applies the existing dplane-prefetch schedule to D256, issuing the dplane TMA load before the corresponding WGMMA block and consuming it in the epilogue after MMA completion.

Four 64-channel XN tiles reuse the existing 8 KB epilogue stage per consumer warpgroup. The preceding dcat shared read is drained before reuse; proxy fences, warpgroup barriers and store-read waits protect each XN tile. The existing final TMA completion wait covers XN as well as dcat. The producer input-prefetch stage retains its lifetime. No global allocation, shared allocation, forward activation save, reduction, folding identity, normalization order or GEMM is added or changed. All eight saved forward tensors retain their layouts. XN remains unmasked because the output-gate weight gradient requires it.

The nominal eliminated input reread is `2 * L * L * 256` bytes, or **75,497,472 bytes at L384**, plus saved-statistic and affine reads. XN's write and its dW read remain. K1 returns that XN was emitted, removing the separate `ln_apply` call. Missing XN in either D256 or D384 backward is rejected by the host helper. Inference, D384 and D512 arithmetic and launch partition remain unchanged.
