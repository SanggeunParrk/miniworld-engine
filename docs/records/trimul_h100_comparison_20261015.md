## Anthropic payload (inference only)

The release's `trimul_native` v5 units only exist for some widths, and its shipped cubins (nvcc 13.0) segfault on this driver, so the
payload is the unmodified sources rebuilt with CUDA 12.9 (`~/ext/trimul_native_cu129/build`, `TRIMUL_NATIVE_BUILD_DIR`). Units cover
single direction D64 / D128 / D256 / D384 and bidirectional D64 / D128; D512 and bidirectional D256 / D384 / D512 have none. The two
modules are built side by side in one process and replayed alternately (min of 5 x 30 graph replays), because the Anthropic row moved by

## Changes made while measuring

* **D512 incoming training was on the Triton fallback** (`uni_training` required `outgoing`): L768 24.0 ms. Both directions now run the
  CUDA `h100_uni_wide_training` path: 18.1 ms. Details: [dispatch selection record](trimul_h100_dispatch_selection_20261013.md) Addendum 16.
* **Residual Triton pieces replaced by the existing CUDA kernels** (weight pack `_pack`, LN-affine fold `_fold`, input LN under
  `torch.compile`): a 240-cell kernel-name scan found 13 cells with Triton kernels (wide training / D512 bidirectional inference), all
  below 6 % of the step; the re-scan of the 36 wide cells shows none. Speed unchanged (0.99 - 1.00x) after switching the input LN to the
  one-warp-per-row kernel (one block per row was 0.87x - 0.95x at bidirectional D512). Regression selection: 556 passed, 0 failed.
* **Single direction D256 inference** takes the tmn K1 / K3 tiles at every L except 384 (in-process A/B against the B200-style port,
  alternating order: 0.983 - 0.995 of its time at L128 / 256 / 512 / 640 / 768 / 896 / 1024). The grids above for that cell were
  measured before this change and are 0.7 - 2.5 % conservative.
