# H100 TriMul D256 (one direction, inference) vs Anthropic `trimul_native`, 2026-10-31

Branch `perf/trimul-d256` (from `perf/trimul-15pct`). Setup, probes and conventions as `trimul_h100_vs_anthropic_15pct_20261030.md`
(graph replays, alternating, median of 9 or 11; ours / Anthropic < 1 = ours faster; outputs compared bitwise with Anthropic's).
Probes: `~/miniworld-engine-scratch/perf1030/probe/` (`k3_diag_probe.py`, `k3_split_probe.py`, `lt_probe.py`, `lt_fixed_probe.py`,
`grid_probe.py`).

## 1. K3: where the time goes (port K3, D256, ROWPAD maps, graph)

`K3_DIAG` measurement builds: 1 = no epilogue arithmetic (y = the x tile as loaded), 2 = no MMAs issued.

| L | full | no epilogue | no MMA | neither | HBM floor (3.6 bytes x L^2 D / 2.6-2.8 TB/s) |
|---|---|---|---|---|---|
| 512 | 0.188 | 0.152 | 0.170 | 0.152 | 0.145-0.155 |
| 1536 | 1.597 | 1.311 | 1.443 | 1.310 | 1.29-1.39 |

Without its epilogue arithmetic K3 streams at the HBM rate; the epilogue costs ~19 % because HBM idles while it runs (the MMAs
hide under the streams). Variants that made TMA zero-fill instead of reading (pair-row extent 1) turned out slower than the real
loads at L1536, so the earlier "83-86 % non-memory" reading (previous record, section 4) overstated K3's compute share.

Rejected: **split operand rings** (k3.cu `NSA` / `NSB`: x / tri chunks in their own deeper ring, weights in a 2-stage ring, one
producer thread each, so the DRAM prefetch can run ahead through the epilogue): 20-50 % slower at D256 / D384 L256-2048 (D256
L512 0.231 vs 0.191, L1536 1.97-2.04 vs 1.65): with two weight stages the L2 latency of each 32 KB weight chunk shows; three
weight stages next to a deeper A ring exceed shared memory (239 KB). Outputs bitwise equal. The switch was removed again (the
measured variant is `~/miniworld-engine-scratch/perf1030/k3.cu.with_split`).

Not built: an epilogue overlapped with MMAs (consumer ping-pong on different tiles, or the projection split into two N halves with
the first half's epilogue under the second half's MMAs). Ping-pong streams each weight chunk once per 64 tokens instead of per 128
(2x the L2 -> shared traffic, ~6.7 TB/s at L1536, beyond L2) or needs both phases' weight chunks in one stage (80 KB stages, two
fit); the N split needs the tri / x chunks resident for both halves (4 x 48 KB) or streamed twice (+33 % L2 traffic), and 192 of
the 232 consumer registers for two accumulator halves plus both packed gate halves. Upper bound of either: the 19 % above, ~5 % of
the call.

## 2. The contraction: cuBLASLt configurations

(tNcMkK = tile id N, custom option M, cluster shape id K; two values = two processes.) Which configuration wins, and whether the
heuristic offers it, changes from length to length (at L896-1408 the L768 winner runs 1.0-1.4x), so a fixed tile-shape rule does

reproduced at <= 0.95 in two processes, keyed (L, a transposed, planes per launch); `_h100_bmm.contract` takes the heuristic
candidate with that configuration (no workspace) and falls back to `bmm` elsewhere. Used by the packaged K1/K3 path and the port's
one-direction contraction (B200's `b200_infer._contract` unchanged). `cublasLtMatmulAlgoInit` with the same attributes is refused by
`cublasLtMatmulAlgoCheck` for most of them, so the heuristic's own candidate is taken.

## 4. K1: where the time goes (port K1 `mw_b200style_k1_direct`, D256, graph)

Measurement builds: LNM 0 (no input LayerNorm), `TMN_K1_DIAG` 2 (no gate arithmetic: the planes take the raw accumulators),
4 (no MMAs).

| L | full | no LN | no gate | no LN, no gate | no MMA | none (loads, stores, barriers) |
|---|---|---|---|---|---|---|
| 512 | 0.284 | 0.267 | 0.250 | 0.227 | 0.192 | 0.181 |
| 1536 | 2.389 | 2.230 | 2.176 | 2.060 | 1.710 | 1.599 |

K1 is MMA-bound: its MMAs alone need 1.85 ms at L1536 at the 670 TFLOP/s this card sustains (2.06 ms with the streams), and the
input LayerNorm (~7 %) and the gate arithmetic (~9 %) do not hide under them. The gate (sigmoid(g) * p * mask per output, fp32,
rounded once) cannot shrink without moving a rounding point. Hiding the LayerNorm needs the next tile's A fragments while the
current tile's wgmmas still read their registers (RS operands): a second 64-register fragment set (the consumers already sit at
the 232-register cap with the two 32-register accumulators), or SS operands normalised in shared memory by the producer warpgroup
(its own summation order, so the LN statistics -- and the bf16 rows -- would no longer match the packaged arithmetic bitwise).
Not built.

Tile / ring / schedule sweep (port K1, graph, vs the shipped (2, 64, 4 slots, 4 chunks, schedule 0)): schedule 1 1.00-1.11,
(2, 64, 8, 2) 1.08-1.09 (schedule 0) / 1.04-1.16 (schedule 1), (1, 128, 8, 2) 1.04-1.07, (1, 128, 4, 4) 0.99-1.03, (2, 64, 6, 2)
1.10-1.27, (1, 64, 4, 4, 2 CTAs / SM): exceeds shared memory. The shipped tile stays.

What bounds D256 now: K1 (~40 % of the call) is the same kernel family as Anthropic's and runs at its speed, MMA-bound plus the

well under Anthropic's K1 -- the LN / gate overlap of section 4 -- which this branch does not build.
