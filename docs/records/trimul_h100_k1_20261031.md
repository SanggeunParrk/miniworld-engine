# H100 TriMul K1 (input LayerNorm + four projections + gating), one direction, inference, 2026-10-31

Branch `perf/trimul-k1` (from `perf/trimul-d256`). The K1 measured here is the port's `mw_b200style_k1_direct` (packaged
`tmn_kernels.cuh` `k1_body`, LNM 1, LN_in statistics saved), driven alone through `h100_b200style_direct.front` (graph replays,
alternating variants in one process, median of 10; probes `~/miniworld-engine-scratch/perf1030/probe/k1_diag_probe.py`,
`k1_det_probe.py`). Bitwise = every plane and statistic equal to the shipped build; first-run correctness = run 0 into a reused
`torch.empty` buffer against an fp32 reference of LN -> projections -> sigmoid gate -> mask (`k1_det_probe.py`).

## 1. Bitwise-preserving overlap

**(a) The input LayerNorm on producer warps (`TMN_K1_PLN`, patch `~/miniworld-engine-scratch/perf1030/k1_producer_ln.patch`).**
`ln_fragment` (LNM 1) is fully determined by the data layout: lane q of a fragment row sums, per k-step, (lo0 + hi0) + (lo2 + hi2)
of the pairs k = 16 ks + 2 q (+1) and 16 ks + 2 q + 8 (+1); math::TreeSum's balanced tree over the k-steps; `quad_sum` (xor 1 then
xor 2) = (S0 + S1) + (S2 + S3); the centred squares the same way; `ln_affine` per element, one bf16 rounding. Producer warps 2 and 3
reproduce it four lanes per row (the consumers' own lane mapping and butterfly) on the z tile in shared memory; a new barrier hands
the tile to the consumers. **Bit-identical at D64 / D128 / D256 / D384** (planes and statistics), first run correct.

| variant (D256, same process) | L512 | L1536 |
|---|---|---|
| one thread per row, full LN in place, producer 40 / 56 / 72 registers | 3.85x / 2.9x / 2.7x | 3.9x / 2.9x / 2.6x |
| four lanes per row, full LN in place, producer 40 / 56 | 1.72x / 1.54x | 1.75x / 1.58x |
| four lanes per row, statistics only (consumers apply `ln_affine_given`), producer 56 | 0.99x | 0.98x |
| same, other lengths (producer 56 / 64) | L256 1.09 / 1.07, L384 1.05 / 1.05, L768 0.99 / 1.04, L1024 1.00 / 1.06, L2048 1.05 / 1.10 | |
| D384 statistics only (56 / 64) | L512 1.03 / 1.05, L1024 0.99 / 0.95, L1536 1.00 / 0.96 | |
| D128 statistics only (40 / 56) | L1536 1.47 / 1.15 | |

The producer warpgroup's register share is the limit: the consumers need their 232 (64 fragment registers, two 32-register
accumulator sets, the gate epilogue), which leaves 40 for the producer warpgroup (launch bound 168 x 384 threads); at 40-72 the
one-thread-per-row form spilled 1.4-1.7 KB per thread (SASS: 921 local loads / stores in the producer branch), the quad form
~0.2 KB. Two warps then do in shared memory what 256 consumer threads did in registers; per tile that is slower than the tile's
MMAs at small L and at D128 (192-token tiles, K = 128). Not routed; the code is removed again (the patch keeps it).

**(b) A-fragment double buffering in the consumers.** Not built: a second 64-register fragment set next to the two 32-register
accumulator sets and the epilogue exceeds the 232-register consumer cap (the LayerNorm alone already serialises its affine pass at
KS >= 24 to stay inside it); 3 warpgroups (1 + 2) is the shipped layout, 2 + 1 halves the MMA warps.

**(c) Gate epilogue overlapped with the next block's MMAs.** Already the shipped schedule (block b + 1's wgmmas are issued before
block b's epilogue, wait depth 1, two accumulator sets, TMA bulk store of the planes). Measured around it:
- Relaxing the per-block plane-store wait (`tma_store_wait_read<0>` -> `<1>`, the other staging buffer's store left in flight):
  0 % faster (D64-D384, L512-2048) and **wrong**: run 0 into a fresh buffer had max error 4.2-4.9 vs the fp32 reference in one
  channel block of the first wave (the stmatrix writes of block b land before the elected thread's wait, so `<0>` at block b - 1 is
  what retires block b - 2's store). Reverted; the bitwise A/B caught it.
- The engine's other store paths: per-warp stores without the warpgroup barrier (`TMN_K1_WARPSTORE`) 1.25-1.32x, the staged lane
  path 1.01-1.03x (both bitwise equal). The bulk store stays.

**(d) Cheaper exact gate math.** The epilogue is sigmoid via one `tanh.approx` (MUFU) + FMAs, the product with p and the mask,
one `cvt.rn.bf16x2` per pair, two stmatrix per block: no redundant conversion to remove without moving a rounding point.

## 2. Variants that change rounding

Not prototyped: the only K1 costs not already at a hardware bound are the LayerNorm (~7 %) and the gate (~9 %). A one-pass
LayerNorm (sum and sum of squares together) saves one of its three passes (~2 % of K1) and is less accurate than the centred
two-pass statement (cancellation in E[x^2] - mean^2), so it would fail "error <= current"; a bf16x2 gate moves the gate's
rounding point for a few percent.
