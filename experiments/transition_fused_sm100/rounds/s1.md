# transition_fused_sm100 — small-L round s1: cluster-scope releases off the critical path, SwiGLU item schedule up to L = 640

- Date: 2026-09-29. User: make a small-L configuration. B200 GPU 7 (`gpuq`), inference forward, CUDA-graph replay medians, µs.
  Variant A/Bs run in one process, alternating (run-to-run noise across processes ~+-10 %).

## 1. Where one tile's time goes (D64, `-DTRACE`)

`src/tfwd_d64.cu -DTRACE` stamps clock64 on CTA 0 / 1 and globaltimer entry / exit of every CTA (`g_t64`, `g_gt`). L128 (128 tiles,
one per CTA), CTA 0, ns from entry:

| event | before | after §2 |
|---|---:|---:|
| barriers initialised (`fence.mbarrier_init.release.cluster`) | 434 | 426 |
| setup cluster sync done | 1130 | 870 |
| LayerNorm: x arrived / done | 1827 / 2607 | 1274 / 2137 |
| MMA sees xn_full | **3174** (+570 after LN done) | 2199 (+60) |
| SwiGLU chunks 0-3 (MUFU-bound: 2 MUFU ops per element, ~2.2 µs per tile at 16 / clk / SM) | 3523 .. ~6300 | 2519 .. ~5400 |
| epilogue out_full / store issued / store done | 6501 / 6978 / 7325 | 5521 / 5995 / 6340 |
| teardown cluster sync done | **7949** (+620) | 6486 (+150) |
| exit | 8192 | 6720 |

The two gaps are `mbarrier.arrive.release.cluster` (the LayerNorm's xn_full signal to the leader) and `barrier.cluster.arrive` (release
by default): each cluster-scope release costs ~0.5-0.6 µs on sm_100a. `try_wait` vs `test_wait` on the waiting side made no difference
(`-DWAIT_CL_TEST`).

## 2. Change (all fused forwards + tswiglu_w + tgemm_nd; `-DOLD_SYNC` restores the old code)

- xn_full: `mbar_arrive_remote_cta` = `mbarrier.arrive.release.cta.shared::cluster` (CUTLASS's `ClusterBarrier::arrive(cta_id)`). The
  payload is shared memory the arriving CTA's threads wrote and fenced to the async proxy; the pair's MMA reads it.
- setup: `fence_barrier_init` (the one required cluster-scope release) then `barrier.cluster.arrive.relaxed` + wait
  (`cluster_sync_relaxed`, CUTLASS's `fence_barrier_init` + `cluster_arrive_relaxed`).
- teardown: `cluster_sync_relaxed` (the pair's TMEM traffic is ordered by the MMA commits and tcgen05 fences).
- D64 / D128: tile 0's x TMA-loaded by the barrier-initialising thread before the cluster sync; D64: gamma / beta loaded by the
  LayerNorm warps under that load.

Outputs bit-identical to the old build at every width and length (also 1 / 3 / 147 / 149 / 297 tiles, 20 replays each), µs:

## 3. SwiGLU schedule by L (D384 / D512, `tswiglu_w -DITEM_SCHED`)

Tile schedule: each cluster pair runs whole tile pairs, all H / 128 chunks of each. Item schedule: (tile pair, chunk) items dealt
round-robin over all pairs (grid = SM count). Outputs identical. SwiGLU kernel alone, medians of 3-6 alternating rounds:

| | L128 | L256 | L384 | L512 | L640 | L768 |
|---|---|---|---|---|---|---|
| D384 tile -> item | 29.6 -> 28.9 | 135.2 -> 118.9 | 321 -> 279 | 565 -> 490 | 849 -> 838 | 1177 -> 1209 |
| D512 tile -> item | 74.8 -> 64.5 | 270.5 -> 197.6 | 548 -> 477 | 928 -> 891 | 1439 -> 1423 | 2059 -> 2069 |

The kernel alone gains up to L640, but the whole forward (LN -> SwiGLU -> squeeze, same process, 6 alternating rounds) only up to L384:

| | L256 | L384 | L512 | L640 |
|---|---|---|---|---|
| D384 forward tile -> item | 250.0 -> 228.9 | 519.3 -> 498.4 | 920.6 -> 917.2 | 1440.7 -> 1445.6 |
| D512 forward tile -> item | 417.4 -> 357.5 | 851.2 -> 840.9 | 1509.2 -> 1510.0 | 2352.3 -> 2347.9 |

Adopted: item schedule up to 1152 tiles (L <= 384), tile schedule above (`bench_infer_all.swiglu_sched`).

## 4. Measured, not adopted

| variant | result |
|---|---|
| D64 `-DSWIGLU_SPLIT`: both warpgroups on every chunk, 32 units each | slower at every tile count (1 tile 8.7 -> 9.1; the SwiGLU is MUFU-bound, not latency-bound) |
| D64 sigmoid on the FMA pipe (`SIG_NR`, `SIG_POLY`, `SIG_MIX`) | slower (the warps are issue-bound too) |
| D64 `SIG_TANH` (one MUFU op, tanh.approx: relaxed) | L128 9.6 -> 8.6, L768 116 -> 108; output error unchanged (2.25e-3) but the negative tail of silu loses relative accuracy -- kept opt-in |
| tgemm_nd (squeeze) `-DEPI3` (3 epilogue warpgroups), `-DLATE_REFILL`, `NST_=3` | equal or slower; with the epilogue removed (`-DABL_NOEPI`) the kernel is ~20 % faster, but that also removes the x read and out write (energy), so the epilogue is not a serialisation to schedule away |

## 8. Training kernels (L384 / L768 only; user: training is fixed to these)

- Setup / teardown syncs relaxed in the backward kernels too (`tbwd`, `tbwd_d64`, `tgate_w`, `tgate_ab`; tgemm_nd / tswiglu_w in §2):
  they have no per-tile cluster-scope release, so this is ~1 µs per kernel (0.3-1 % of a step, below the process noise). Every
  rebuilt cubin's `-DOLD_SYNC` build has the SASS of the previous cubin (same flags); gradients unchanged.
- D384 / D512 SwiGLU forward with saves on the item schedule (`tswiglu_abis_d*`, `bench_wstep.py --sg-item`), and the backward gate on
  it too (`tgate_ab -DITEM_SCHED`, `tgate_abnhis_d*`, `--gate-item`); same process, 5 alternating rounds, µs, gradients identical:

| | fwd tile / item / item + gate | step tile / item / item + gate |
|---|---|---|
| D384 L384 | 665.5 / 642.4 / 642.5 | 1917.9 / 1915.6 / 1913.9 |
| D384 L768 | 2605.0 / 2545.7 / 2551.0 | 7658.7 / 7585.2 / 7592.0 |
| D512 L384 | 1046.7 / 1000.0 / 1003.3 | 3066.3 / 3048.2 / 3075.3 |
| D512 L768 | 4150.9 / 3998.2 / 3996.1 | 12201.4 / 12134.7 / 12235.8 |

  The forward gains 2-4 %, the step 0-1 %: the card is at its power cap, so the energy saved nowhere shows as time saved in the step
  (w5 §2). Adopted: SwiGLU item schedule in training (harmless, forward faster); the gate item schedule: no (not faster).
- What is left for training is wiring, not kernels: the engine has D128 only.
