# transition_fused_sm100 — round v10: DX accumulator / buffer restructuring (measured, not adopted)

- Date: 2026-09-25
- Target kernel: `transition_bwd_sm100`, DX role. Kernels unchanged from v9 (`963aa7a0`); all variants are kept as patches in
  `records/experiments/`.

## 1. Starting point (v9 trace, `trace_bwd.py` with producer and per-warpgroup stamps)
Per DX chunk ~3230 clk, dependency cycle over two chunks: ab(c) → gate(c) 1785 → d_xn(c) issued 1070 after the gate → `[Wa;Wb]`
slot refill 441 + 762 → ab(c+2). Both gate warpgroups finish together (−13..−26 clk apart); TS with an MN-major B runs at full rate
in isolation, so d_xn's slow completion (~1180 clk after the gate for 512 clk of work) is contention with chunk c+1's dh / `[a|b]`.

## 2. Variants

| variant (patch) | idea | L384 bwd (best R) | what the trace showed |
|---|---|---:|---|
| `bwd_x_in_tmem_3slot` | x copied to TMEM (tcgen05.cp), single xn buffer, third `[Wa;Wb]` slot | 243 µs | weight wait gone; d_xn still contends with dh / `[a|b]` of c+1 |
| `bwd_dedicated_dab_buffer` | `[dA|dB]` in its own TMEM buffer, single dh; `[a|b]` / dh released when the gate has READ them | 232 µs | the `[Wa;Wb]` slot chain becomes the limit again (980 clk wait) |
| `bwd_single_buffer_x_in_tmem` | the above + single `[a|b]` (freed early) + x in TMEM + third slot (TMEM 448 cols) | 256 µs | in-tile chunk 3200 → **2380 clk**, but each tile boundary costs ~5400 clk (x load → TMEM copy → next xn load, serial) |
| `bwd_single_buffer_x_via_dy` | x staged through the dy buffers ahead of time, two TMEM x buffers | 293-526 µs | the dy buffer's reuse now waits for the LayerNorm-backward epilogue (~12 k clk per tile), stalling dy of the next tile |

## 3. What this establishes
The DX role couples three chains that all want the same 227 KB of shared memory and 512 TMEM columns: the `[Wa;Wb]` slot cycle,
the `[a|b]` / `[dA|dB]` accumulator reuse, and the tile-level input / x / epilogue cycle. Fixing one within the budget moved the
bottleneck to the next; the in-tile chunk did get to 2380 clk (−26 %), so a DX role near the gate's own period is possible if the
tile boundary is solved too. The epilogue (~7-8 k clk pass 1, ~4 k pass 2 per tile) is what makes buffer reuse across tiles slow —
a faster LayerNorm backward is the prerequisite for the single-buffer layout to pay.
