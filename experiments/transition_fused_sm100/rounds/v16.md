# transition_fused_sm100 — round v16: relaxed precision (e4m3) + exchange backward — training step at SoL 91 % (L384) / 96 % (L768)

- Date: 2026-09-26. The user allowed a precision change and an algorithm change. The bf16 kernels (v8 forward, v9 backward) stay the
  default contract path; the new path is separate: `src/tfwd8.cu` (forward), `src/tbwd8x.cu` (backward + weight quantizer + reduction),
  hosts `fwd8_op.py` (`FusedFwd8`, `Train8`) and `bwd8_op.py` (`Quant8`, `FusedBwd8x`), bench `bench8.py`, `step8_sustained.py`.
- Intermediate kernel `src/tbwd8.cu` (e4m3, H100 recompute structure, DX-published dy_q) is kept for reference: backward 188 µs.

### SoL (training step)
Basis, unchanged from v9-v15: the H100 design's tensor work 28·M·D·H (270.6 GFLOP at L384) against the bf16 cuBLAS 8192³ ceiling,
both measured **in the same regime, back to back** (`step8_sustained.py`, ~3 s NVML-sustained):

| | cuBLAS ceiling | step | SoL |
|---|---:|---:|---:|
| L384 e4m3, R = 14 (two runs) | 1.30 PF/s | 227.7 / 228.1 µs | **91.2 / 91.1 %** |
| L384 bf16 v8 + v9 | 1.30 PF/s | 318.6 µs | 64.9 % |
| L768 e4m3, R = 13 | 1.30 PF/s | 861.1 µs | **96.6 %** |

Correction of the earlier rounds: v9-v15 quoted the bf16 step as 71 % "against 1.30 PF/s", but compared a short-burst graph time
(291 µs) with the sustained ceiling. Same-regime numbers for the bf16 step are 65 % (sustained / sustained) and 63 % (burst / burst,
cuBLAS 1.46 PF/s). Burst-regime SoL of the e4m3 step: 224.7 µs vs 185 µs ideal at 1.46 PF/s = 83 %; the burst ceiling itself moves
between 1.30 and 1.8 PF/s run to run, so the sustained figure is the one to use on this power-capped card.

What the SoL does and does not say: the numerator is the reference algorithm's work at bf16 rate, i.e. this is a time target
(≤ 230 µs sustained at L384). The kernels execute less tensor work (22·M·D·H: no DX recompute) and mostly at e4m3 rate; against a
precision-matched ceiling (e4m3 2.57 PF/s sustained) the executed work runs at ~45 %.

## 2. What changed

### Precision (e4m3 operands, fp32 accumulate)
- Forward: xn → e4m3 with the bound-based scale s_x = (max|γ| √127 + max|β|) / 448 (overflow impossible); weights e4m3 per tensor;
  h → e4m3 in TMEM with a delayed scale; stored xq (e4m3) replaces the bf16 xn save.
- Backward: [a | b] recompute, dWab and d_xn in e4m3; dA / dB e4m3 (delayed scale); dh and dWs stay bf16 (dy bf16 × Ws bf16,
  dy bf16 × h bf16) — an e4m3 dy needed a conversion whose placement always ended up on a critical path (section 3).
- SwiGLU (both passes) in packed fp32x2 (FFMA2 / FMUL2) with sigmoid(a) = 0.5 tanh(a / 2) + 0.5 (one MUFU op per element).
- Delayed-scaling emulation: activation amax values come from a torch pass over the same inputs at bind time (in training: the
  previous step's amax); the weight quantizer runs inside the timed step.

Accuracy vs the fp32 autograd module (L384; L128-L768 within ±0.5 pt): y 3.4 % (residual branch 6.6 %), dx 3.7 %, dWa 5.8 %,
dWb 5.4 %, dWs 5.4 %, dgamma 5.3 %, dbeta 5.8 % — the bf16 kernels are at 0.2-0.4 %. Finite and bit-reproducible at every length.

### Algorithm (backward, `tbwd8x.cu`)
- The DW slice CTAs keep the recompute of their slice (dh, a, b), run the only gate, and publish the e4m3 [dA | dB] block of each
  (tile, slice) — 16 KB, TMA store from the buffer their dWab product reads, flag with release / acquire and a per-launch epoch.
- The DX CTAs no longer recompute or run a gate: d_xn = [dA | dB] [Wa; Wb] from the published blocks (A from shared memory, K-major;
  weights streamed, multicast over the pair), then the LayerNorm backward on two warpgroups (64 columns each, row sums through
  shared memory — the single-warpgroup epilogue took ~15 000 clk per tile and was the critical path once the gates were gone).
- Tensor work 22 → 16·M·D·H per backward; gate evaluations halved; R = 14 (112 DW + 36 DX CTAs).
- Reduction kernel: dgamma / dbeta summed one column per warp (was 7.3 µs, now < 1 µs of the step); weight quantizer vectorized.

## 3. Measurements that shaped the design
- MMA energy (`mma_energy.cu`, resident operands, 148 SMs): bf16 0.39 pJ/FLOP at 2.23 PF/s (878 W, not capped), e4m3 0.18 pJ/FLOP;
  f16 accumulation saves ~10 % of MMA energy only. cuBLAS (with data movement): bf16 1.31, e4m3 2.57 PF/s sustained.
- Timing models (half the MMA instructions, numerics wrong) in `tbwd.cu` / `tfwd2.cu` (`FP8SIM`, `GATE_H2`, `DW_DB2`, `EXCH_SIM`,
  `DX_NOREC`): e4m3-rate MMA alone brought the bf16 step from 305 to 260 µs — not enough; the gates are issue / latency bound, not
  MUFU bound (tanh sigmoid alone: no gain).
- tbwd8 (recompute structure, e4m3): dy conversion inside every DW slice CTA (8× redundant, 1334 clk per tile on one warp per SMSP)
  serialized the 2-stage input ring (2975 clk per DW tile). Publishing dy_q from the DX role removed that (1733 clk) but made DW wait
  on DX; R = 7 balanced it: 188 µs backward, 186 mJ (bf16 v9: 241 µs, 236 mJ).
- tbwd8x with DX-published dy_q deadlocked (warps 12-15 fell into the epilogue branch — fixed) and then paced DW on a slow converter;
  dropping dy_q entirely (bf16 dh / dWs in DW) was simpler and faster.
- Programmatic dependent launch between the kernels (`-DPDL`): 231.3 / 231.6 µs vs 227.7 / 228.1 µs without — off by default.
