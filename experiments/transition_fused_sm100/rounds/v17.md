# transition_fused_sm100 — round v17: e4m3 path tuning — training step SoL 93 % (L384) / 99.6 % (L768), 95 % / 102 % with e4m3 dy

- Date: 2026-09-26. Builds on v16 (`tfwd8.cu`, `tbwd8x.cu`). Defaults changed: fp32x2 LayerNorm-backward epilogue in the DX role
  (`EPI2`, now default; `-DEPI1` restores v16), fp32x2 LayerNorm statistics / normalization and residual in the e4m3 forward, host
  shared-memory request raised to the maximum so every ring-depth build fits. New opt-in: `-DDW_DYQ` (the DW role converts bf16 dy to
  e4m3 itself, from a multicast double-buffered staging ring, so dh and dWs run in e4m3 as well).

## 3. Tried, not adopted
- DX tail: the DX CTAs end ~10 µs after the DW CTAs (last-published tiles + one epilogue). Deeper [dA | dB] / weight rings (4 / 3),
  no weight multicast in DX (`DX_NOMC`): ±1 µs. Dynamic DX tiles claimed from a global counter with finished DW CTAs joining:
  slower (234 µs step, 708 B spills from the second inlined epilogue) and not bit-reproducible (dgamma / dbeta summation order
  follows the claim order) — removed.
- DX epilogue reading x / dy from global memory into registers (to free 128 KB for deeper rings): 120 B spills, 269 µs — reverted.
- L2 policy hints (evict_last on the exchange stores, evict_first on streamed inputs): 174.4 vs 172.6 µs; no L2 discard: 176.1 µs.
- PDL on the quantize → forward boundary only: no change (223.4 vs 223.2 µs).
