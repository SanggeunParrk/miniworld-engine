# transition_fused_sm100 — round v20: the exchange backward in bf16 (contract kept) — no real gain

- Date: 2026-09-26. The e4m3 record's algorithm (DW slices run the only gate and publish [dA | dB]; DX CTAs form d_xn from the
  published blocks and run the LayerNorm backward) ported to bf16 with the tbwd.cu contract: `src/tbwdx.cu`, `FusedBwdX` /
  `FusedTrain(..., x=True)` in `bwd_op.py`, `bench_bwd.py --x`, `spanx.py`, `energyx.py`. Default stays v8 + v9.
- Layout: DW keeps v9's single h / [dA | dB] buffer (the 2 bf16 input stages fill shared memory); DX runs 16 KB half-chunks
  (dA_j with Wa_j, dB_j with Wb_j; rings 3 + 3) next to its two 64 KB dy | x stages.

## Accuracy
vs the contract (bench_bwd.py): dx 1.6e-4, dWa / dWb / dWs 4.2-4.3e-4, dgamma / dbeta 1.4-1.6e-4; vs fp32 identical to v9
(0.31-0.41 %). Finite, bit-reproducible.

Energy is unchanged: the bf16 exchange moves 302 MB each way (twice the e4m3 record's), and that traffic costs about what
dropping the DX gate, the DX recompute (6·M·D·H of bf16 MMA) and the Ws stream saves. DW slice-tiles take 2.4 µs (v9 1.7 µs):
the next gate waits for the TMA store to finish reading the single [dA | dB] buffer.
Rejected variant `-DPUB_DIRECT` (gate threads store their rows to global memory, per-warp release flags): DW 311 µs at R = 12.
