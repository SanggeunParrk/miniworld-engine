# transition_fused_sm100 — round v21: first ncu profile of the bf16 path (v8 forward + v9 backward)

- Date: 2026-09-26. ncu works on the B200 box through `gcsudo` (root; see memory note b200-ncu-via-gcsudo). Report:
  `profiles/v21/step_v9.ncu-rep` (`prof_step.py`, `--set full`, one training step after warm-up; ncu locks the SM clock at
  ~0.94 GHz, so durations are inflated and only ratios matter). Helpers: `ncu_top.py` (stall lines), `ncu_conf.py` (bank conflicts).

## What ncu says (v9 backward, L384, R = 9)
| | |
|---|---:|
| tensor pipe active | 39 % |
| MMA operand reads from shared memory (tc wavefronts) | 45 % of peak |
| issue slots busy | 40 % |
| MUFU (xu) pipe | 28 % |
| DRAM read / write | 115 / 24 MB per call |
| largest stall | long scoreboard on the mbarrier try_wait loops (roles waiting on each other) |
| local-memory spill requests | 392 k (the DX LayerNorm-backward epilogue) |
| excess shared wavefronts on LDS / STS | none (the 4-way on LDS.128 is the 512-B request itself) |

No pipe or memory level is saturated at the fixed clock: the kernel is bound by the role pipeline (gate → MMA → gate chains, as the
clock64 traces showed), and at real clocks by the 1000 W cap. The forward shows the same picture (SM throughput 55 %, tc wavefronts 24 %).

## Change adopted
- `tbwd.cu`: the two gates in fp32x2 (`gate_pair16`: FMUL2 / FFMA2 with the scalar form's contraction, kit sigmoid per unit) —
  outputs bit-identical to v9 (`cmp_bits.py`), backward 240.5 vs 242.3 / 243.9 µs sustained, step 317 vs 320 µs (alternating runs,
  `ab_bwd.py`). `-DGATE1` restores the scalar gate.

## Standing
bf16 path: training step ~65-66 % SoL sustained. The profile shows no single resource to relieve; the remaining levers are the ones
already measured (energy-bound at real clocks, the bf16 exchange break-even in v20).
