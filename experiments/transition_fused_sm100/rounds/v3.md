# transition_fused_sm100 — round v3: backward roles (trace-driven)

- Date: 2026-09-25
- Target kernel: `transition_bwd_sm100`
- Baseline: v2 (`72a611b8`), backward 264.8 µs at L384

## 1. Environment / commands
As v2. New: `OUT=tbwd_trace ./build.sh tbwd -DTRACE && python trace_bwd.py --repl R` (clock64 stamps for DW CTA 0 and DX CTA 0),
`l2_bench.cu` (L2 → smem TMA throughput).

## 2. Pre-change profile (v2 backward, `trace_bwd.py`)
- DX: 3338 clk per chunk vs 1408 of tensor work. The single gate warpgroup was busy 2143 clk per chunk; the dh+[a|b] issuer waited
  1432 clk per chunk for its weight slot (the 48 KB slot is released only by d_xn(c-2)). The LayerNorm-backward epilogue took
  ~11-12 k clk per tile.
- DW: 4234 clk per tile vs 1792 of tensor work: 2174 clk waiting for the input tile, a 2484-clk single-warpgroup gate in the chain.

## 3. Hardware facts measured this round
- L2 → smem TMA: **~80 B/clk per SM** (≈ 23 TB/s over 148 SMs); a 32 KB tile takes 411 clk even with a 2-deep ring
  (`profiles/v3/l2_bench.txt`). The forward's 48 KB of weights per chunk is therefore 600 clk of one SM's L2 bandwidth against 768
  clk of tensor work — close to binding once everything else is fixed.
- setmaxnreg and ptxas: an `if (warp < 4) dec else inc` **before** the role dispatch merges the two limits and ptxas compiles all
  later code at the lower one (the whole backward came out at 56 registers, 4.6 KB of spills, 987 µs). The increase has to be issued
  inside each math role's own branch (as the forward already did).

## 4. Changes
1. DX gate: two warpgroups in ping-pong over the two `[a|b]` buffers (512 threads, WG0 at 56 registers, math WGs at 152).
2. DW gate: split by columns over two warpgroups (hidden units 0-31 / 32-63 of the slice); each reads only its 96 TMEM columns and
   releases the accumulators immediately (`gate_read` count 8), so the next tile's dh + `[a|b]` starts ~200 clk into the gate.
3. DX weights in two rings: Ws_j (released by dh_j, early) and `[Wa_j; Wb_j]` (released by d_xn_j).
4. `[dA|dB]` written back half by half in the order dA(0-31) | dB(0-31) | dA(32-63) | dB(32-63): each half lands only on
   columns already read, which removed the gate's 160-register peak; the d_xn product pairs each 8-column A block with the matching
   16-row block of the packed weight tile (same sum, K order permuted).
5. Register-lean LayerNorm-backward epilogue: gamma through volatile `ld.shared.v2` (plain loads were hoisted into 128 registers),
   x streamed 8 columns at a time, one reusable reduce-scatter work array that swaps halves in place instead of building
   send/keep temporaries.

Tried and reverted (documented in the trace history): a 3-slot `[Wa;Wb]` ring paid for by single-buffering xn and reading x from
global memory in the epilogue — the weight wait vanished (1362 → 164 clk) but per-thread-row 16-byte global loads touch 32 cache
lines per warp instruction and pass 1 of the epilogue went to ~20 k clk per tile (333 µs overall).

## 5. Validation
dx 1.6e-4, dWa / dWb / dWs 4.2-4.4e-4, dgamma / dbeta 1.4-1.6e-4 vs the contract (L384); vs fp32 autograd dx 3.08e-3 (contract
3.10e-3). Bit-reproducible. L768 likewise.

## 7. Next ideas
1. DW input chain (1569 clk/tile waiting for the tile two ahead) and the DX `[Wa;Wb]` slot cycle are both load-latency chains
   bounded by smem capacity (two buffers). Options: TMA multicast of the shared tile across the 8 DW slices of a replica / of the
   weight chunk across DX CTAs (cluster launch) — fewer L2 requests; or freeing smem so a third buffer fits.
2. Forward: polynomial ex2 for part of the SwiGLU, output-accumulator double buffer.
