# transition_fused_sm100 — round v4: pair clusters and the DX gate split

- Date: 2026-09-25
- Target kernel: `transition_bwd_sm100`
- Baseline: v3 (`ba2477a9`), backward 254.2 µs at L384

## 1. Environment / commands
As v3; the backward is now launched with a 2-CTA cluster attribute (`drv.Kernel(..., cluster=2)`). New probes: `mc_bench.cu`
(TMA multicast vs unicast), `occ.py` (`cuOccupancyMaxActiveClusters`).

## 2. Pre-change profile (v3)
DW 3583 clk/tile with 1569 clk waiting for the input tile two ahead; DX ~3400 clk/chunk with ~1360 clk waiting for the `[Wa;Wb]`
slot and the gate warpgroups each taking ~930 clk per chunk in the slot's dependency chain.

## 3. Measurements that shaped the round
- Multicast: a burst of 6 × 32 KB per SM arrives in 3681 clk unicast vs 2333 clk when each CTA of a pair requests half and
  multicasts (53 → 84 B/clk/SM received): the per-SM L2 path is partly request-limited, and multicast also halves L2 requests.
- Cluster residency (`profiles/v4/occupancy.txt`): 1 CTA/SM at this shared-memory size allows 74 two-CTA clusters (all 148 SMs)
  but only 33 four-CTA (132 SMs) and 15 eight-CTA clusters (120). The kernel is persistent and needs every CTA resident, so a
  4-CTA cluster made the backward 426 µs (a second wave); the cluster size is 2.

## 4. Changes
1. DW: the two slices of a cluster share each (dy, xn) input tile: each requests 4 of its 8 boxes and multicasts; the slot is
   released by a multicast `tcgen05.commit` from both slices (`in_empty` count 2).
2. DX: the two CTAs of a cluster share every weight chunk (each requests half of Ws_j and one K-block of `[Wa_j; Wb_j]`, multicast;
   both slots are released by multicast commits from both). Both CTAs must walk the same chunk sequence, so a CTA one tile short
   repeats its last tile as a dummy with stores and dgamma / dbeta accumulation disabled. (With L a multiple of 16 the tile count is
   even and pairs never differ; the dummy path exists for correctness.)
3. DX gate: the two warpgroups now split every chunk by columns (hidden units 0-31 / 32-63) instead of taking alternate chunks —
   same throughput, half the latency in the slot chain.
Items 1-2 alone measured neutral (250.7 / 253.0 µs): the waits are chain latency, not transfer time. Item 3 is the gain.

## 5. Validation
Unchanged: dx 1.6e-4, dW* 4.2-4.4e-4, dgamma / dbeta 1.4-1.6e-4 vs the contract (L384 and L768), bit-reproducible.

## 7. Next ideas
1. DX: the `[Wa;Wb]` slot chain (ab(c) → gate(c) → d_xn(c) → refill → ab(c+2)) still costs ~1000 clk of waiting per chunk; a third
   slot needs 32 KB that the current layout does not have.
2. DX epilogue (LayerNorm backward) is ~20 k clk per tile on the first tile and ~12 k later; the forward is next for the SwiGLU work.
