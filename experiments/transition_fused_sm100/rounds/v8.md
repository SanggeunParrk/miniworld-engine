# transition_fused_sm100 — round v8: 2-CTA (cta_group::2) forward

- Date: 2026-09-25
- Target kernel: new `transition_fwd2_sm100` (`src/tfwd2.cu`); `transition_fwd_sm100` (v6) kept for comparison
- Baseline: v6/v7 forward

## 1. Hypothesis (from v7's energy accounting)
The forward is power-bound; cuBLAS's 256-wide 2-SM tiles read fewer operand bytes per FLOP than our 128-wide 1-SM tiles. With
cta_group::2 the expand's `[Wa_j; Wb_j]` (N = 128) splits cleanly by N (leader: Wa_j rows, peer: Wb_j rows) and so does the squeeze's
Ws_j (leader: d 0..63, peer: d 64..127): each SM streams and reads half of the weights (16 + 8 KB per chunk instead of 48 KB) and one
MMA instruction covers both SMs.

## 2. Implementation
The two CTAs of a cluster run their own 128-row tiles in lockstep; the leader issues M = 256 SS expands and TS squeezes
(`umma_ss2` / `umma_ts2`); accumulators, SwiGLU, LayerNorm and epilogue stay per CTA with the same TMEM columns. Weight TMAs of both
CTAs complete on the leader's barriers (`cp.async.bulk.tensor...cta_group::2`, peer bit cleared); the leader's commits arrive on both
CTAs' barriers (`tcgen05.commit.cta_group::2...multicast::cluster`); SwiGLU / LayerNorm / epilogue completions are counted on the
leader's barriers by remote arrives. Weight rings are 4 deep (half-size slots). TMEM allocation `cta_group::2` in both CTAs.
2-SM MMA throughput checked in isolation (`profiles/v8/mma2_bench.txt`): M256 N128/N256 SS and TS all at 8187-8190 FLOP/clk/SM.

## 3. What mattered: remote-arrive semantics
First version: 85.6 µs vs 57.2 (v6). The trace (`trace_fwd2.py`) showed each SwiGLU chunk taking ~2900 clk instead of ~1800: the
remote `mbarrier.arrive.release.cluster` after every chunk implies a cluster-scope release fence. The TMEM handoffs (`ab_empty`,
`h_full`, `out_empty`) are already ordered by `tcgen05.fence::before_thread_sync`, so they now use
`mbarrier.arrive.relaxed.cluster`; only the LayerNorm's `xn_full` (generic shared-memory writes read by the peer's async proxy) keeps
release semantics. With that: 58.4 µs, parity with v6 in the short benchmark, ahead when sustained.

## 4. Validation
L128 / L384 / L768: out vs contract 8.9e-5 / 8.6e-5 / 8.8e-5, mismatch fraction and xn / rstd / c1 identical to v6, bit-reproducible.

## 5. Performance
Short benchmark (20 × 5 graph replay): L384 inference 58.4 µs (v6 57.2), training build 61.7 (61.4); L768 training build
**221.4 µs (v6 228.2)**, inference 250 (noisy, 233-256 for v6).
Sustained 3 s, NVML energy (`energy.py --fwd`):

| | v6 1-CTA | **v8 2-CTA** |
|---|---:|---:|
| L384 inference | 64.0 µs, 1.081 pJ/FLOP | **63.3 µs, 1.077** |
| L384 training build | 70.9 µs, 1.204 | **69.3 µs, 1.176** |
| L768 inference | 254.6 µs, 1.093 | **250.1 µs, 1.093** |
| L768 training build | 268.1 µs, 1.138 | **259.4 µs, 1.101** |

A small, consistent gain (1-3 %): halving the weight bytes per SM is real but the energy is dominated by the SwiGLU, the TMEM round
trips, LayerNorm and the tensor work itself. The 2-CTA forward becomes the default in `bench_all.py`.
