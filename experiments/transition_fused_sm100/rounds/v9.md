# transition_fused_sm100 — round v9: DW input chain (xn and dy travel separately)

- Date: 2026-09-25
- Target kernel: `transition_bwd_sm100`
- Baseline: v4 backward (237.5 µs L384 at R = 10; 240 in later sessions), unchanged through v8

## 1. Profile (`trace_bwd.py`, with a new stamp on the DW input producer)
DW per tile 3595 clk; tensor work 1792. The chain was fully serial across tiles:
`dh+[a|b] (i) → gate (i) → wgrad (i) → release the (dy, xn) buffer → load tile i+2 (~1430 clk) → dh+[a|b] (i+2)`.
A gate-math ablation (`-DABL_DW_NOMATH`) cut the gate from 1548 to 1174 clk but the tile only to 3257 — the gate is not the long
pole; the 64 KB reload is.

## 2. Change
The DW input tile is two independent streams with their own full / empty barriers: xn (read by `[a|b]` and by dWab) and dy (read by
dh and by dWs). The producer loads xn first; warp 1 issues `[a|b]` as soon as xn lands and dh when dy lands; warp 2 releases xn right
after the dWab product and dy after dWs. Each half is 32 KB, shared by the slice pair (multicast) as before.
Tried on top and reverted: splitting the gate-output release (dA / dB freed by dWab, h by dWs, h held in registers) — neutral.

## 3. Result
DW per tile 3595 → **2983 clk** (`profiles/v9/trace_bwd.txt`); the best replica count moves to R = 9 (72 DW + 76 DX CTAs):

| | v4 (R 10) | **v9 (R 9)** |
|---|---:|---:|
| backward L384 | 240 µs | **228.1 µs** |
| training step L384 (v6 forward) | 312 µs | **291.5 µs** |
| backward L768 | 929-944 µs | **894.3 µs** |
| training step L768 | 1199-1222 µs | **1152.3 µs** |

Validation: dx 1.6e-4, dW* 4.2-6.8e-4, dgamma / dbeta 1.4-1.7e-4 vs the contract at L128 / 384 / 768; bit-reproducible.
Backward SoL (1.58 PF): 134.6 / 228.1 = 59 %. The DX role (3233 clk per chunk) is now the one to shorten.

## 4. Also measured (not adopted): x in TMEM + third `[Wa;Wb]` slot, on top of v9
Patch: `records/experiments/bwd_x_in_tmem_3slot.patch`. Best 243 µs (R = 8) vs 228-233. With the finer trace: the weight loads are
now far ahead (a slot is refilled ~1800-2200 clk before it is needed), but the DX chunk stays at ~3200 clk because d_xn(c) takes
~1180 clk from the gate's completion to its own completion (512 of tensor work) while warp 1's dh / `[a|b]` of chunk c+1 are
issued late and contend with it; holding dh behind the `[a|b]` buffer release did not change it. TS with an MN-major B runs at
full rate in isolation (`profiles/v9/mma_mn_bench.txt`: 8189 FLOP/clk), so the loss is in the pipeline, not the instruction.
