## 1. D = 64 forward (`tfwd_d64.cu`)

tfwd2.cu's 2-CTA schedule with the weights RESIDENT: this CTA's half of all four 64-unit chunks is 48 KB (Wa_j or Wb_j 4 x 8 KB,
Ws rows 32 crank .. +31 4 x 4 KB), loaded once. Expand M256 N128 K64, squeeze M256 N64 (32 rows of Ws per CTA) K64. TMEM 448 columns.
115.7 KB shared memory, 128 registers, no spills.

Correct at 1 / 3 / 15 / 128 / 1152 / 4608 tiles: out vs contract 6e-5 (0.06 % of elements one bf16 ulp apart), vs fp32 2.27e-3 =
the contract's own; xn / rstd / c1 at 1e-5 / 4e-8; bit-reproducible.

| sigmoid (bench_w.py, CUDA graph, µs) | L384 inference | L768 inference | out vs contract |
|---|---:|---:|---|
| **kit (ex2 + rcp on MUFU), default** | **31.5** | **115.4** | 6.5e-5 |
| `-DSIG_NR` reciprocal by Newton on the FMA pipe | 36.8 | 134.1 | same |
| `-DSIG_POLY` exponential by polynomial | 40.1 | 145.6 | same |
| `-DSIG_MIX` half the reciprocals by Newton | 33.6 | 121.7 | same |
| `-DSIG_TANH` 0.5 tanh(a / 2) + 0.5 (relaxed) | 28.7 | 107.3 | 1.8e-4 (vs fp32 unchanged) |

At D = 64 the SwiGLU's MUFU work per tile (~4.1 k clk) exceeds the tensor work (~1.8 k clk), but moving MUFU work to the FMA pipe is
slower, as at D = 128 (v5, v7): the SwiGLU warps are issue-bound. Kit stays the default; tanh is recorded as an option.

## 2. D = 64 backward (`tbwd_d64.cu`)

tbwd.cu's two roles. DW CTAs: 4 hidden slices x R replicas (pairs of slices multicast each tile's xn / dy); dWs_s = dy^T h has M = D = 64,
run as M = 128 with the MN-major A descriptor's LBO = 0 (the second 64-row block aliases the first; rows 64..127 duplicate and are
dropped). DX CTAs keep ALL weights resident (96 KB, loaded once), so no weight ring and no pair lockstep. LN backward over 64 columns
(fp32x2, two reduce-scatter groups). 164.9 KB shared memory, 128 registers, no spills.

Correct at 1 (fewer tiles than replicas) / 3 / 15 / 128 / 1152 tiles: dx 1e-4, dW 3e-4, dgamma / dbeta 1e-4 vs the contract; vs fp32
every gradient equals the contract's own error (3.1-4.4e-3); bit-reproducible.

## 3. D = 256 forward (`tfwd_d256.cu`)

Resources are the constraint at this width: the output accumulator is 256 TMEM columns and the two [a|b] buffers 2 x 128, so h_j is
written IN PLACE over the first 32 columns of its own [a|b] buffer and expand(j + 2) waits for squeeze(j); shared memory holds one xn
buffer and one x buffer (64 KB each) plus a 2-stage weight ring (48 KB per stage and CTA) = 226.5 KB. The next tile's x is loaded into
the xn buffer as soon as the current tile's last expand is done and normalised in place; the x buffer holds the tile's own x for the
residual and the output staging (x is read twice, the second time mostly from L2).

First build had the LayerNorm loop over 16 of the 32 16-byte column groups (mean over 128 of 256 columns); fixed.

Correct at 1 / 3 / 15 / 128 / 1152 / 4608 tiles: out vs contract 1.3e-4 (0.3 % one-ulp mismatches), vs fp32 2.2e-3 = the contract's;
bit-reproducible.

| D = 256 (bench_w.py, µs) | L128 | L384 | L768 |
|---|---:|---:|---:|
| torch.compile (same script) | 58.8 | 433.6 | 1881.6 |
| **fused, inference** | **29.9** | **191.5** | **820.4** |
| fused, training build (saves xn) | 29.8 | 216.5 | 877.8 |

The forward's tensor work is 232 GFLOP at L384: 178 µs at the 1.30 PFLOP/s sustained cuBLAS rate of this card.

## 4. Next

- D = 256 backward: the D128 two-role design does not fit (a DW slice needs dy + xn tiles of 128 KB per stage plus 96 KB of weights, and
  576 TMEM columns); a split design (gate kernel writing h / dA / dB, dW GEMMs, d_xn + LayerNorm backward) is the H100 answer.
- D = 384 / 512: the output accumulator alone is 384 / 512 TMEM columns.
