# transition_fused_sm100 — widths round w2: the split path for D = 256 / 384 / 512 (the H100 wide structure, developed for B200)

- Date: 2026-09-29. The user chose the H100 wide structure for D >= 256. n = 4, bf16, B200 GPU 7, nvcc 13.1.
- New kernels: `tgate_w.cu` (backward gate), `tswiglu_w.cu` (forward expand + SwiGLU, D >= 384), `tln_w.cu` (forward LayerNorm, D >= 384),
  `tgemm_nd.cu` (out[M][D] = A B with a fused epilogue: EPI_RESID squeeze + residual, EPI_PLAIN d_xn), `tlnbwd_w.cu` (LayerNorm backward +
  residual). Scripts: `bench_wide_bwd.py` (backward; `--breakdown`, `--old`), `bench_wfwd2.py` (two-kernel forward; `--addmm`).

## 1. Pieces

| path | kernels |
|---|---|
| forward D = 256 | fused `tfwd_d256.cu` (w1 §3) |
| forward D = 384 / 512 | `tln_w` -> `tswiglu_w` (h to HBM) -> `tgemm_nd` EPI_RESID (out = bf16(h Ws^T + x), fp32 accumulation) |
| backward D = 256 / 384 / 512 | `tgate_w` (dh, [a|b] recomputed in fp32, gate -> h, [dA|dB] to HBM) -> dWs = dy^T h, [dWa; dWb] = [dA|dB]^T xn (cuBLAS, fp32 out) -> `tgemm_nd` EPI_PLAIN (d_xn) -> `tlnbwd_w` (+ residual) |

- `tgate_w`: 2-CTA pairs, each CTA its own 128-row tile, per item (tile, 64-unit hidden chunk) dh (N 64) + [a|b] (N 128) with the B operand
  split by N over the pair; A (dy, xn) and B through a 4-stage K-block ring (44 KB per stage); accumulators double-buffered in TMEM; gate on
  two warpgroups (units 0-31 / 32-63) into shared-memory staging, TMA stores. First version deadlocked: `acc_empty` counted 8 arrivals where
  both warpgroups of both CTAs arrive (16); `tswiglu_w` had the same slip.
- `tswiglu_w`: as tgate_w without dh, 128-unit items (N 256 per product, B split Wa / Wb over the pair), TMEM 2 x 256.
- `tgemm_nd`: N = D cut into parts of <= 256 (384 = 256 + 128, 512 = 256 + 256), each CTA half of every part's B rows; TMEM double-buffered
  at D <= 256; epilogue on two warpgroups taking alternate 64-column blocks with a 2-slot x prefetch ring each.
- Why not cuBLAS for the squeeze: `addmm(x, h, Ws^T)` rounds the product to bf16 before adding x (out vs contract 1.7e-3, 18.6 % of elements
  one ulp off; `allow_bf16_reduced_precision_reduction` makes no difference); fp32 accumulation + x in the epilogue matches the contract (2e-4).

## 2. Accuracy

All widths, 1 / 3 / 15 tiles and L128 / L384 / L768: forward out vs contract 1.6-2.4e-4 (vs fp32 = the contract's own 2.2-2.3e-3), xn 1e-5,
h 1e-4; backward h / dA / dB vs contract 3-12e-5, dx 2-4e-4, dW 3-13e-5, dgamma / dbeta 1.5-3.9e-4; vs fp32 every gradient equals the
contract's own error (2.9-3.8e-3); bit-reproducible.

## 4. Why the wide backward does not beat torch.compile

- **Recompute.** The contract recomputes a / b in fp32 inside the gate (the H100 design): 16 M D H of tensor work per backward against the
  12 M D H of a backward that keeps the forward's a / b (what PyTorch / torch.compile do, in bf16). On this power-capped card time follows
  work at D >= 384.
- **Gate kernel efficiency.** 0.74-0.76 PF/s: its A operand (dy, xn) is re-streamed for every 64-unit chunk, ~115 B/clk of SM intake
  against the measured ~60-80 B/clk (a wider chunk does not fit: 128 units = 384 TMEM columns, no double buffer).
- **cuBLAS weight gradients** at 0.85-1.3 PF/s; d_xn through tgemm_nd at 0.85-1.2 PF/s.

## 5. LayerNorm backward register cap (L384, µs; `-DLNB_MINB`)

| D | 1 block/SM hint (103-116 regs) | 4 blocks/SM (64 regs) |
|---|---:|---:|
| 256 | 92.6 | 70.1 |
| 384 | 187-192 | 145.5 (144 B spill) |
| 512 | 139-140 | 159.5 (160 B spill) |

Default: 4 for D = 256 / 384, 2 for 512. D = 384 leaves half the lanes idle on the second 8-column pass (48 chunks per row).
