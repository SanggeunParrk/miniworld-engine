# transition_fused_sm100 — widths round w6: D = 256 d_xn + LayerNorm backward fused (measured, not adopted)

- Date: 2026-09-29. B200 GPU 7, L384, µs. `src/tdxln_w.cu`, `bench_wide_bwd.py --dxln`.

## Design

d_xn = [dA | dB] [Wa; Wb] (K = 2H = 2048) on the tgemm_nd main loop (2-CTA, M 256, N 256 split over the pair, 3-stage ring, TMEM double
buffer) with the LayerNorm backward + residual as the epilogue: warpgroup g takes 64-column blocks g and g + 2, its x / dy blocks resident
for the tile (4 x 16 KB, prefetched a tile ahead), pass 1 = row sums (exchanged between the warpgroups through shared memory) and the
dgamma / dbeta terms (warp reduce-scatter per 32 columns, per-lane accumulation across tiles), pass 2 = dx written over dy and TMA-stored.
d_xn never reaches HBM.

## Result

Correct (1 / 15 / 1152 tiles: dx 2.4-2.8e-4, dgamma / dbeta 1.5-2.6e-4 vs the contract; vs fp32 = the contract's; bit-reproducible), slower:

| build | tdxln | tgemm_nd d_xn + tlnbwd_w |
|---|---:|---:|
| d_xn kept in registers for pass 2 (724 B spill) | 225 | 135 + 54 = 189 |
| d_xn re-read from TMEM in pass 2, one work array (172 B spill) | 244 | 140 + 62 = 202 |

In the GEMM epilogue a lane owns a ROW (the TMEM layout), so the per-column dgamma / dbeta sums cost eight warp reduce-scatters per tile
(the D128 finding, v23); the standalone LayerNorm backward owns columns per lane and sums them in registers for free. On H100 the fused
dxn_lnbwd won (1.12x) because the wgmma fragment layout is not row-per-thread; on B200 it loses.

## D = 256 against its energy floor

Recompute path (fused forward + tgate_w + cuBLAS dW + tgemm_nd d_xn + tlnbwd_w), L384: 22 M D H of tensor work (~0.64 J at ~0.75 pJ/FLOP)
+ ~3 GB of HBM traffic (~0.28 J) = ~0.94 ms at 985 W; measured 1.06 ms. The no-recompute path lands at the same energy (18 M D H + ~4.5 GB).
What is left above the floor is ~12 %; removing the second read of [dA | dB] (d_xn accumulated inside the gate kernel, which fits TMEM at
D = 256 only) would take ~6 %.
