# Hopper cluster DSM B7–B12 prototype

Status: implemented as `front_cluster.cu`, generated by `make_cluster.py`; initial L64 correctness passed. Training shapes, replay, sanitizer and speed qualification remain pending. Production and published selection unchanged.

## Why

The two-CTA implementation independently reads preactivation and d_left/right and computes GLU in dW/dX roles. Cache hints and bounded progress windows brought only small gains. This design computes B7 once and passes its BF16 outputs directly between SM shared memories, avoiding a second read from HBM and duplicated GLU arithmetic. It preserves the forward saves and the B7–B12 arithmetic/rounding contract.

## Actual pipeline

Each eight-CTA cluster has four dW/GLU producer CTAs (H128 each) and four dX/LN consumer CTAs (one64-row tile each). All CTAs have256threads. Each dW CTA retains four32KiB output stages plus64KiB preactivation/upstream/x_n input storage. Each dX CTA retains128KiB received GLU outputs plus64KiB weights/gate staging. Total dynamic shared192KiB/CTA. Current cubin uses254registers, no stack/spills.

Producer TMA-loads input, computes mask+GLU, fences its writes, and pushes32KiB via `cp.async.bulk.shared::cluster.shared::cta` to the appropriate consumer. dW WGMMA reads the same output locally. The consumer waits for four pushes through a131072-byte transaction barrier and performs gate dgrad, front dgrad in Lg→Lp→Rg→Rp order, LN backward and residual. It arms the next transaction barrier before acknowledging reuse to all four producer slots. No global d_concat or dx_n tensor is introduced. Only small parameter partials use global storage.

Cluster barriers protect shared-memory lifetime. A fully resident cooperative grid performs final dW/LN reductions inside the same launch. On this node02 device, `cuOccupancyMaxActiveClusters` reports15 eight-CTA clusters at the requested geometry;120CTAs are legal. A128-CTA trial was explicitly rejected by the driver as too large and was not run. `ClusterPlan` queries occupancy before execution.

The two dW accumulation segments per cluster maintain the established FP32 accuracy requirement. One workspace allows only one concurrent invocation. Exact saved inputs and weights are read afresh each invocation.

Sources: Anthropic native v5 primitives; NVIDIA PTX documentation for cluster shared memory copies and mbarriers; CUDA driver occupancy/cooperative launch APIs. Remote bulk copies are push operations (local CTA shared source, remote cluster shared destination), not remote-to-local pull operations.
