# triangle_attention — v5: strided dq/dk/dv writes (A) + strided grad_output read (C) — 1.67× vs baseline

**GPU:** H100 (sm90).  **Shape:** d_pair=512, L=384, n_head=4 → HEAD_DIM=128, B=1, bf16.
**Base:** v4 (stride-native reads + contiguous bias, 7.32 ms/layer).  **Baseline:** 10.98 ms.

## Verdict

**SHIP.** Two symmetric changes that remove the remaining backward layout copies:
- **A:** write dq/dk/dv directly into the **projection layout** `[B,L,L2,H*D]` (strided
  `[B,H,L,L2,D]` views) so the module's rearrange-backward is a FREE view — kills the
  ~0.6 ms grad-transpose copy.
- **C:** consume `grad_output` **strided** (no `.contiguous()`) in preprocess + dkdv + dq —
  kills the ~0.33 ms grad_output copy.

Correct (cos 0.99999 / 0.99998) and **step 7.32 → 6.58 ms (1.11× vs v4, 1.50× cumulative…
actually 1.67× vs the 10.98 ms baseline)**.

## A — dq/dk/dv in projection layout (strided writes)

The bwd kernels previously wrote dq/dk/dv to a contiguous merged `[B,HL,L,D]`; autograd then
transposed them back to `[B,L,L2,H*D]` for the projection weight/input grads (a 0.6 ms
`[B,L,L2,H,D]` copy). Fix: allocate dq/dk/dv as `[B,L,L2,H*D]` and hand the kernels strided
`[B,H,L,L2,D]` views (same q-group strides as q/k/v); the kernels write strided (head_dim
stride-1 → coalesced, free like the reads). Returned as `[B,H,L,L2,D]` views whose storage IS
`[B,L,L2,H*D]`, so the module's `rearrange`-backward is a free view — no transpose copy.

## C — strided grad_output

`grad_output` arrives as a `[B,H,L,L2,D]` strided view of the upstream `[B,L,L2,H*D]` grad;
`.contiguous()` + the `(H L)` merge forced a 0.33 ms copy. Fix: pass it strided (5D) with its
own strides; `_attn_bwd_preprocess` rewritten to read `do` via explicit strides (out stays
contiguous merged); dkdv/dq read `do` via the strided `ds_*` group. No copy.

## Validation

`ta_verify.py` D=512 L=384 NH=4 bf16 vs pytorch fp32 ref: fwd cos 0.99999, grad_pair cos
0.99998, PASS. Precision unchanged.

## Remaining (mostly not removable)

- vectorized_elementwise adds (~4.4 %, ~0.3 ms) = pair-grad accumulation (pair feeds 5
  projections) — inherent autograd, not a copy.
- a small fwd `[B,L,L2,H,D]` copy (~0.2 ms, "B") in the gate/value path — source needs a
  stack-trace to pin; low priority.
- dbias per-row `[B,HL,L,L]` materialize + `reduce(sum)` — could fuse the row-reduction.
