## What was built
`sm100_gate_gemm_collective.py::GatedPersistentGemmKernel` subclasses the vendored
CUTLASS `PersistentDenseGemmKernel` (`_blackwell_dense_gemm.py`) and inherits ALL its tuned
machinery via `super()._setup_attributes()`:
- warp specialization (tma warp / mma warp / 4 epilogue warps)
- multi-stage `PipelineTmaUmma` TMA→tcgen05 load↔MMA pipeline (num_ab_stage from smem heuristic)
- acc double-buffering (`PipelineUmmaAsync`, num_acc_stage=2) → epilogue(i) overlaps MMA(i+1)
- `StaticPersistentTileScheduler` over the M=L² tiles (fixes the naive 8192-tiny-CTA tail wave)
- tuned k-tiling, epilogue tile, cluster layout, `PipelineTmaStore` C write
Overrides:
- `_setup_attributes`: recompute AB stages for ab_bytes = A + 2·B (dual B shares one A load);
  dual TMEM accumulator (proj+gate = 2× cols, ≤512 TMEM budget).
- `__call__`: build TMA atoms for A, Bp, Bg, C (M-major); permute inputs (L,X,Y)→(X,Y,L) MNKL.
- `kernel`: TMA warp loads A+Bp+Bg into one AB buffer/tile; MMA warp runs TWO tcgen05 MMAs
  (proj, gate) into two TMEM accumulators; one acc commit/tile.
- `_gated_epilogue`: custom dual-accumulator TMA-store epilogue = t2r-load proj & gate →
  sigmoid(gate)*proj → bf16 → smem → TMA store, M-major zero-copy into [B,D,L,L].
config @ (128,128) tile, cluster(1,1), CtaGroup.ONE, use_tma_store=True.

Cluster (2-CTA) not used: 1-CTA already beats target; 2-CTA left as next idea.

## Key bug found & fixed: the sigmoid, not the GEMM
Correctness was perfect from the first compile (cos 0.999999) but the kernel was 0.452 ms/side
(worse than naive 0.319). nsys bisection (single side, M=1M) pinned the cost precisely:

| variant (single side)                                   | ms/side |
|---------------------------------------------------------|---------|
| plain collective single GEMM (ref)                      | 0.093   |
| proj-only (1 MMA, 1 store)                              | 0.0946  |
| both MMAs, store proj only (gate MMA is ~free)          | 0.0875  |
| both MMAs + both t2r loads, ov = p*g (no sigmoid)      | 0.089   |
| sigmoid via exp2 (no division): ov=p*exp2(g)           | 0.109   |
| **sigmoid via 1/(1+exp(-g)) — IEEE division**          | **0.452** |
| sigmoid via 1/(1+exp2(...)) — still IEEE division      | 0.426   |
| sigmoid via 0.5+0.5*tanh(0.5g)                          | 0.207   |
| **sigmoid via rsqrt reciprocal (1/d = rsqrt(d)²) [chosen]** | **0.149** |

The 2nd MMA is essentially free (tensor core ~5% SOL). The entire blow-up was the epilogue's
IEEE `1.0/(1+e)` division (~0.33 ms), which was NOT hidden behind the C-write bandwidth. Fix:
division-free sigmoid using the hardware MUFU reciprocal via `1/d == rsqrt(d)²` (d = 1+exp2(-g·log2e) > 0).
Precision preserved: rsqrt approx (~22-bit) ≫ bf16 output; relmean identical to the exact-exp path.
(Side-experiment toggles `MW_SIG`/`MW_PROJONLY`/`MW_NOEXP` retained, all default to the fast path.)
