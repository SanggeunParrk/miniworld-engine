# triangle_multiplication_tm1_cute — round v16 (software-pipelined GLU epilogue: hide t2r latency behind the async C-store)

- Date: 2026-07-05
- Branch: `perf/tm1-cutlass-collective` (v16 off v15 = 7e8c415, off origin/main 2a10ee6)
- GPU: NVIDIA B200 sm_100; nvidia-cutlass-dsl 4.4.2. nsys + ncu (via gcsudo/tmux).
- Target: tm1 gated GEMM `out = sigmoid(A@Bg.T)*(A@Bp.T)`, M-major -> [B,D,L,L].
  M=L^2, N=K=128. bf16 in / fp32 acc / bf16 out. **Algorithm & precision unchanged** (same rsqrt division-free sigmoid).

## Starting point (v15 = confirmed win)
v15 isolated tm1 GEMM 0.150 ms/side (nsys); no-sigmoid floor 0.089 ms/side => ~0.061 ms/side of
sigmoid was EXPOSED. Goal this round: overlap the sigmoid math with the async TMA C-store to push
0.150 toward 0.089.

## Profiling first (v15 baseline, this box)
Isolated per-side (nsys, iso2.py, M=1048576, 22 instances):

| variant (single side, nsys)                     | ns/side |
|-------------------------------------------------|---------|
| no sigmoid (ov=p*g, both MMA+t2r)               | 88,848  |
| exp2 only (ov=p*exp2(g), 1 MUFU)                | 109,203 |
| **rsqrt sigmoid [v15 default]**                 | **150,475** |

So exp2 adds +0.020, the reciprocal (rsqrt+square, a *dependent* chain on exp2) adds +0.041.

ncu on the v15 kernel (single side, gcsudo):
- Hottest pipe = **XU (MUFU/transcendental) 45.5%** of peak; FMA 17.3%, LSU 2.1%.
- **`math_pipe_throttle` ~= 0.01** => XU is NOT the wall (not throughput-saturated).
- **Dominant stall = `long_scoreboard` 1.60** (+ short_scoreboard 0.49, wait 0.98).
- Occupancy `warps_active` 9.3% (~2 CTA/SM, smem/TMEM-capped — matches prior analysis).

**Theory:** the epilogue is **latency-bound on the tcgen05 t2r (TMEM->reg) loads that feed the
sigmoid**, not MUFU-throughput-bound. Each subtile's `t2r -> sigmoid -> r2s -> barrier -> store` is a
dependent chain and the next subtile's t2r is not issued until the current store's barriers pass, so
the t2r latency is exposed on the critical path. (subtile_cnt=4, epi_tile (128,32), num_c_stage=4,
num_acc_stage=2 — the C-store side is already deeply pipelined; the compute side was not.)

## The change (one cohesive change)
`_gated_epilogue`: **software-pipeline the subtile loop with double-buffered register fragments.**
- `for subtile_idx in cutlass.range_constexpr(subtile_cnt)` (python-unrolled => compile-time
  double-buffer index).
- Two register fragment sets `rAccP[0/1]`, `rAccG[0/1]` (`cute.make_fragment_like`).
- Prologue issues subtile 0's t2r; each iteration issues subtile **k+1**'s t2r (proj+gate) *before*
  computing subtile k's sigmoid, so the k+1 TMEM->reg latency overlaps k's sigmoid MUFU math + the
  async TMA C-store.
- Store path, barriers, sigmoid math, and all side-experiment toggles unchanged.
- Cost: +1 register fragment set (32 fp32/thread). Occupancy is smem/TMEM-capped, not
  register-capped, so this costs no CTA (confirmed: warps_active flat).

+32 / -7 lines, kernel file only. No math/precision change.

## Next ideas
- Deepen the compute pipeline to 3 register stages (prefetch k+2): long_scoreboard is still 1.28,
  wait-stall now 1.13; more depth may hide the residual t2r/barrier latency (register budget allows).
- Single approximate MUFU reciprocal (rcp) instead of rsqrt(d)^2 (saves 1 mul; same MUFU count) —
  math-impl only, opt-in, must keep relmean within ~2x bf16 floor.
- Lighter epilogue barrier structure (2 named-barrier syncs per subtile; wait-stall is now the
  next-largest after long_scoreboard).
