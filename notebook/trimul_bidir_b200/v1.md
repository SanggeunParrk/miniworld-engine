# trimul_bidir_b200 v1 — bidirectional trimul on the current sm100 kernels (INFERENCE)

## Goal
Build the repo's FUSED bidirectional trimul (outgoing + incoming, shared 2h back-half)
out of the CURRENT cuequiv-free sm100 kernels, and benchmark honestly vs cuequiv on B200.
Prior cuequiv-free wins were single-direction only; the pre-existing cute bidir path reused
cuequiv's `layer_norm_transpose` (NOT cuequiv-free) + torch matmuls for the back.

## Environment
- B200 (sm_100a), GPU 6. Branch `perf/trimul-bidir-b200`, worktree `~/psk/mw-bidir`
  (off `perf/trimul-train-b200` @ f8f986c). B=1, d_pair=d_hidden=128, bf16.

## Composition (all current sm100 kernels; NO cuequiv, NO quack LN)
`kernels/trimul_inproj/cute/bidirectional_sm100.py` + `_forward_cute_free` in the module:
    LN_in (triton triton_layernorm)
      -> tm1 front `tm1_cute_forward(out_layout=bdll_sm100)` x2 (GatedPersistentGemmKernel tcgen05):
             outgoing half = to_*.weight[:h]  -> left_o,right_o [B,h,L,L]
             incoming half = to_*.weight[h:]  -> left_i,right_i [B,h,L,L]
      -> outgoing einsum bdik,bdjk->bdij  +  incoming einsum bdki,bdkj->bdij  (cuBLAS)
      -> cat over channels -> tri [B, 2h, L, L]
      -> back_split_sm100: sm100 LayerNormLinear over 2h (triton M-major LN + tm1 tcgen05
         proj GEMM) + triton gate_elem.
Since d_hidden==d_pair, each per-direction weight slice is square (d,h)=(128,128), which the
bdll_sm100 front accepts unchanged (no kernel edits — only weight slicing + a wider 2h back).
Selected by default on sm_100 via `MINIWORLD_TRIMUL_CUEQUIV_FREE` (=0 -> old cuequiv path).

## Correctness (eager bf16 vs fp32 pytorch reference; non-degenerate random weights + randn)
L=384 : cos 0.999976  relmean 6.93e-3  maxabs 2.28e-2   (bf16-ref floor: cos .999968 relmean 7.9e-3)
L=768 : cos 0.999975  relmean 7.00e-3  maxabs 2.52e-2
L=1024: cos 0.999976  relmean 6.90e-3  maxabs 2.85e-2
cute relmean is BELOW the bf16 reference floor (fp32 LN stats). PASS (cos>=0.9999, relmean<floor).
Graph replay vs eager: cos 1.000000, relmean 0, maxabs 0 at all L (no dropped kernels -> graph
time is honest).

## Honest benchmark — graph time (do_bench, replay-cos=1.0 verified), ms
    L    | cute-bidir | cueq-bidir(2 calls) | speedup | old-cute-bidir(cuequiv-reusing)
    384  |   0.2824   |      0.4178         | 1.479x  | 0.3826 (1.091x)
    768  |   0.9972   |      1.5860         | 1.590x  | 1.2327 (1.265x)
    1024 |   1.8296   |      2.7881         | 1.524x  | 2.2065 (1.264x)
cuequiv bidir = two single-dir cuequiv `triangle_multiplicative_update` calls (outgoing +
incoming) — cuequiv exposes no fused-2h API, so this is the honest way to do bidir with cuequiv.

## nsys cross-check (L=1024, --cuda-graph-trace=node, 100 replays, REPLAY nvtx window)
cute:  wall 1.768 ms/iter, GPU-kernel-SUM 1.755 ms/iter, 21 kernels/iter (none dropped)
       breakdown: 5x cutlass tm1 GEMM 0.651 (4 front + 1 back-proj), _ln_mmajor 0.227,
       2x nvjet einsum 0.397, CatArrayBatchedCopy 0.164, _gate_mul 0.118,
       layer_norm_fwd_fused (LN_in) 0.095, gate GEMM 0.081, 8x elementwise 0.019.
cueq:  wall 2.796 ms/iter, GPU-kernel-SUM 2.787 ms/iter, 15 kernels/iter
       4x fused_sigmoid_gated_dual_gemm 1.355, 4x layer_norm_transpose 0.927, 2x nvjet 0.379.
nsys true speedup L=1024 = 2.787/1.755 = 1.588x (consistent with graph 1.524x).

## Verdict
cute bidir BEATS cuequiv bidir on B200: 1.48-1.59x (graph, cos-verified) / 1.59x (nsys true,
L=1024). The new sm100 kernels also beat the old cuequiv-reusing cute bidir by 1.21-1.36x and
flip the small-L (384) case from 1.09x to 1.48x.
