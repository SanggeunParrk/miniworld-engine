# trimul cuequiv-free B200 — v1 (two-kernel sm100 LayerNormLinear)

## Goal
Make the B200 (sm_100) cute trimul forward CUEQUIV-FREE, mirroring the H100
`trimul_inproj` design. The pre-existing `_forward_cute` on B200 secretly reused
NVIDIA cuequivariance kernels for LN_in/LN_out (`layer_norm_transpose`) and tm2
(`fused_sigmoid_gated_dual_gemm_dual_x`). This round replaces the whole path with
our own kernels — the tm1 tcgen05 collective (already ours), triton LayerNorms,
an sm100 LayerNormLinear, and a triton GateElem — so ZERO cuequiv kernels run.

## Environment
- GPU: NVIDIA B200 (sm_100), CUDA 13.1, `pixi run --frozen`, bf16.
- Base branch `perf/tm1-cutlass-collective` (tm1 GEMM v16). New branch
  `perf/trimul-cuequiv-free-b200`.
- Single direction (outgoing), B=1, D=128, L in {384,768,1024}.
- Weights: non-degenerate (override zero-init on to_out/to_gate/gates,
  N(0,0.05)); randn input. Correctness vs an fp32 PYTORCH reference.

## Design (cuequiv-free composition, single-dir)
```
LN_in  = triton_layernorm (ours)                          [layer_norm_fwd_fused]
front  = tm1 tcgen05 collective, out_layout=bdll_sm100     [GatedPersistentGemmKernel] (ours, already cuequiv-free)
einsum = torch.einsum bdik,bdjk->bdij                      [cuBLAS nvjet]
back   = sm100 LayerNormLinear (two-kernel)  +  GateElem (triton)
```

### sm100 LayerNormLinear (the port; the crux)
The H100 `gemm_layernorm_linear_fused.py` forks quack's `GemmSm90` (WGMMA) and
folds the LN stats into the GEMM epilogue — it does NOT run on Blackwell. Ported
as the explicitly-blessed **two-kernel** milestone (`ln_linear_sm100.py`):

1. LN_out over the K(=d_hidden) channel of the einsum output `tri` [B,K,L,L]:
   a custom Triton kernel `_ln_mmajor_kernel` reads `tri` M-major (channel strided
   by M=L*L, X[m,k] at offset `m + k*M`) — no transpose copy, mirroring the H100
   LNL's M-major A view — and writes a contiguous (M,K) bf16 `LNout`. fp32
   reduction. K is a power of two so BLOCK_K==K (no masked/variance-corrupting
   columns).
2. proj = LNout @ Wp.T on OUR tm1 tcgen05 CUTLASS Blackwell collective
   (`GatedPersistentGemmKernel`) in `proj_only` mode (single effective B; the gate
   MMA + GLU are skipped, the dummy 2nd-B TMA load is negligible as B=(N,K) is
   tiny). fp32 accumulate, bf16 out.

Math = standard LayerNorm-then-Linear (bf16 in / fp32 acc / bf16 out); precision
preserved. `back_split_sm100.py` = LayerNormLinear + `gate_elem_triton`
(`y = proj (.) sigmoid(x_n@Wg)`, gate GEMM = cuBLAS + a triton sigmoid*mul).

### Wiring
`module.py::_forward_cute_free` runs the composition; `_forward_cute` delegates to
it by default on sm_100 (`MINIWORLD_TRIMUL_CUEQUIV_FREE`, default "1" on sm_100,
"0" elsewhere). Set the env to "0" to fall back to the old cuequiv-reusing
`_forward_cute` for comparison. sm_90 and older archs are unchanged. tm1 files
untouched (no v16 regression).

## Validation
- Eager correctness vs fp32 ref: cos 0.99999, relmean 4.71e-3, maxabs <=1.6e-2
  for all L. relmean within ~2x the bf16 floor (~6.7e-3 @ L=1024).
- CUDA-graph replay-cos vs eager = 1.00000 for all L (no kernel dropped; graph
  time valid).

Back-half (our LayerNormLinear + GateElem) = 0.125+0.082+0.202 = 0.409 ms, vs the
cuequiv back-half it replaces (LN_out 0.301 + tm2 0.252 = 0.553 ms).

### cuequiv-free confirmation (nsys kernel summary)
No `layer_norm_transpose`, no `fused_sigmoid_gated_dual_gemm*`, no cuequiv symbol
of any kind. Only: GatedPersistentGemmKernel (ours), nvjet/cuBLAS (einsum + gate
GEMM), and the triton kernels (_ln_mmajor_kernel, layer_norm_fwd_fused,
_gate_mul_kernel). See `v1/nsys_kern_sum.txt`.

## Result
The cuequiv-free B200 path BEATS cuequiv (1.30-1.39x), the current cuequiv-
reusing `_forward_cute` (1.17-1.24x), and dtv1 (1.57-1.64x) across L=384/768/1024,
at equal correctness. Honest, verified (replay-cos-checked + nsys).
