## Approach

Chosen path: per-thread register load from global for gamma/beta, plus WG-local row-param staging for `rstd/c1`.

The direct-register gamma/beta path is viable because each thread normalizes a fixed 8-column slice. The normalization loop uses:

```c++
for (int vec = wg_tid; vec < (WG_M * kK) / 8; vec += 128)
```

With `WG_M=64`, `kK=128`, and `kXVecElems=8`, the `vec += 128` step advances by exactly `1024` elements, so `k0 = (vec * 8) % 128` is invariant for a given `wg_tid`. Each thread therefore needs only `gamma[k0:k0+8]` and `beta[k0:k0+8]`, loaded once from global into local register arrays.

The old CTA-wide LN-param sync also protected `rstd/c1`, because WG0 staged all 128 CTA rows and WG1 read rows `64..127`. v14 changes that staging so each WG writes its own 64 row parameters, then uses the same per-WG named barrier style as v13:

```c++
cutlass::arch::NamedBarrier::arrive_and_wait(kWarpgroupThreads, wg_id + 1);
```

Result: the cross-WG LN-param dependency is removed. Gamma/beta availability needs no sync; `rstd/c1` availability is WG-local.

## Smem Accounting

Gamma/beta shared staging was removed:

- Removed: `2 * K * sizeof(bf16) = 2 * 128 * 2 = 512 B`.
- Row params kept: `2 * kBlockM * sizeof(float) = 2 * 128 * 4 = 1024 B`.
- `kNormParamSmemBytes`: `1536 -> 1024`.
- `kTensorSmemBytes`: `230912 -> 230400`.
- `kPipelineStorageOffsetBytes`: `230912 -> 230400`.
- `kPipelineStorageSmemBytes`: unchanged at `32`.
- `kDynamicSmemBytes`: `230944 -> 230432`.

This remains within the H100 opt-in limit checked by `kDynamicSmemBytes <= 227 * 1024`.

## Hypothesis

Removing the last CTA-wide LN-param sync should reduce `barrier` stall below v13 `0.88` by avoiding cross-WG arrival skew. Expected movement:

- `barrier`: down versus v13 `0.88`.
- `issue_active`: up versus v13 `40.1%`.
- Runtime: small improvement versus v13 `~433 us` if the saved CTA barrier cost exceeds the extra per-thread gamma/beta register loads.
- `wait`: roughly unchanged versus v13 `1.31`, because the dominant WGMMA completion / occupancy floor is untouched.
- Dynamic smem: down by `512 B`, from `230944 B` to `230432 B`.

Expected gain is likely small. v13 is already close to the observed hard floor, and this round does not change WGMMA occupancy, tensor-core issue, bank conflicts, TMA, or the output path.

- cos(cuda,triton) = 1.000000. Perf (M=524288): v14 = **414.9-426.7 us = 1.26-1.31x** of Triton (~540us),
  median ~421us, vs v13 ~433us/1.25x. Duration (M=262144) 274 -> 263us.
- ncu (M=262144): SM throughput 48.96 -> **51.14%**, issue_active 40.1 -> 40.3%. `barrier` 0.88 -> 0.87
  (barely changed), `wait` 1.31 -> 1.34, `long_scoreboard` 0.27 (small, from the global gamma/beta
  register loads). regs 255, spill 0, smem 230944 -> 230432 B.
- Mechanism note: the speedup came NOT from the barrier ratio (unchanged) but from removing the
  gamma/beta smem-staging WORK (fewer prologue instructions + less smem traffic) and the freed sync
  latency. Each thread now loads its fixed 8-column gamma/beta slice from global into registers.
- Verdict: WIN, committed as new best. Remaining dominant stall = `wait 1.34` (wgmma completion) =
  occupancy floor (1 CTA/SM, 8 warps; 2-CTA smem-blocked). barrier 0.87 residual is mostly the
  one-time pipeline-init sync (hard to remove).
