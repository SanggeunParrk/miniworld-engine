# fused_front_gemm (sm100 B200) — v2: σ(gate) store trick (drop preact, −1.16× front)

Follows v1 (which proved the front is memory/store-bound but occupancy-pinned at 1 CTA/SM, and
that the only >2× lever is cutting the `preact` store traffic — 56% of bytes, backward-only).
v2 takes the low-risk slice of that lever.

## Idea (GLU-backward algebra)
The front computes `left = proj⊙σ(gate)` (= the saved output `lr`). The backward needs
`d_proj = d_out⊙σ(gate)` and `d_glogit = d_out⊙proj⊙σ(gate)(1-σ(gate))`. Substituting
`proj⊙σ(gate) = lr`:

    d_proj   = d_out · σ(gate)
    d_glogit = d_out · lr · (1 - σ(gate))

**Neither needs `proj`.** So the forward doesn't need to spill raw `preact[4H]` (gate+proj logits);
it only needs `σ(gate)[2H]` — which the epilogue *already computes* (`= r·r` on the rsqrt path).
Forward store planes: `lr[2H] + preact[4H] = 6H` → `lr[2H] + sg[2H] = 4H` (**−1/3**).

## Implementation (contained to the single-dir sm100 path; bidir/H100 untouched)
- `front_fused_gemm_sm100.py`: `store_sigmoid` flag + `FusedSigGemmKernel(FusedPreactGemmKernel)`
  + `fused_front_gemm_sig(A,Bp,Bg,lr,sg)`. Epilogue stores `lr`(b0) + `sg`(b1) — 2 stores/subtile
  (sstride=2) instead of 3; `sg` carried in the `cpe` slot, `cpo` unused.
- `back_fused.py`: `_dconcat_sig_kernel` + `front_bwd_dW_sig(d_left,d_right,left,right,sg,...)` —
  builds the SAME `dconc[4H,M]=[d_gLlog;d_pL;d_gRlog;d_pR]` from `(lr,sg)` via the formulas above
  (no `σ` recompute, no `proj`). Same dW/W_stack/returns as `front_bwd_dW`. dW stays cuBLAS.
- `front_train_sm100.py`: `trimul_front_sm100_train_sig` → `(left,right,sg)`.
- `v6_training_merged_sm100.py`: wired — saves `sg` (was `preact`), backward calls
  `front_bwd_dW_sig(d_left,d_right,lf,rf,sg,...)`.

## Result (L=1024, D=128, bf16, B200 GPU0)
**Forward kernel, ncu `--set full` base-clock (apples-to-apples, forward-only NVTX PROFILE):**
| | Duration | Compute | Memory | DRAM |
|---|---|---|---|---|
| shipped (preact[4H]) | 623.3 µs | 35.0% | 59.1% | 50.4% |
| **v2 (sig, lr+sg[2H])** | **535.0 µs** | 41.1% | 48.7% | 43.7% |
→ **1.16× (−88 µs)** on the front GEMM; occupancy unchanged (9.34%, still 1 CTA/SM — v1's wall),
DRAM drops (less store traffic), so it shifts toward compute. Matches the store-byte cut (6H→4H).

**Backward:** read volume unchanged (`front_bwd_dW_sig` reads lr[2H]+sg[2H] vs preact[4H], +the
lr already read by the contraction bwd) → ~neutral. Forward is the win.

## Validation (full V6TriMulMergedSm100, fwd+bwd)
- Front-only: `lr` cos 1.000000, `sg` cos 0.999998–1.0 vs fp32 (L=384/768/1024).
- `verify_v12` (grads vs fp32): worst grad cos **0.999980** @ all L (PASS @0.9999). dWLg/dWRg =
  0.999980 (one extra bf16 round from `lr·(1-sg)` vs `proj·sg·(1-sg)`; relmean 6.3e-3 = bf16 floor).
- `graph_train_v12` (CUDA-graph replay vs eager): worst_cos **1.000000**, worst_relmean **0** @ all
  L — no kernel dropped, graph valid.

## End-to-end (honest)
Front fwd −88 µs ≈ ~2% of the ~4 ms training step; below graph-time run-to-run noise (clock
wander ~2×), so no e2e speedup is claimed — the deterministic **1.16× front-kernel** result is the
measured headline. Precision-neutral to the bf16 floor; strictly a store-reduction + algebraic
reconstruction (math identical).
