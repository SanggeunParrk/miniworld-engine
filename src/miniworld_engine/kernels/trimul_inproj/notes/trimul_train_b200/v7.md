# trimul_train_b200 v7 — fuse the GLU-backward elementwise (small win); LN identified as real cost

## Goal
Fold the memory-bound backward elementwise into fused kernels (H100-spirit): the GLU-backward
(dy*gate / dy*proj / gate-derivative) and the dx_n accumulation.

## Change (training_b200.py, gated MINIWORLD_TRAIN_FUSE_GLU, default on)
- `_glu_bwd` Triton kernel: reads dy/gate/proj once, writes d_proj=dy*gate and
  d_glog=dy*proj*gate*(1-gate) in ONE pass (was 5 torch elementwise passes).
- `_add3` Triton kernel: dx_n = dx_n_gate + dxn_L + dxn_R in one pass (was 2 adds).
The back-half GLU has proj and gate from DIFFERENT inputs (out_n vs x_n), so it is NOT the
shared-A pattern the gatebwd tcgen05 epilogue fuses — folding it into the tcgen05 mainloop would
be a deep multi-round bring-up (cf. the m-major RowVecReduce blocker), so it is done as a single
fused prologue kernel instead (net 5->1 and 2->1 passes).

## Correctness (train_recon, grads vs fp32) — PASS, unchanged
L=1024 all tensors cos >= 0.99996, relmean ~7.6-9.0e-3 (inside 2x bf16 floor). dInput 0.99997.

=> ~5-6 ms/iter (over half of 10.68) is the torch _ln_fwd/_ln_bwd broadcast elementwise + reduces.
cuequiv fuses all of LayerNorm into single kernels. THIS is the next lever (v8).
